# agent-session-atlas

Local-first analytics for GitHub Copilot session logs — visualize tokens, skills, agents, hooks, instruction files, and llm-wiki usage from `~/.copilot`, without an LLM.

GitHub Copilot のセッションログ(`%USERPROFILE%\.copilot`)を手元で集計し、ブラウザで読めるレポートにするツールです。集計に LLM は使わず、元のファイルも書き換えません(複製してから読みます)。

## 何が分かるか

- トークン・AI 使用量(AIU)・premium request・変更行数を、プロジェクト・月・モデル・クライアント別に
- 使ったツール・MCP サーバー・skill・agent・hook・指示ファイルの利用ランキングと、インストール済みで使っていない skill
- ツールの失敗を要因(時間切れ・対象が見つからない・引数の誤り・通信の失敗など)別に数え、どのツールがどの要因で失敗しているか
- 摩擦(ツールの失敗、権限の確認、compaction、エラー)と待ち時間
- 依頼(ターン)ごとの工程(調査・実装・検証など)と、どの工程でどれだけ詰まったか(ツールの失敗・拒否・中断・再編集など)。依頼の種類(作業・質問・修正など)ごとの内訳
- AI の成果がどれだけ採用されたか(そのまま・中身を修正・体裁を修正・不採用)と、合わなかった点・普段の工程ごとの差(任意。LLM に判定させたときだけ)
- 依頼ごと・セッションごとの表(CSV。Excel で開ける)と、タスクタグ単位の書き出し
- 指示ファイルの注入と llm-wiki の参照
- 改善点の傾向(指示文や skill の版の前後比較、止まっている箇所、スキル化の候補)
- セッションごとの詳細ページ・経過の記録(Markdown)・自分用のメモ
- 推定人手工数(任意。LLM に判定させたときだけ)

## 使い方

前提: Node.js 24 以上と Git。このリポジトリを `git clone` して使います(配布用の zip はありません)。

0. (任意)設定は、`atlas.bat` で開いた画面の右上の「設定…」で決められます(llm-wiki の vault・普段の工程名・アップロード先・まとめて送るプロジェクト)。黒い窓で決めたいときは、`setup.bat` も使えます(下記「[初期設定(setup.bat)](#初期設定setupbat)」)。llm-wiki の参照を数えないなら、どちらも飛ばして構いません。
1. リポジトリ直下の `atlas.bat` をダブルクリックします(初回だけ `npm install` が走ります)。
2. 集計が終わると、既定のブラウザにレポートが開きます。約 800 セッションで十数秒かかります。2 回目以降は、変わっていないファイルの複製を省きます。
3. 読み終わったらブラウザを閉じます。黒い窓とローカルサーバ(`127.0.0.1` だけに公開)も止まります。

もう一度 `atlas.bat` を実行すると集計し直します。新しい版にするには `git pull` してから `atlas.bat` を実行します(依存が変わっていれば `npm install` が走り、レポートのテンプレートも作り直します)。前の `atlas.bat` の黒い窓が開いたままだと、更新前のサーバが動き続け、画面の上に「画面とサーバの版が違います」と出ます。その黒い窓を閉じてから、もう一度 `atlas.bat` を実行し、新しく開いた画面を使ってください(前の版で作ったページを開いたときも同じ帯が出ます。直し方は同じです)。

### 初期設定(setup.bat)

同じ設定は、`atlas.bat` で開いた画面の右上の「設定…」でも決められます(`setup.bat` を使わなくても構いません)。画面では、まとめて送るプロジェクトも選べます。

`setup.bat` は、依存を入れ(初回だけ `npm install`)、次の 3 つを順に尋ねて、リポジトリ直下に `atlas.config.json` を書きます。集計はしません。終わったら `atlas.bat` をダブルクリックします。

1. **llm-wiki の vault**: `y` を入れるとエクスプローラー(フォルダを選ぶ画面)が開くので、vault のフォルダを選びます。フォルダを黒い窓にドラッグするか、フォルダ名を入力しても決められます。フォルダ名だけで登録し(フルパスより確実です)、中に `wiki` フォルダがあれば個別ページの場所として勧めます。インストール済みの skill のうち、名前に `wiki` を含むものは「wiki の skill」として数えるか尋ねます。vault は続けて複数入れられます。何も入れずに Enter で次へ進みます。
2. **普段の工程名**: 依頼ごとの採用の判定で使う工程名です。Enter で今のまま(初回は既定)になります。変えるときは `設計 / 実装 / テスト` のように区切って入力します。
3. **アップロード先**: 画面のタスクタグの「アップロード」と `upload-project.bat` で、セッションの生ログを写す基底のフォルダ(例: `E:\dev\atlas-logs`)です。まだ決めていなければ、Enter でエクスプローラーが開くので、フォルダを選びます(決めないなら `n`)。決めてあれば Enter で今のまま、`y` でエクスプローラーが開きます。フォルダを黒い窓にドラッグするか、フルパスを入力しても決められます。後から画面や `upload-project.bat` でも決められます。

最後に書き込む内容を表示し、確認してから書きます。前の設定は `atlas.config.json.bak` に残します。もう一度実行すると、今の設定を見ながら直せます。手で書くときの項目は [docs/cli.md の「wiki の指定」](docs/cli.md#wiki-の指定) にあります。

### 画面でできること

`atlas.bat` から開いた画面では、次の操作ができます。`out\atlas.html` を直接開いたときは閲覧と絞り込みだけです。

| 操作 | 場所 |
|---|---|
| 期間・プロジェクト・モデルなどで絞り込む | レポートの上部 |
| 集計し直す | レポートの右上 |
| 別のフォルダを開く…(アップロード先 = 全員の分、その下の人のフォルダ = その人の分、プロジェクトのフォルダ。集計して新しいタブで開く。下記「[アップロードされたセッションを集計する](#アップロードされたセッションを集計する別のフォルダを開く)」) | レポートの右上 |
| 設定…(llm-wiki の vault・普段の工程名・アップロード先・まとめて送るプロジェクト。`setup.bat` と同じ設定) | レポートの右上 |
| 判定する…(工数 / 依頼ごとの採用。このツールで回すと AI クレジットを消費します。実行前に確認が出ます) | レポートの右上 |
| セッションを選んで集計する / タスクタグを付ける | セッション一覧(詳細ページでも付け外しできる) |
| タスクタグのセッションをアップロードする(決めた場所の `<タグ名>\<セッション ID>\` へ写す。タグの説明とメモも残す) | タスクタグで絞り込んだときの見出し |
| `upload-project.bat` と `schedule-upload.bat`(毎日自動で送る)が送るプロジェクトに印を付ける | 「プロジェクト別」の表の「まとめて送る」 |
| 記録を読む / 全文を作って読む | 詳細ページの表題の下 |
| メモを書く(Markdown と画像) | 詳細ページ |

各欄の読み方と操作の細かい決まりは [docs/screen.md](docs/screen.md) にあります。用語はレポートの「用語の説明」ページで引けます。

## 共有するときの注意

**`out/` はそのまま渡さないでください。** スナップショット・セッション記録・全文記録には依頼文・応答・ツールの結果・ファイルのパスがそのまま入り、秘密情報が混じることがあります。伏せ字でない `atlas.html` と詳細ページにも、最初の依頼と最後の応答が入ります。

共有するときは伏せ字版を作り、中身を確かめてから `out/atlas.html`・`out/glossary.html`・`out/sessions/` だけを渡してください。

```
npm run atlas -- all --anonymize
```

伏せ字版では、プロジェクト名・パス・リポジトリ名・ブランチ・人のフォルダの名前を仮名にし、依頼の本文・メモ・タスクタグの名前を出しません。何を伏せ、何が残るかは [docs/cli.md の `--anonymize`](docs/cli.md#オプション) にあります。評価バンドル(`bundle`)は伏せ字になりません。

## コマンドで使う

期間の絞り込み・記録の中身の調整・全件の全文記録・伏せ字版など、細かい指定はコマンドで行います。

```
npm install
npm run atlas                              # atlas.bat と同じ集計(snapshot → extract → metrics → export)
npm run atlas -- all --since 2026-07-01    # 7 月以降に更新されたセッションだけ
npm run atlas -- export --full             # 解析用の全文記録(外に出さない前提)
npm run atlas -- serve                     # 集計せずに画面だけ開く
npm run atlas -- --help                    # 使い方
```

コマンドとオプションの一覧は [docs/cli.md](docs/cli.md)、出力ファイルの中身は [docs/outputs.md](docs/outputs.md) にあります。

## llm-wiki の参照を数えるとき

**vault を指定しないと、llm-wiki の参照は 0 件のままです。** `setup.bat` で指定するか、リポジトリ直下に `atlas.config.json` を置いて、vault のフォルダ名を書いてください(雛形は `atlas.config.example.json`)。

```json
{ "wikis": ["my-wiki"] }
```

`path` にはフルパスよりもフォルダ名だけを書くほうが確実です。索引やページの場所の指定、数え方は [docs/cli.md の「wiki の指定」](docs/cli.md#wiki-の指定) にあります。

## 推定人手工数(任意)

「同じ作業を人が AI なしでやったら何時間かかるか」を LLM に推定させ、レポートに足せます。集計とは別の手順です。推定には幅と確信度を付けますが、人手での実測ではありません。

- **画面から自動で**: 「判定する…」で「工数」を選び、未判定のセッションを上限(既定 10 件)まで `copilot -p` で判定します。
- **チャットに貼って(M365 Copilot など)**: 「判定する…」で「チャットに貼って判定する」を選びます。画面の 4 つの手順(添付ファイルを作る → ダウンロードしてチャットに添付する → 返答を貼って取り込む → レポートに反映する)に沿って進めます。ターミナルは使いません。

`copilot -p` は AI クレジットを消費します。従量課金の `anthropic` は、コマンドで明示したときだけ使います。手順・費用・安全策は [docs/judge.md](docs/judge.md) にあります。

## 依頼ごとの採用(任意)

依頼(ターン)ごとに、AI の成果が利用者にどう扱われたか(そのまま採用 / 中身を修正して採用 / 体裁を修正して採用 / 不採用。質問なら 役に立った / 追加で聞いた / 的外れ)と、合わなかった点(意図の取り違え・誤り・品質・範囲・環境)、普段の工程名を LLM に判定させ、「工程と詰まり」の欄に足せます。判定の材料は次の依頼の文と、その依頼の間の拒否・中断です。LLM が勝手に動くことはありません。

- **チャットに貼って(M365 Copilot など。既定)**: 「判定する…」で「依頼ごとの採用」と「チャットに貼って判定する」を選び、工数と同じ 4 つの手順で進めます。
- **画面から自動で**: 「依頼ごとの採用」と「このツールが判定する」を選ぶと、GitHub Copilot CLI(`copilot -p`)で依頼数件ずつ判定します(AI クレジットを消費します)。

普段の工程名は `atlas.config.json` の `phases` で変えられます(既定: 要件定義 / 設計 / 実装 / テスト / レビュー / 調査 / 運用 / その他)。詳しくは [docs/judge.md の「依頼ごとの採用」](docs/judge.md#3-依頼ごとの採用段階-2) にあります。

## タスクごとにセッションをアップロードする

セッションにタスクタグ(例: `Player-Weapon`)を付け、タグごとにそのセッションの生ログを決めた場所へ写せます。1 つのセッションに複数のタグを付けられます(保存先とコマンドでは「グループ」と呼びます: `atlas-notes/groups.json`、`atlas group …`)。

1. セッション一覧でタスクのセッションをチェックし、「タスクタグを付ける ▾」→「新しいタスクタグ…」でタスク名(例: `Player-Weapon`)のタグを付けます。詳細ページの表題の下でも、1 件ずつ付け外しできます。
2. 左の「タスクタグ」でそのタグを選びます。見出しの下に「アップロード先」が出ます。初回は「場所を決める…」→「エクスプローラーで選ぶ…」で基底のフォルダ(例: `E:\dev\atlas-logs`)を選びます(`setup.bat` で決めてあれば不要)。
3. 見出しの「アップロード」を押すと、写す前に確認が出ます(送り先・件数・大きさ。秘密らしい文字列があれば警告)。「送り先を変える…」でエクスプローラーから選び直せます。「写す」を押すと、次の形で写します。同じセッションは置き換え、ほかのフォルダには触れません。

```
E:\dev\atlas-logs\Player-Weapon\README.md                        タグ名・タグの説明・写した日時・セッションの一覧(題名・タスクタグ・メモの有無)
E:\dev\atlas-logs\Player-Weapon\<セッション ID>\events.jsonl など  セッションの生ログ
E:\dev\atlas-logs\Player-Weapon\atlas-index.json                 プログラムや AI が読む索引(セッションごとのタスクタグ・題名・日時)
E:\dev\atlas-logs\Player-Weapon\<セッション ID>\atlas-session.json そのセッションのタスクタグ・題名・日時・プロジェクト名
E:\dev\atlas-logs\Player-Weapon\<セッション ID>\atlas-memo.md     そのセッションのメモ(画像は atlas-memo\ に)
```

写すのは `atlas.bat` を起動したとき(か「集計し直す」)に複製したログです。写したフォルダは `npm run atlas -- all --home "E:\dev\atlas-logs\Player-Weapon" --out out-player-weapon` でそのまま集計できます(`--home` にはタスクタグのフォルダを指定し、`--out` は集計するフォルダごとに分けます。いつもの `out` や別のフォルダを集計した出力先を指定すると、セッションが混ざるので書かずに止まります。集計が途中で止まった出力先でも同じです。プロジェクト名は送った PC で決めた名前のままです)。このとき、セッションごとの読みやすい記録(`<出力先>\sessions\<セッション ID>.md`。依頼・応答・ツールの経過をまとめた Markdown)もできます(記録は生ログから作れるので、送るものには含めません。送り先の容量を使わないため)。生ログには依頼文や応答、パスがそのまま入るので、写す先を見られる人を確かめてください。詳しくは [docs/screen.md の「タスクタグを作る・直す」](docs/screen.md#タスクタグを作る直すatlasbat-から開いたときだけ) にあります。

## プロジェクトのセッションをまとめて送る(upload-project.bat)

集計のプロジェクト(画面の「プロジェクト別」と同じ単位)ごとに、そのセッションをまとめて送れます。タスクタグの無いセッションも送ります。送り先の `README.md`(タスクタグの列とタグごとの一覧)と `atlas-index.json` に各セッションのタグを書くので、送った先で人も AI もタスクごとに見分けられます(タグの無いものは「タグなし」)。

0. (任意・最初に一度)送るプロジェクトを決めておきます。`atlas.bat` の画面の「プロジェクト別」の表で、送るプロジェクトの「まとめて送る」に印を付けます。印は `atlas.config.json` の `uploadProjects` に残り、外すと消えます。印があれば、bat は番号を聞かずに印のプロジェクトをまとめて送ります。
1. `upload-project.bat` をダブルクリックします。最新のログを集計し直してから、送るプロジェクトを出します。
   - 集計: 進み具合は 1 行で出し、経過の細かい行は窓に出さずに `%TEMP%\atlas-upload-project.log` に書きます(1 行ごとにその場で書くので、途中で窓を閉じてもそこまでの経過が残ります)。窓に出すのは、送るものに関わる「注意」(ログの一部を今回は複製できず、前回の複製を使った、など)と、失敗したときの理由です。ほかの注意(記録で伏せた文字列の数など)は経過のファイルにだけ書きます。集計の中で警告が出たときは、警告があったことと経過のファイルの場所を 1 行で出します。
   - 質問が出るまでに押したキー(文字も Enter も)は捨てるので、次の質問の答えにはなりません。この間に Ctrl+C を押すと、その場で終わります(「続行するには何かキーを押してください」に進みます)。
   - 印があるとき: 「画面で印を付けた N プロジェクトを送ります」と出し、番号は聞きません。ログが無くて送れないセッションがあれば、その数を出します。印の無いプロジェクトは送らず、その数と、最近更新した 3 件の名前を出します(新しく始めたプロジェクトを送るなら、画面で印を付けてください)。
   - 印が無いとき: プロジェクトの一覧(番号・セッション数・最終更新)を出すので、送るプロジェクトの番号を入れて Enter を押します。`1 3 5-8` のように複数選べます。当たらない番号を入れたときは、入れ直せます(やめるなら何も入れずに Enter)。
2. 送り先がまだ決まっていなければ、フォルダを選ぶ画面が開くので、送り先のフォルダ(例: `E:\dev\atlas-logs`)を選びます。選んだ送り先は覚えておき、次からは聞きません(`atlas.config.json` の `uploadRoot`。画面のアップロードと同じ設定です)。
3. 「送る前の確認」に、送り先・セッション数・大きさ・秘密らしい文字列を出します(何プロジェクトかを送るときは、プロジェクトごとの 1 行と合計)。`y` = 送る、`n` = 今回だけ別のプロジェクトを番号で選び直す(印は変えません)、`c` = 送り先を変える、何も入れずに Enter = やめる、です。
4. 送っている間は、進み具合を 1 行で出し(書き換えるので行は増えません)、プロジェクトを 1 つ送るごとに結果を 1 行出します。最後に、送ったプロジェクト・セッションの数と送り先をまとめて出します。途中でやめたときは「途中でやめました」と、送っていない残りのプロジェクトを出します。

止まるとき・聞き直すとき:

- 何プロジェクトかを送る途中で 1 つ送れなかった(送り先のファイルが開かれているなど)ときは、残りを送ってから、送れなかったプロジェクトと理由を出して止まります。もう一度実行すれば送り直せます(送ったものは置き換えるだけです)。途中で止まったとき(確かめ直す間に画面で集計し直し始めたなど)も、ここまでに送ったプロジェクトを出します。
- 一度に送るプロジェクトのうち、フォルダ名が同じになるもの(`owner/app` と `owner_app` など)があれば、混ざるので何も送らずに止まります。
- 覚えている送り先が見つからない(ネットワークドライブの切断・フォルダの削除)ときは、その場でフォルダを選び直せます。
- 確かめてから `y` を押すまでの間に、`atlas.bat` の画面で集計し直してログが変わったときは、写さずにもう一度確かめます(確かめていない中身を送らないため)。
- `atlas.bat` の画面で集計し直している最中は、送らずに止まります。終わってからもう一度実行してください。
- 前に送ったセッションを置き換えたとき、前のフォルダが送り先で開かれていて消せなかったら、その場所を出します(`atlas.bat` の画面のアップロードでも、結果に件数と場所を出します)。閉じてから手で消してください。
- 送れなかったプロジェクトがあるときも、確かめ直しでやめて送らなかった残りは「残りの N プロジェクトは送っていません」と分けて出します。
- 一覧の「ほかに、ログが無くて送れないもの」は、`session-store.db` にだけ記録が残っているセッションです(ログの本体が無いので送れません)。
- 送り先のフォルダに、フォルダ名が同じになる別のタスクタグやプロジェクトがすでに送られているときは、混ざるので送りません(送り先を変えてください)。

送り先には `<送り先>\<プロジェクト名>\<セッション ID>\` の形で写します(プロジェクト名のフォルダ名に使えない文字は `_` にします。例: `owner/app` → `owner_app`)。空のセッションは送りません。中身と注意はタスクタグのアップロードと同じです。

毎日決まった時刻に自動で送るなら、下記「[毎日自動で送る](#毎日自動で送るschedule-uploadbat)」で登録できます。

## 毎日自動で送る(schedule-upload.bat)

`upload-project.bat` を毎回手で実行しなくても、毎日決まった時刻に自動で送れます(1 日に何回かでも送れます)。Windows のタスク スケジューラに、自分のユーザーで動くタスクを 1 つ登録します(タスクの名前は `agent-session-atlas-upload`)。

先に決めておくこと(どちらも一度だけ):

- **送り先**: `upload-project.bat` を一度使うか、`atlas.bat` の画面の「設定…」で決めます。
- **送るプロジェクト**: `atlas.bat` の画面の「プロジェクト別」の表で、「まとめて送る」に印を付けます。自動で送るのは、印のあるプロジェクトだけです。

登録のしかた:

1. `schedule-upload.bat` をダブルクリックします。今の様子(登録の有無・送り先・印を付けたプロジェクト)と、自動で送るときの決まりを出します。
2. 送る時刻を入れて Enter を押します(例: `17:30`。何も入れずに Enter なら `18:00`。やめるなら `n`)。1 日に何回か送るなら、`12:00,18:00` のように `,` で区切って入れます(6 回まで。早い順に並べ、同じ時刻は 1 つにまとめます)。
3. 「今すぐ 1 回送って試しますか?」に `y` で答えると、その場で 1 回送り、終わるまで待って結果を出します。

自動で送るときの決まり:

- 決めた時刻になるたびに、窓を出さずに最新のログを集計し直してから、印のあるプロジェクトを送り先へ送ります。中身は `upload-project.bat` と同じです(`<送り先>\<プロジェクト名>\<セッション ID>\`)。
- その時刻に PC が止まっていたら、次に PC を使い始めたときに送ります。ログオンしている間だけ動きます(NAS やネットワークドライブへ、いつもの資格情報で書けるように)。電池で動いているときも送ります。
- **送る前の確認は出しません**。秘密らしい文字列があっても送り、その数を結果に残します。送り先を見られる人を、登録の前に確かめてください。
- 印の無いプロジェクトは送りません。新しく始めたプロジェクトは、画面で印を付けてください(印の無いもののうち最近更新したものの名前を、記録に残します)。
- `atlas.bat` の画面で集計し直している最中なら、終わるまで待ってから始めます(1 時間待っても終わらなければ、その回は送りません)。
- 送れなかったときは、Windows の通知で知らせます。送り先が見つからない・印が無いなど、尋ねないと進めないときも、何も送らずに通知します。

登録した後にもう一度 `schedule-upload.bat` を開くと、送る時刻・次の回・前回の結果(送ったプロジェクトとセッションの数、送れなかった理由)を出します。そこで `t` = 時刻を変える(Enter だけなら今の時刻を全部そのまま。1 日 1 回に戻すときは時刻を 1 つだけ入れます)、`s` = 今すぐ 1 回送る、`d` = 自動で送るのをやめる(登録を消す。送ったものは残ります)を選べます。Node.js を入れ直して場所が変わったときは、登録し直すよう出るので `t` で登録し直します。

結果は `out\auto-upload.json`、経過は `out\auto-upload.log`(集計の経過は `out\auto-upload-aggregate.log`)に、回ごとに書き直します。登録はタスク スケジューラ(`taskschd.msc`)でも見られます。窓を出さずに動かすため、タスク スケジューラの「前回の実行結果」はいつも成功(0x0)と出ます。送れたかどうかは `schedule-upload.bat` か `out\auto-upload.json` で確かめてください。

Windows 以外では登録できません。cron などから `node packages/cli/src/upload-auto.ts` を動かすと、同じことをします。

## アップロードされたセッションを集計する(別のフォルダを開く)

いつもの画面(この PC のセッション)とは別に、アップロード先のフォルダを選んで集計し、新しいタブで開けます。この PC の集計はそのまま残ります。

送り先が人ごとに分けてあるとき(`<送り先>\<名前>\<プロジェクト>\<セッション ID>\`)は、選ぶフォルダで集計する範囲が決まります。

| 選ぶフォルダ | 集計する範囲 |
|---|---|
| `<送り先>`(例: `\\server\share\log`) | 全員の分(2 段下まで読みます) |
| `<送り先>\<名前>` | その人の分 |
| `<送り先>\<名前>\<プロジェクト>` | そのプロジェクト(かタスクタグ)の分 |

`<送り先>` を選んで開いたレポート(全員の分)には、絞り込みに「人」が、内訳に「人別」の表が加わります(`<名前>` のフォルダごとの集計。名前を押すとその人に絞り込みます)。人のフォルダやプロジェクトのフォルダを選んだとき、この PC の集計には出ません。

1. `atlas.bat` で開いた画面の右上の「別のフォルダを開く…」を押します。
2. 「エクスプローラーで選ぶ…」でフォルダを選ぶか、フォルダのフルパスを入れて「調べる」を押します。何を読むか(例: 「下のフォルダ 2 件をまとめて集計します」)が出ます。集計できないフォルダなら、理由が出ます。
3. 「集計して開く」を押します。集計が終わると、新しいタブで開きます(一覧の「表示する」からも開けます)。開いた画面は、上部に「対象: <フォルダ名>」と出ます。
4. 一度開いたフォルダは「開いたことのあるフォルダ」に並ぶので、次からは「集計して開く」を押すだけです(開くたびに集計し直します)。

**初めからフォルダを選んで開く(open-folder.bat)**: いつもの画面を開かずに、アップロード先のフォルダだけを見たいときは、リポジトリ直下の `open-folder.bat` をダブルクリックします。フォルダを選ぶ画面(エクスプローラーの「フォルダーの選択」)が出るので、上の表のどれかのフォルダを選ぶと、集計してブラウザで開きます。2 回目からは、前に開いたフォルダの場所で選ぶ画面が出ます。

- フォルダを `open-folder.bat` に重ねて離す(ドラッグ アンド ドロップ)と、選ぶ画面を出さずにそのフォルダを開きます。
- 選ぶ画面で「キャンセル」を押すと、何もせずに終わります。集計できないフォルダを選んだときは、理由を出して止まります(何も書きません。もう一度 `open-folder.bat` を実行してください)。
- 出力先は、画面の「別のフォルダを開く…」で開いたときと同じ場所です(同じフォルダなら、どちらから開いても同じレポートになります)。この PC の集計(`out\`)には触れません。
- 黒い窓は、ブラウザのタブを閉じるまで残ります(閉じるとサーバも止まります。`atlas.bat` と同じです)。

- **開いた画面は読むだけです**(上部に「読むだけ」と出ます)。タスクタグとメモは、送った人が付けていたもの(送った時点のもの)を出し、この画面では付け外し・書き換え・アップロードをしません。タスクタグは人ごとに分け、「<名前> / <タグ>」と出します(同じ名前のタグでも、別の人のものは別です)。人のフォルダを開いたときは、タグの名前だけです。「集計し直す」と「判定する…」は使えます(この PC の出力先に書くだけで、送り先は書き換えません)。
- 集計の出力は、いつもの `out\` には混ぜず、フォルダごとに `out-folders\<フォルダごとの名前>\out\` に置きます(フォルダごとの名前は、フォルダ名とパスから決まります)。
- 開いたタブを閉じると、そのフォルダのサーバは止まります(いつもの画面と同じ決まりです)。「一覧から外す」は一覧から消すだけで、集計の出力とメモは残ります。
- 同じ id のセッションが何人かのフォルダにあるときは、`events.jsonl` が大きいほうだけを数えます。
- コマンドでも開けます: `npm run atlas -- open "\\server\share\log\<名前>"`、選ぶ画面から選ぶときは `npm run atlas -- open --pick`([docs/cli.md](docs/cli.md#別のフォルダを開くopen))。
- 生ログには依頼文や応答、パスがそのまま入っています。集計の出力(`out-folders\`)も、見られる人を確かめて扱ってください。

操作の細かい決まりは [docs/screen.md の「別のフォルダを開く」](docs/screen.md#別のフォルダを開く) にあります。

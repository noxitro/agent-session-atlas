# agent-session-atlas

Local-first analytics for GitHub Copilot session logs — visualize tokens, skills, agents, hooks, instruction files, and llm-wiki usage from `~/.copilot`, without an LLM.

GitHub Copilot のセッションログ(`%USERPROFILE%\.copilot`)を手元で集計し、ブラウザで読めるレポートにするツールです。集計に LLM は使わず、元のファイルも書き換えません(複製してから読みます)。

## 何が分かるか

- トークン・AI 使用量(AIU)・premium request・変更行数を、プロジェクト・月・モデル・クライアント別に
- 使ったツール・MCP サーバー・skill・agent・hook・指示ファイルの利用ランキングと、インストール済みで使っていない skill
- 摩擦(ツールの失敗、権限の確認、compaction、エラー)と待ち時間
- 依頼(ターン)ごとの工程(調査・実装・検証など)と、どの工程でどれだけ詰まったか(ツールの失敗・拒否・中断・再編集など)。依頼の種類(作業・質問・修正など)ごとの内訳
- AI の成果がどれだけ採用されたか(そのまま・中身を修正・体裁を修正・不採用)と、合わなかった点・普段の工程ごとの差(任意。LLM に判定させたときだけ)
- 依頼ごと・セッションごとの表(CSV。Excel で開ける)と、グループ単位の書き出し
- 指示ファイルの注入と llm-wiki の参照
- 改善点の傾向(指示文や skill の版の前後比較、止まっている箇所、スキル化の候補)
- セッションごとの詳細ページ・経過の記録(Markdown)・自分用のメモ
- 推定人手工数(任意。LLM に判定させたときだけ)

## 使い方

前提: Node.js 24 以上。

0. (初回だけ・任意)リポジトリ直下の `setup.bat` をダブルクリックして、初期設定をします(下記「[初期設定(setup.bat)](#初期設定setupbat)」)。llm-wiki の参照を数えないなら飛ばして構いません。
1. リポジトリ直下の `atlas.bat` をダブルクリックします(初回だけ `npm install` が走ります)。
2. 集計が終わると、既定のブラウザにレポートが開きます。約 800 セッションで十数秒かかります。2 回目以降は、変わっていないファイルの複製を省きます。
3. 読み終わったらブラウザを閉じます。黒い窓とローカルサーバ(`127.0.0.1` だけに公開)も止まります。

もう一度 `atlas.bat` を実行すると集計し直します。[GitHub Release](../../releases) の zip を展開した場合も、同じく `atlas.bat` をダブルクリックするだけです。

### 初期設定(setup.bat)

`setup.bat` は、依存を入れ(初回だけ `npm install`)、次の 3 つを順に尋ねて、リポジトリ直下に `atlas.config.json` を書きます。集計はしません。終わったら `atlas.bat` をダブルクリックします。

1. **llm-wiki の vault**: vault のフォルダを黒い窓にドラッグするか、フォルダ名を入力します。フォルダ名だけで登録し(フルパスより確実です)、中に `wiki` フォルダがあれば個別ページの場所として勧めます。インストール済みの skill のうち、名前に `wiki` を含むものは「wiki の skill」として数えるか尋ねます。vault は続けて複数入れられます。何も入れずに Enter で次へ進みます。
2. **普段の工程名**: 依頼ごとの採用の判定で使う工程名です。Enter で今のまま(初回は既定)になります。変えるときは `設計 / 実装 / テスト` のように区切って入力します。
3. **グループのアップロード先**: 画面のグループの「アップロード」で、セッションの生ログを写す基底のフォルダ(例: `E:\dev\atlas-logs`)です。フォルダを黒い窓にドラッグするか、フルパスを入力します。Enter で今のまま(初回は決めない)になり、後から画面でも決められます。

最後に書き込む内容を表示し、確認してから書きます。前の設定は `atlas.config.json.bak` に残します。もう一度実行すると、今の設定を見ながら直せます。手で書くときの項目は [docs/cli.md の「wiki の指定」](docs/cli.md#wiki-の指定) にあります。

### 画面でできること

`atlas.bat` から開いた画面では、次の操作ができます。`out\atlas.html` を直接開いたときは閲覧と絞り込みだけです。

| 操作 | 場所 |
|---|---|
| 期間・プロジェクト・モデルなどで絞り込む | レポートの上部 |
| 集計し直す | レポートの右上 |
| 判定する…(工数 / 依頼ごとの採用。このツールで回すと AI クレジットを消費します。実行前に確認が出ます) | レポートの右上 |
| セッションを選んで集計する / グループにする | セッション一覧 |
| グループのセッションをアップロードする(決めた場所の `<グループ名>\<セッション ID>\` へ写す。グループの説明とメモも残す) | グループで絞り込んだときの見出し |
| 記録を読む / 全文を作って読む | 詳細ページの表題の下 |
| メモを書く(Markdown と画像) | 詳細ページ |

各欄の読み方と操作の細かい決まりは [docs/screen.md](docs/screen.md) にあります。用語はレポートの「用語の説明」ページで引けます。

## 共有するときの注意

**`out/` はそのまま渡さないでください。** スナップショット・セッション記録・全文記録には依頼文・応答・ツールの結果・ファイルのパスがそのまま入り、秘密情報が混じることがあります。伏せ字でない `atlas.html` と詳細ページにも、最初の依頼と最後の応答が入ります。

共有するときは伏せ字版を作り、中身を確かめてから `out/atlas.html`・`out/glossary.html`・`out/sessions/` だけを渡してください。

```
npm run atlas -- all --anonymize
```

伏せ字版では、プロジェクト名・パス・リポジトリ名・ブランチを仮名にし、依頼の本文・メモ・グループ名を出しません。何を伏せ、何が残るかは [docs/cli.md の `--anonymize`](docs/cli.md#オプション) にあります。評価バンドル(`bundle`)は伏せ字になりません。

## コマンドで使う

期間の絞り込み・記録の中身の調整・全件の全文記録・伏せ字版など、細かい指定はコマンドで行います。

```
npm install
npm run atlas                              # atlas.bat と同じ集計(snapshot → extract → metrics → export)
npm run atlas -- all --since 2026-07-01    # 7 月以降に更新されたセッションだけ
npm run atlas -- export --full             # 解析用の全文記録(外に出さない前提)
npm run atlas -- serve                     # 集計せずに画面だけ開く
npm run atlas -- --help                    # 使い方
```

コマンドとオプションの一覧は [docs/cli.md](docs/cli.md)、出力ファイルの中身は [docs/outputs.md](docs/outputs.md) にあります。

## llm-wiki の参照を数えるとき

**vault を指定しないと、llm-wiki の参照は 0 件のままです。** `setup.bat` で指定するか、リポジトリ直下に `atlas.config.json` を置いて、vault のフォルダ名を書いてください(雛形は `atlas.config.example.json`)。

```json
{ "wikis": ["my-wiki"] }
```

`path` にはフルパスよりもフォルダ名だけを書くほうが確実です。索引やページの場所の指定、数え方は [docs/cli.md の「wiki の指定」](docs/cli.md#wiki-の指定) にあります。

## 推定人手工数(任意)

「同じ作業を人が AI なしでやったら何時間かかるか」を LLM に推定させ、レポートに足せます。集計とは別の手順です。推定には幅と確信度を付けますが、人手での実測ではありません。

- **画面から自動で**: 「判定する…」で「工数」を選び、未判定のセッションを上限(既定 10 件)まで `copilot -p` か `opencode` で判定します。
- **チャットに貼って(M365 Copilot など)**: 「判定する…」で「チャットに貼って判定する」を選びます。画面の 4 つの手順(添付ファイルを作る → ダウンロードしてチャットに添付する → 返答を貼って取り込む → レポートに反映する)に沿って進めます。ターミナルは使いません。

`copilot -p` は AI クレジットを消費します。従量課金の `anthropic` は、コマンドで明示したときだけ使います。手順・費用・安全策は [docs/judge.md](docs/judge.md) にあります。

## 依頼ごとの採用(任意)

依頼(ターン)ごとに、AI の成果が利用者にどう扱われたか(そのまま採用 / 中身を修正して採用 / 体裁を修正して採用 / 不採用。質問なら 役に立った / 追加で聞いた / 的外れ)と、合わなかった点(意図の取り違え・誤り・品質・範囲・環境)、普段の工程名を LLM に判定させ、「工程と詰まり」の欄に足せます。判定の材料は次の依頼の文と、その依頼の間の拒否・中断です。LLM が勝手に動くことはありません。

- **チャットに貼って(M365 Copilot など。既定)**: 「判定する…」で「依頼ごとの採用」と「チャットに貼って判定する」を選び、工数と同じ 4 つの手順で進めます。
- **画面から自動で**: 「依頼ごとの採用」と「このツールが判定する」を選ぶと、GitHub Copilot CLI(`copilot -p`)で依頼数件ずつ判定します(AI クレジットを消費します)。opencode は使いません。

普段の工程名は `atlas.config.json` の `phases` で変えられます(既定: 要件定義 / 設計 / 実装 / テスト / レビュー / 調査 / 運用 / その他)。詳しくは [docs/judge.md の「依頼ごとの採用」](docs/judge.md#3-依頼ごとの採用段階-2) にあります。

## タスクごとにセッションをアップロードする

タスクごとにグループを作り、そのセッションの生ログを決めた場所へ写せます。

1. セッション一覧でタスクのセッションをチェックし、「グループに追加 ▾」→「新しいグループ…」でタスク名(例: `Player-Weapon`)のグループを作ります。
2. 左の「グループ」でそのグループを選びます。見出しの下に「アップロード先」が出ます。初回は「場所を決める…」→「エクスプローラーで選ぶ…」で基底のフォルダ(例: `E:\dev\atlas-logs`)を選びます(`setup.bat` で決めてあれば不要)。
3. 見出しの「アップロード」を押すと、次の形で写します。同じセッションは置き換え、ほかのフォルダには触れません。

```
E:\dev\atlas-logs\Player-Weapon\README.md                        グループ名・グループの説明・写した日時・セッションの一覧(題名・メモの有無)
E:\dev\atlas-logs\Player-Weapon\<セッション ID>\events.jsonl など  セッションの生ログ
E:\dev\atlas-logs\Player-Weapon\<セッション ID>\atlas-memo.md     そのセッションのメモ(画像は atlas-memo\ に)
```

写すのは `atlas.bat` を起動したとき(か「集計し直す」)に複製したログです。受け取った側は `npm run atlas -- all --home "E:\dev\atlas-logs\Player-Weapon" --out out-player-weapon` でそのまま集計できます。生ログには依頼文や応答、パスがそのまま入るので、写す先を見せてよい相手か確かめてください。詳しくは [docs/screen.md の「グループを作る・直す」](docs/screen.md#グループを作る直すatlasbat-から開いたときだけ) にあります。

# 画面の見方と操作

[README](../README.md) に戻る。コマンドで使うときは [cli.md](cli.md) を見てください。

## サーバと黒い窓

`atlas.bat` は、`bin\atlas.exe` が無いか版が違うときだけ用意し直したあと(README の「atlas.exe の用意と更新」)、`~/.copilot` を `out\snapshot` に複製して集計し、`out\atlas.html` と各セッションの記録(`out\sessions\<id>.md`。詳細ページからリンク)を作ります(実データ約 800 セッションで十数秒。うち記録の生成に 5 秒ほど)。そのあと`out/` をローカルサーバ(`127.0.0.1` だけに公開。ポートは空いているものを自動で取ります)で配信し、既定のブラウザで開きます。

- 黒い窓はブラウザを閉じるまで残り、atlas の画面(一覧・詳細・用語)をすべて閉じると約 15 秒後にサーバも止まります(ページを移るだけなら止まりません。窓を閉じても止まります)。別のタブで作業している間やスリープの後でも止まりません(閉じたことを知らせずに画面が消えたときは、合図が 30 分届かなければ止まります)。フォルダを選ぶ画面を出している間やアップロードの途中など、サーバが画面の求めに応えている最中は、終わるまで止まりません(終わってから約 15 秒後に止まります)。サーバが止まると、画面の上に「サーバが止まっています」と出ます。
- atlas を更新した(`git pull` など)後も、前から開いている黒い窓のサーバは更新前のまま動きます。画面を作ったときの atlas とサーバの版が違うと、画面の上に「画面とサーバの版が違います」と出ます(それまでは、新しく入った操作が使えないことがあります)。その黒い窓を閉じてから、もう一度 `atlas.bat` を実行し、新しく開いた画面を使ってください。サーバが新しく、ページのほうが前の版のまま(前の版で作って残っている指示文のページ、開いたままのタブ)のときも同じ帯が出ます。直し方は同じです(`atlas.bat` はページを作り直し、サーバも起動し直します)。版は、atlas のソースと、画面の作り方・依存を決めるファイル(各パッケージの設定と `package.json`、`package-lock.json`)の中身から作る目印で比べます(画面を作るときにページへ埋め込み、サーバは起動したときの目印を返します。エディタの作業ファイルや改行の違いでは変わりません)。`atlas serve` をコマンドで実行して前のサーバを使い回すときは、版が違えば、そのターミナルにも同じことを出します(`atlas.bat` をダブルクリックしたときは、すぐ窓が閉じるので画面の帯で知らせます)。
- もう一度 `atlas.bat` を実行すると集計し直し、サーバが動いていればブラウザを開くだけにします。
- 画面から「集計し直す」や添付ファイルの作成を実行している最中は、同じ `out/` に並行して書かないよう `atlas.bat` の集計を止めて理由を出します(終わってから実行してください)。
- 逆に、`atlas` のコマンド(`all`・`build`・`judge`・`tasks` など out/ に書くもの)が動いている間は、画面からの処理も始めずに理由を出します。動いている印は `out\.job.json` で、処理が落ちて残っても、そのプロセスが無ければ次の実行が自動で無視します。
- サーバ無しで開いた画面(`out\atlas.html` を直接開いたもの)は閲覧だけで、メモ・画面からの操作は出ません。

## 画面からの操作

`atlas.bat` から開いた画面(ローカルサーバ経由)では、次の操作ができます。`file://` で開いた画面には出ません。画面から動かす処理は同時に 1 つだけで、動いている間は他の操作のボタンが押せません。処理の出力は `atlas.bat` の黒い窓にも流れます。

| 画面の操作 | 場所 | すること |
|---|---|---|
| 集計し直す | レポート(`atlas.html`)の右上 | `atlas.bat` と同じ集計(`all`: snapshot → extract → metrics → export)をやり直す。終わると本文の上の帯に「新しい集計ができました」と「再読み込み」が出る。自動では読み直さない(メモの入力中などを消さないため)。集計中は詳細ページと記録が作り直しの途中なので、開くと「集計し直している最中です」と出ることがある |
| 別のフォルダを開く… | レポートの右上 | この PC のセッションとは別に、選んだフォルダ(アップロード先 = 全員の分、その下の人のフォルダ = その人の分、プロジェクトのフォルダ)を集計して、新しいタブで開く。集計は別のプロセスが行い、この画面はそのまま使える(下記「[別のフォルダを開く](#別のフォルダを開く)」) |
| 判定する… | レポートの右上 | ダイアログで「判定するもの」(工数 = セッションごとの推定人手工数と成果の質・手戻り / 依頼ごとの採用 / タスクの紐づけ)と「判定の方法」(チャットに貼って判定する / ZIP にまとめてエージェントに渡す)を選ぶ。判定するのは外部の LLM で、このツールは LLM を呼ばない(ダイアログの上にそう書く)。どれも別の判定で 1 つだけでも使えること、迷ったら工数だけで足りることを選択肢の下に出し、依頼ごとの採用には「任意」と付ける。「タスクの紐づけ」は、タスクの設定か記録があって、読むだけの画面でないときだけ出る。選んだものはブラウザに覚える(前の版で覚えた「このツールの中で判定する」方法は、チャットに貼る手順にする)。初期フォーカスは表題の横の「閉じる」で、Esc でも閉じる。対象はいつも未判定のすべて(1 セッションだけなら `bundle --session <id>` で添付ファイルを作る。[judge.md の「範囲を絞る」](judge.md#範囲を絞る1-セッション)) |
| 判定する… →「依頼ごとの採用」 | 同じダイアログで判定するものを切り替える | 依頼ごとに、AI の成果の扱い・合わなかった点・普段の工程を LLM に判定させる([judge.md の 3](judge.md#3-依頼ごとの採用))。どちらの方法も下の行と同じ 4 つの手順で、添付ファイルは `out/turn-bundle/parts/`(ダウンロードの名前は `turns-part-01.txt` など)、ZIP は `out/turn-bundle.zip`(結果を書かせるファイルは `turn-judgments.json`)、取り込み先は `out/turn-judgments.json`。採用を判定できる依頼(次の依頼がある依頼)が先に並び、手順 1 に、チャットなら「先頭の M ファイルに入っています」、ZIP なら「ZIP の中の先頭の K 個の塊(chunks/0001.md〜)に入っています」と出る。その後ろはセッションの最後の依頼だけ(チャットの一覧に「最後の依頼だけ」と付く)で、採用率だけを見たいときは先頭の分で止められる |
| 判定する… →「チャットに貼って判定する」 | 同じダイアログで方法を切り替える | M365 Copilot のように、ファイルの添付と貼り付けしかできないチャットで判定する流れ(相手は M365 Copilot に限らない。ファイルの添付か貼り付けができる LLM なら使える)。添付ファイル(`out/bundle/parts/`)を未判定のセッションだけで作り、次のファイルのダウンロード(`.txt` で保存)・本文のコピー・依頼文のコピーを出す。チャットの返答を貼って(返答を保存したファイルを選んで欄に入れてもよい)「取り込む」と `judgments.json` に入れ、形が合わなければ何も取り込まずに、何件目のどのセッションのどの欄が違うかを出す(「直す点をコピー」でチャットに渡せる)。「レポートに反映する」でレポートを作り直す(`export`)。サーバが Windows なら、手順 2 に「M365 Copilot で自動で判定する」が出て、開いている M365 Copilot のアプリを操作して残りのファイルを 1 つずつ送り(Think Deeper)、返答を取り込んでレポートに反映する(動いている間は上の帯に出て、ログをダイアログに出す)。選んだ方法はブラウザに覚える([judge.md の 2](judge.md#2-外部の-llm-で判定する)) |
| 判定する… →「ZIP にまとめてエージェントに渡す」 | 同じダイアログで方法を切り替える(工数・依頼ごとの採用・タスクの紐づけのどれでも選べる) | フォルダやファイルを読めるエージェントやローカルの LLM に、バンドルを 1 つの ZIP で渡す流れ([judge.md の「エージェントやローカルの LLM に渡す」](judge.md#エージェントやローカルの-llm-に渡す))。手順は 4 つ。(1) 「未判定 N 件で ZIP を作る」で、未判定のセッションのバンドルと `out/bundle.zip` を同じ回に作る(`bundle --unjudged --zip`。「チャットに貼って判定する」の添付ファイルも作り直される)。(2) 「bundle.zip をダウンロード」と依頼文のコピーを出す(保存した ZIP を展開し、できた `bundle` フォルダだけをエージェントに開かせる。依頼文は、結果をそのフォルダの中の `judgments.json` に書かせる。ターミナルの返答を写すと、行の折り返しで JSON が壊れて取り込めないことがあるため。出力先の中の ZIP の場所は出さない)。(3) エージェントに書かせた `judgments.json` か返答を保存したファイルを選んで(貼り付けてもよい)「取り込む」。(4) 「レポートに反映する」。手順の上に、中身を渡してよい相手か確かめることと、ツールを使えるエージェントにはシェルの実行と Web へのアクセスを許可しないこと、書き込みを許可するのは結果のファイルだけにすること、出力先(`out/`)を開かせないことを出す。前のバンドルから作った ZIP は出さない(`--zip` なしで作り直すと消える)。依頼ごとの採用は `turn-bundle.zip`(`turn-judgments.json`)、タスクの紐づけは `task-bundle.zip`(`links.json`)で、ほかは同じ |
| 設定… | レポートの右上 | `setup.bat` と同じ設定を画面で決める(どれも押した時点で `atlas.config.json` に書く。設定ファイルを読めないときは理由を出して変えさせない)。**llm-wiki の vault**: 「エクスプローラーで選ぶ…」かフォルダ名・パスの入力で調べ、実在すればフォルダ名だけにして中の `index.md` と `wiki/` を見る。個別ページのフォルダ(既定は `wiki/` があればそれ)・索引のファイル名(`index.md` が無いとき)・wiki の skill として数えるもの(インストール済みの skill のうち名前に `wiki` を含むもの)を確かめてから足す。外すこともできる。変えたら「集計し直す」で反映される(ダイアログにも「集計し直す」が出る)。**普段の工程名**: `/` か `,` で区切って 2 つ以上。「既定に戻す」もある。**アップロード先**: `upload-project.bat` と毎日自動で送るタスクが写す先の基底のフォルダ(「エクスプローラーで選ぶ…」か、フルパスの入力)。**まとめて送るプロジェクト**: 「プロジェクト別」の表の「まとめて送る」と同じ印を、名前で絞り込んで付け外しする(空のセッションだけのプロジェクトは出さない。送れるものが無いため) |
| 記録を読む ↗ | 詳細ページの表題の下 | そのセッションの記録(`out/sessions/<id>.md`)を別のウィンドウで読む。見出しの目次つき。詳細ページはそのまま残る |
| 全文を作って読む ↗ | 詳細ページの表題の下 | そのセッションの全文記録だけを作って(`out/full/<id>.md` と `out/full/assets/<id>/`。他のファイルは作り直さない)、別のウィンドウで読む(押すとすぐ空のウィンドウが開き、できたらそこに表示。もう一度開くときは状態の行の「全文記録を開く」) |
| 判定する… →「タスクの紐づけ」 | 同じダイアログで判定するものを切り替える(設定に `tasks` があるか、タスクの記録があって、読むだけの画面でないときだけ) | 機械で紐づかなかったセッション(依頼の記録があって、紐づけの無いもの)を、外部の LLM に管理ツールのタスクに紐づけさせる([judge.md の 4](judge.md#4-管理ツールのタスクへの紐づけ))。手順は工数と同じ 4 つで、手順 1 のボタンは「紐づけの無い N 件で作る」(`tasks bundle`。ZIP なら `tasks bundle --zip`)、添付ファイルは `out/task-bundle/parts/`(ダウンロードの名前は `tasks-part-01.txt` など)、ZIP は `out/task-bundle.zip`(結果を書かせるファイルは `links.json`)。手順の上に、題名・最初の依頼の文と候補のタスクを渡すことと、手で決めた紐づけと前に LLM で決めた紐づけは変えないことを出す。取り込むと `atlas-notes/task-links.json` に紐づけの出所 LLM で書き、書かなかったセッション(取り込む前に手動か LLM で紐づいていたもの)の数を結果の文に出す。候補に無い ID だけの答えなど形の合わない項目が 1 件でもあれば何も書かず、直す点を出す |
| タスクの紐づけを変える… | 詳細ページの表題の下の「タスク」の行(読むだけの画面には出ない) | 「変える…」で、紐づけるタスクの札(今の紐づけから始まる。札ごとに「外す」。10 件まで)、探す欄(ID か名前の一部。打ち終えると合った数を状態の行で知らせる)と加えるタスクの選択(札にあるものは除く。未完了が先。完了と XML に無いものには印)と「加える」、「保存」「どのタスクでもない」「自動に戻す」「閉じる」が開く。加える・外すは下書きで、「保存」で札のタスクを手動の紐づけにする(札が空なら押せない。「どのタスクでもない」は押すとすぐ保存する)。外すと、焦点は次の札の「外す」(無ければ探す欄)に移る。タスクの一覧に無い ID の札には「一覧にないタスク」の印を付ける(そのままでは保存できず、サーバはどの ID が無いかを書いて断るので、その文を失敗の枠に出す)。保存すると `atlas-notes/task-links.json` に手動の紐づけを書き、行をすぐ書き直す。押せないボタンは `aria-disabled` にして焦点を受けたままにし(保存の間も焦点を失わない)、Esc(漢字の変換中は除く)で閉じて「変える…」に焦点を戻す。「自動に戻す」は手動か LLM の紐づけを外し、機械の紐づけをすぐ決め直す(LLM には聞き直さない。機械の紐づけのときは押せない)。レポートの画面は開き直すと今の紐づけを読む。`tasks.csv` は次の集計で作り直す |

- **実行中**: 帯に経過時間と、出力の最後の 1 行が出ます。「止める」で止められます。M365 Copilot の自動の判定は 1 ファイルずつ取り込んでいるので、止めても取り込んだ分は残り、次の「集計し直す」でレポートに出ます。集計を途中で止めたときは、レポートが作り直しの途中かもしれないので、もう一度「集計し直す」を押してください。
- **失敗したとき**: 帯に終了コードと、出力の末尾(200 行まで)を開けるログが出ます。M365 Copilot の自動の判定で一部のファイルが失敗したときも、取り込めた分はレポートに反映されるので「再読み込み」が出ます。
- **画面を閉じても処理は最後まで続きます**。サーバは処理が終わってから、画面が開いていなければ止まります。
- **記録の表示**は、メモと同じ規則で描きます。生の HTML は文字のまま(atlas 自身が書く `<small>` `<details>` `<summary>` の属性の無い形だけはタグとして描きます)、リンクは http / https / mailto だけ、外部の画像は読み込みません。全文記録だけは、そのセッションの `out/full/assets/<id>/` にある画像とファイルへのリンクを通します。20MB を超える `.md` は描かず、大きさと「.md を開く」を出します。
- 記録の本文はサーバに token を付けて取りに行くので、`atlas.bat` から開いた画面からしか読めません(表示のアドレス `/view/<id>` を他のページから開いても本文は出ません)。
- 画面から集計し直すときは `atlas.bat` に渡した引数(`--since` など)を引き継ぎません(既定の `all`)。絞り込んだ集計はコマンドで行ってください。

### 別のフォルダを開く

管理する人が、アップロード先(NAS や共有フォルダ)に集まったセッションを見るための操作です。いつもの画面(この PC のセッション)はそのまま残り、選んだフォルダのレポートが新しいタブで開きます。

- **選べるフォルダ**: 送り先が `<送り先>\<名前>\<プロジェクト>\<セッション ID>\` の形なら、`<送り先>` を選ぶと全員の分、`<名前>` を選ぶとその人の分、`<プロジェクト>` を選ぶとそのプロジェクトの分になります。読むのは 2 段下までです。`~/.copilot` の形のフォルダ(別の PC から写したものなど)も選べます。
- **初めからフォルダを選んで開く**: いつもの画面を開かずに始めるときは、`open-folder.bat` を使います(選ぶ画面が出て、選んだフォルダを集計して開きます。出力先とメモは、この画面から開いたときと同じです。[README](../README.md#アップロードされたセッションを集計する別のフォルダを開く))。
- **フォルダを選ぶ**: 「エクスプローラーで選ぶ…」(Windows だけ)か、フルパスを入れて「調べる」。調べると、フォルダ名と、何を読むか(人のフォルダなら「下のフォルダ 2 件をまとめて集計します(proj-a、proj-b)」、送り先なら「2 段下まで読み、2 個のフォルダ(person-a、person-b)の下にある 3 件のフォルダをまとめて集計します」のように、入る人のフォルダの名前)が出ます。集計できないとき(フルパスでない・見つからない・セッションが無い)は、その理由が出ます。エクスプローラーの「パスのコピー」で付く `"…"` は付けたままで構いません。
- **集計して開く**: 押すと、「開いたことのあるフォルダ」にそのフォルダが「集計しています…」(進み具合の最後の 1 行つき)で並びます。終わると「開いています」に変わり、新しいタブで開きます。タブが開かなかったときは、行の「表示する」を押してください。ダイアログやこの画面を閉じても集計は続きます。
- **開いたことのあるフォルダ**: 新しく開いた順に 30 件まで並びます。行の状態は次のとおりです。

  | 状態 | 出るもの |
  |---|---|
  | 集計しています… | 進み具合。終わるまで操作は出ません |
  | 開いています | 「表示する」(新しいタブ) |
  | 前に開いた日時 | 「集計して開く」(フォルダを読み直してから開きます。前に集計したときから何も変わっていなければ、作り直さずにそのときのレポートを開くので、すぐに開きます) |
  | 失敗しました: <理由> | 理由(分からないときは、記録 `open.log` の場所)と、「もう一度開く」 |
  | この画面で表示中 | そのフォルダの画面で見ているとき。操作は出ません |

  「一覧から外す」は一覧から消すだけで、集計の出力とメモは残ります(もう一度同じフォルダを開くと、同じ場所を使います)。
- **開いた先の画面**: 上部に「対象: <フォルダ名>」が出て(カーソルを合わせるとフルパス)、タブの題名が「<フォルダ名> | Copilot Session Atlas」になります。この PC のセッションの画面には、どちらも出ません。「別のフォルダを開く…」を開くと、今のフォルダと、「この PC のセッションを表示する」(いつもの画面が開いているとき。閉じていれば、`atlas.bat` で開けることを出します)が出ます。そこから別のフォルダも開けます。
- **サーバと置き場**: フォルダごとに別のサーバ(`127.0.0.1` だけ。黒い窓は出ません)が立ち、そのタブを閉じると、いつもの画面と同じ決まりで止まります。いつもの画面を閉じても、開いたフォルダの画面は残ります。集計は `out-folders\<キー>\out\` に分けて置き、いつもの `out\` と `atlas-notes\` には混ぜません([cli.md の「別のフォルダを開く(open)」](cli.md#別のフォルダを開くopen))。開いた先の画面で「集計し直す」を押すと、同じフォルダを読み直します。読み直すたびに、フォルダから無くなったセッション(送り先から消したセッション・プロジェクト・人のフォルダ)は、前に写した複製も消して、レポートから外します。前にあったフォルダを読めなかったとき(アクセス権・つながらない共有フォルダ)などは、無くなったとみなさずに前の複製で数え、レポートの警告に出します([cli.md の「snapshot と extract が読むもの」](cli.md#snapshot-と-extract-が読むもの) の「元のフォルダから無くなったセッションは、複製も消します」)。「設定…」は、いつもの画面と同じ `atlas.config.json` を書きます。
- **開いた先は読むだけ**: 上部に「読むだけ」と出ます。メモは、送った人が付けていたもの(アップロードしたときに各セッションのフォルダに入った `atlas-memo.md`。送った時点のもの)を出します。前の版で送ったセッションの `atlas-session.json` にあるタスクタグ(`tags`)は読みません。
  - 出さない操作: メモを書く、「まとめて送る」の印(表と設定)。サーバも、これらの書き換えを断ります(画面を通さずに呼んでも)。
  - 使える操作: 「集計し直す」「判定する…」(この PC の出力先 `out-folders\<キー>\out\` に書くだけで、送り先は書き換えません)、「全文を作って読む」、「設定…」(いつもの画面と同じ `atlas.config.json`)、「別のフォルダを開く…」。
  - 前の版で、開いた先の画面に書いたメモとタスクタグ(`atlas-notes\folders\<キー>\`)は、ファイルには残りますが、画面には出しません。
- **設定のフォルダ**(共有の `AtlasSettings`。[README の「本番の置き方」](../README.md#本番の置き方sessionlog-と-atlassettings)): 開いたフォルダから上へ探して `AtlasSettings\atlas.config.json` が見つかったとき(か、前にそのフォルダを開いたときに使ったとき・`--settings` で指したとき)は、開いた先の画面の上部に「設定: <設定のフォルダの名前>」が出ます(カーソルを合わせるとフルパス)。「別のフォルダを開く…」で調べた結果にも、同じ札と「上のフォルダで見つけた設定のフォルダを使います」(前に使ったものなら「前にこのフォルダを開いたときの…」)が出ます。
  - 集計は、その `atlas.config.json` を設定として読みます。「設定…」で変えた wiki と工程名も、その設定ファイルに書きます。このときダイアログの先頭に「共有の設定(AtlasSettings)を書き換えます。ほかの集計する人の結果も変わります」と出て、ボタンも「共有の設定に保存」「この vault を共有の設定に足す」「共有の設定から外す」「共有の設定を既定に戻す」になります。書き換えたら、サーバのログ(黒い窓)に「共有の設定(<フォルダ>)を書き換えました: …」と 1 行残します。
  - 工数と依頼ごとの判定は、設定に `tasks` が無くても、設定のフォルダの `judgments.json`・`turn-judgments.json` に書き、集計する人のあいだで共有します。「判定する…」の取り込み・未判定の数・判定済みの数は、どれもこの置き場から数えます。人のフォルダを開いた画面と、`SessionLog` の根を開いた画面で、同じ判定を使います。
  - その設定に `tasks` があれば、タスクの紐づけは読むだけにしません(メモは読むだけのまま。「読むだけ」の札の説明もそう変わります): 「判定する…」の「タスクの紐づけ」と、詳細ページの「タスクの紐づけを変える…」が出て、設定のフォルダの `task-links.json` に書きます。タスクの節は設定のフォルダの記録から作り、送った人が添えた記録は使いません。
- **送った atlas の版**: 送り先から集計した画面の上部に「送った atlas: すべて最新」か、「送った atlas: 対応が要る人 3 人」のような注意(色付き)が出ます。数えるのは人です(送り先をまとめて開いたとき。同じ人が何件送っていても 1 人)。カーソルを合わせると、理由ごとの人数(「5 人のうち 対応が要る人 3 人(古い atlas で送った人 2 人・書き換えた atlas で送った人 1 人)」)、最新の atlas、対応が要る人の一覧(1 人 1 行。理由とセッションの数、当てはまるフォルダ、使った atlas、そのフォルダを送った日付)、理由ごとの頼むこと、最新の atlas で送った人、この PC の atlas が出ます。理由は次の 5 つです。「古い atlas で送った」は、最新より前の atlas で送った人です。`atlas.bat` を開いてもらう(開くと最新になります)か、定期の自動送信(送る前に最新にします)を待ってから、送り直してもらってください。「書き換えた atlas で送った」は、atlas のフォルダのファイル(git が管理しているもの)を書き換えたまま送った人です。書き換えたファイルを元に戻してから(`git status` で分かります。戻すまで自動の更新も止まります)、送り直してもらってください。「版の記録が無い」は、版を記録する前の atlas で送ったか、atlas を使わずに置いたセッションです(今の atlas で一度送れば、変わっていないセッションにも記録が付きます。ログは写し直しません)。「版の新旧が分からない」は、git で取得していないフォルダの atlas で送った人です。「送った記録を読めない」は、フォルダの索引を読めなかった人で、送っている最中に集計したときに出ることがあり、集計し直すと消えることがあります。セッションがすべて最新でも、最後に送ったときの atlas が最新でない(または書き換えた atlas だった)フォルダがあれば、その人を同じ理由で数えます。最新の atlas は、送った atlas とこの PC の atlas のうち、コミットの日時がいちばん後のものです。人のフォルダやプロジェクトのフォルダを開いたときは、送った人が 1 人なので、タグはセッションの数(「古い atlas で送ったセッション 3 件」)、内訳はフォルダごとになります。数え方は [cli.md の「snapshot と extract が読むもの」](cli.md#snapshot-と-extract-が読むもの)の「送った atlas の版を数えます」。
  - `atlas all --home <送り先>` で集計した画面も、`atlas serve`(`atlas.bat`)で開くと同じく読むだけです。
  - 送った人のメモは、本文 1 MB まで・画像は 1 セッションで合計 100 MB までを出します(超えるものは写しません)。
- **もう開いているフォルダ**をもう一度「集計して開く」と、集計し直さずに、一覧の見出しの下に「<フォルダ名> はもう開いています」と出て、その行の「表示する」に移ります(そこから開けます)。集計し直すには、開いた先の画面で「集計し直す」を押します。
- **一覧の読み直し**: このダイアログを開いている間、集計中のフォルダがあれば 1.5 秒ごと、開いているフォルダがあれば 5 秒ごとに一覧を読み直します(開いた先のタブを閉じてサーバが止まると、「開いています」が「前に開いた日時」に変わり、「表示する」が「集計して開く」に変わります。見出しの下の「表示するを押してください」の知らせも消えます)。ほかのタブからこの画面に戻ったときにも読み直します。
- **判定(工数・依頼ごとの採用)** の添付ファイルは、開いた先の画面でもそのフォルダの出力先に作ります(取り込んだ判定は、設定のフォルダを使うときは設定のフォルダに、使わないときはそのフォルダの出力先に書きます)。ほかの人のログを外部の LLM に渡すことになるので、渡してよいかを確かめてから使ってください。タスクの紐づけは、読むだけの画面では出ません(紐づけは送った人のもの。設定のフォルダの設定に `tasks` があるときは出ます)。

## 画面の見方

- **上部**: 生成日時、記録期間、「記録 N 件のうち M 件を集計対象にしています(空のセッション K 件を除外)」の 1 文、配色の切り替え(自動 / ライト / ダーク)。
- **目次と件数**: 幅 768px 以上では左にサイドバーが固定され、各欄へのリンクを 概況(全体・要点・改善点(llm-wiki の参照を数えたレポートでは、その下に改善点の「llm-wiki の利用」の箱へ飛ぶ「llm-wiki」)・工程と詰まり・集計明細・AI の変更の残存(照合してあるときだけ)・比べる)/ 内訳(利用ランキング・実行の性質・プロジェクト別・月別推移・モデル別・モデルと推論強度の効果。送り先の全体を集計したレポートでは、プロジェクト別の前に人別)/ 一覧(セッション一覧)/ 付録(失敗の台帳の集計、指示文と skill、用語の説明。どれも別ページ)の 4 群に分けて並べます。概況・内訳・一覧の群の題は、その下の「タブ」へのリンクで、今開いているタブの題は緑の地で示します。別のタブの欄を押すと、そのタブに切り替えてからその欄へ移ります。スクロールに合わせて、今のタブの中で読んでいる欄に印が付き、下に「表示中 N / 集計対象 M セッション」、絞り込みが効いているときは「K 条件で絞り込み中」の印と「解除」が出ます。768px 未満ではサイドバーの代わりに上部に細い目次の行が固定され(横に流れます。現在地に印)、行の先頭にタブ(概況・内訳・一覧。今のタブは緑の地)、続いて今のタブの欄と付録が並び、右端に件数と「解除」が出ます。母数の M は上部の 1 文の M と揃えています。
- **タブ**: 本文は 概況 / 内訳 / 一覧 の 3 つのタブに分かれています(目次の群と同じ分け方。付録は別ページ)。絞り込みの行の下にタブの帯があり、押すとそのタブの欄だけが出ます(開いたときは概況)。ページの途中で押すと、帯が画面の上端に来る位置へ移ります。タブを切り替えると履歴に残るので、ブラウザの「戻る」「進む」で前のタブとその位置に戻れ、再読み込みしても同じタブと位置で開きます。今のタブは URL の `#…&tab=breakdown`(内訳)・`#…&tab=list`(一覧)に残り(概況は書きません)、絞り込みの条件を変えてもタブはそのままです。タブは絞り込みの条件ではないので、「K 条件で絞り込み中」には数えず、「解除」でも変わりません。ページ内の欄へのリンク(詳細ページの「工程と詰まり」への `atlas.html#phases` や、要点・集計明細の中のリンク)は、行き先のあるタブを開いてからその欄へ移ります。要点の「このツールを使ったセッションに絞り込む」は、絞り込んでから一覧のタブを開きます(「戻る」で絞り込みが外れ、元のタブと位置に戻ります)。「戻る」などでタブが替わって、焦点のあった部品が隠れたときは、焦点はタブの帯の今のタブに移ります。ブラウザのページ内検索(Ctrl+F)は、今開いているタブの中だけを探します(ほかのタブの中身は、そのタブを開いてから探します)。印刷するときは、どのタブの欄もすべて出ます(タブの帯は出ません)。
- **絞り込み**: 1 行目に期間(開始日・終了日・直近 30 / 90 日)・プロジェクト・クライアント・モデル(送り先の全体を集計したレポートでは、プロジェクトの前に「人」。下記「人別」)・タスク(管理ツールのタスクの記録があるときだけ。「すべて」「タスクなし(件数)」と、セッションの紐づいたタスクを「名前 · ID(件数)」(長い名前は縮め、全文は重ねると出る)で、件数の多い順。タスクなしには「どのタスクでもない」と決めたものも入る。URL の `#…&task=<ID>`、タスクなしは `task=(none)`)、「その他の条件」を開くとブランチ・入力トークン記録の有無・タスク分類・空のセッションの切り替えが出ます(どれかが効いている間は閉じられず、効いている数を印で出します)。llm-wiki の参照を数えたレポートで、参照したセッションがあるときは、「その他の条件」に「wiki を参照したセッションだけ(件数)」も出ます(集計明細・改善点の「llm-wiki の利用」と同じ数え方で、書き込みだけのセッションは入れません。URL の `#…&wiki=1`)。絞ると下の欄がすべてその条件で集計し直され、サイドバー(狭い画面では上部の固定行)の「表示中 N / 集計対象 M セッション」が今の件数です。絞り込み行そのものは固定せず、スクロールすると流れます(条件を変えるときは上に戻ります)。キーボードでは Tab で順に移り、押した部品に緑の枠が出ます(日付入力は年・月・日の 3 区画で Tab を使うブラウザの仕様です)。**空のセッション**(依頼・ツール呼び出し・応答がどれも無い、開いただけのもの)は既定で集計・一覧・プロジェクト表・中央値のすべてから外しています。「その他の条件」の「空のセッションを含める」にチェックすると含めます(このときの「集計対象 M」は空を含めた件数)。条件は URL の `#` 以降に残るので、ブックマークすれば同じ絞り込みで開けます。タスク分類は LLM による判定(judgments.json)があるときだけ選べます(無いときは理由を欄の下に出します)。
- **要点**: 絞り込み後の集計から決まった規則で選んだ短い一覧です(LLM は使いません)。AI 使用量(AIU)の大きいセッション上位 3 件(AIU の記録が無い条件では出力トークンの多い順)、失敗率の高いツール(結果の記録が 5 回以上で失敗・拒否のあったもの。失敗の要因の記録があれば、いちばん多い要因を添えます)、compaction の多いセッション、インストール済みで未使用の skill。各項目にはリンクがあり、セッションならその詳細ページ、ツールなら今の絞り込みに「そのツールを使ったセッション」を足した状態(URL の `#…&tool=<ツール名>`)、未使用の skill なら利用ランキングの未使用一覧に移ります。ツールで絞っているときは絞り込み行に「<ツール名> を使った ×」が出て、押すと外れます。
- **全体サマリ(表紙)**: 規模の 4 欄(セッション数、期間、実働時間、推定人手工数)。帳票の「表紙 → 摘要(要点)→ 明細」の順に並べているので、この下に要点、その下に集計明細が来ます。空のセッションを外しているときは、その件数を「空のセッション N 件を除外」と出します。
  - **管理ツールのタスクの工数**(タスクの記録があるときだけ。「管理ツールのタスク」の節が出る条件と同じ): 4 欄の下に、幅いっぱいの 5 つ目の欄を置き、「比べられる完了タスク」と同じ範囲の 3 つの時間を並べます。タスクの所要(開始〜完了、稼働時間帯。タスクの節の「AI を使った場合の工数」)/ 推定人手工数(AI を使わなかった場合)/ AI の実働 で、値はタスクの節の欄と同じものです(集計したときに決めた値で、画面では数え直しません)。比(AI を使わなかった場合 ÷ 使った場合)は出しません(タスクの節の欄にだけあります)。欄の下に 2 つの注記を出します: 集計したときの値で、上の絞り込みに従わないこと。タスクの所要は、並行して進めたタスクのそれぞれに同じ時間が入るので、合計が実際の勤務時間を超えることがあること。比べられる完了タスクが 0 件なら、時間は「—」で、件数 0 と理由(セッションが紐づいたタスクの数と、比べないものの理由ごとの数。タスクの節と同じ言い方)を出します。「タスクの所要」は、表紙の「実働時間の合計」(AI のセッションの実働)とまぎれないように付けた名前で、用語の説明の「稼働時間帯の工数」にも書いています。狭い幅では 3 つの時間が縦に並びます。
- **集計明細**(要点の下): 4 列 × 3 行の 12 欄。トークン(入力・出力・うち推論・キャッシュ読取)、AI 使用量(AIU)、premium request、API リクエスト、ツール呼び出し(失敗率つき)、変更行数、skill・agent・hook の件数、指示ファイルと llm-wiki の利用(llm-wiki は参照したセッションの数で、書き込みだけのセッションは入れません。数え方は用語の説明の「llm-wiki」。対象の vault は「[wiki の指定](cli.md#wiki-の指定)」。vault を指定せずに集計したレポートでは wiki の欄を出さず、見出しの下に数えていない理由を出します)、摩擦の合計。各欄の下の注記は 1 行程度に抑え、摩擦の内訳の続きは「実行の性質」へのリンクにしています。**入力トークン・AI 使用量・premium request・変更行数は記録が残っているセッションだけの合計**で、欄の下に「記録あり N / M セッション」を出します。
  - AI 使用量は nano AIU を 10 億で割った AIU で、桁区切りで表示します。金額には換算しません。premium request は旧来の課金単位で、記録のある(主に 2026 年 7 月以前の)セッションだけの合計です。
  - 変更行数(追加 / 削除)は、セッション終了時の累計(`session.shutdown` の `codeChanges`)を優先し、無ければツールごとの行数(`toolTelemetry`)を合計したものです。
  - 依頼の回数には、autopilot が自分で作業を続けるときの自動継続(ログ上はユーザーのメッセージとして残る)を含めず、別に「自動継続 N 回」と出します。
  - ツール呼び出しの回数には、作業の途中経過を画面に出すための内部ツール(`report_intent`)を含めず、件数だけ別に出します。
  - 摩擦の内訳では「ツール失敗」(個々のツール呼び出しの失敗)と「エラー」(`session.error`。利用上限・通信エラーなどセッション全体のエラー)を分けています。
  - その下の「入力トークン記録の内訳」で、明細あり / 終了時の累計のみ / 出力のみ / **記録なし(欠測)** の件数を確認できます。記録なし(欠測)は、依頼や応答があるのにトークン量の記録がどこにも無いセッションです(2026 年 9 月以降のログは `assistant.message` に出力トークン数を書かなくなったため、session-store.db・usage_record・終了時の累計のどれも無いと出力トークンも分かりません)。0 として足さず、件数で示します。帯の欠測の区画は色に加えて斜線で区別しています。
  - 帯の下に、画面で使う欠測の語の凡例を置いています: **記録なし**(ログにその項目の記録が無い)/ **推計不可**(出力トークンだけ記録があり入力は求められない)/ **未判定**(LLM の工数判定をまだ実行していない)/ **不明**(記録はあるが分類できない。クライアント・モデルなど)/ **—**(該当なし)。用語の説明ページの先頭にも同じ凡例があります。
- **改善点の「llm-wiki のページごとの参照率と役立った率」**: 改善点の「絞り込みに従う」群の最後に、幅いっぱいの箱で出します(列が多いので、ほかの箱と横に並べません)。ページ 1 行の表で、列は ページ / 読んだセッション / 参照率 / 役立った / 役立たなかった / 分からない / 未判定 / 役立った率。読んだセッションの多い順(同じならページの名前の順)に上位 10 行を出し、残りは「全件を表で見る」で開きます。上の絞り込みに従います。中身は [outputs.md](outputs.md#改善点規則による分析) の表のとおりです。
  - **ページの名前**: 全ページに共通のフォルダ(`wiki/topics/` など)と `.md` を除いて出し、何を除いたかを注に書きます(`.md` を除くと名前が重なるときは除きません)。元の名前は、名前に重ねると出ます。
  - **読んだセッションを開く**: ページの名前を押すと(キーボードでは Enter)、すぐ下の行に、そのページを読んだセッション(新しい順。詳細ページへのリンク)と、それぞれの役立ったかの見立て(役立った / 役立たなかった / 分からない / 未判定)が開きます。もう一度押すと閉じます。並べるのは 50 セッションまでで、残りは件数だけ出します(絞り込みで狭めると全部出ます)。
  - **並べ替え**: 列の見出しを押すと、その列で並べ替えます(数の列ははじめ多い順・高い順、ページははじめ名前の順。もう一度押すと逆)。上位 10 行と「全件を表で見る」の表は同じ並びで、並べている列は見出しの印と `aria-sort`、表の題(「分からないの多い順」など)で示します。率が「—」のページは、どちらの向きでも後ろに並べます。
  - **参照率** = そのページを読んだセッション ÷ wiki を参照したセッション(集計明細・改善点の「llm-wiki の利用」と同じ数え方。書き込みだけのセッションは入れません)。wiki を参照したセッションの件数を表の題に出します。ログで分かるのは「読んだ」ことまでなので、言葉は「引用」でなく「参照率」で、注に「回答の中で引用したかは見ていません」と書きます。
  - **役立った・役立たなかった・分からない** は、判定を回したセッションの LLM の見立ての件数です([judge.md の「llm-wiki のページごとの判定」](judge.md#llm-wiki-のページごとの判定))。**未判定** は、判定していないセッション、ページごとの判定が無い前の版の判定、判定に載せなかったページ(1 セッション 10 ページまで)、返答の形が崩れていたページです。**役立った率** = 役立った ÷(役立った + 役立たなかった)で、分からない・未判定は分母に入れません。注に「役立ったかは LLM の見立てで、判定役は読んだページの名前と、ログにあれば抜粋を見たうえで答えています。測った値ではありません」と書きます。
  - 率は、分母(参照率は wiki を参照したセッション、役立った率は役立った + 役立たなかった)が改善点のほかの率と同じ閾値(`packages/report/src/lib/insights.ts` の `THRESHOLDS.MIN_SESSIONS`)に届かなければ「—」です。どのページも「—」になる率は、列ごと出さずに、出さない理由(wiki を参照したセッションの件数が閾値に届かない / 役立った + 役立たなかったが閾値に届くページが無い)を注に書きます(閾値も実行時の値を出します)。参照率(ログ)と役立った率(LLM の見立て)は別の列のままで、1 つの点数にまとめません。セッション全体の判定の「llm-wiki の効果」(−2〜+2)はそのまま残り、この表には使いません。
  - vault を指定せずに集計したレポート・指定の記録が無い古い集計では、表を出さずに「llm-wiki の利用」の箱と同じ理由の文だけを出します。ページの名前を記録する前の版(埋め込みの版 17 以前)で作った `atlas.html` でも表を出さず、集計し直すと出ることを書きます。詳細ページの「LLM による判定(推定)」には、そのセッションのページごとの見立てと理由を出します。
- **工程と詰まり**(改善点の下): 依頼(ターン。利用者の 1 回の依頼から次の依頼の直前まで)ごとに、AI が主にしたこと(工程)とその間のつまずきを数えた表です。工程はその依頼で使ったツール(サブエージェントの分を含む)から決めます: 編集があれば実装、無くてテスト・ビルドを実行していれば検証、git のコミット・push などがあれば運用、計画・確認だけなら計画、ツールを使わなければ回答のみ、それ以外は調査。LLM は使いません。
    - **工程別**: 依頼の数と割合、実働時間、AI 使用量、詰まりのあった依頼(ツールの失敗・拒否・中断・エラー・前の依頼で編集したファイルの再編集・文脈圧縮のどれかがあったもの)の数と割合、それぞれの回数(エラーの括弧内は利用上限・速度制限によるもの)、「次の依頼で直し・差し戻し」(次の依頼が「直して」「戻して」などだった依頼 / 次の依頼があった依頼)。最後の行が合計です。
    - **依頼の種類 × 工程**: 依頼文の語で粗く分けた種類(作業 / 質問 / 修正 / 差し戻し / 続行)が、どの工程で起きたかの件数。「どこで聞いているか」を見る表です。言い回しの違う修正は「作業」に入ることがあります。
    - **採用(LLM の判定)**(依頼ごとの判定があるときだけ。無いときは判定のしかたの案内): 普段の工程別に、判定した依頼の数、作業の依頼の扱い(そのまま / 中身を修正 / 体裁を修正 / 不採用)と採用率(判定できた作業の依頼のうち「そのまま」の割合)、質問の依頼の扱い(役に立った / 追加で聞いた / 的外れ)と役に立った率、判定不能。その下に、合わなかった点(意図・要件の取り違え / 誤り・不具合 / 品質・体裁・決まりごと / やり過ぎ・足りない / 環境・ツール・権限 / その他)× 普段の工程の件数。どれも次の依頼の文から LLM が決めた推定です。絞り込んだセッションに、依頼の数が 1 セッションの上限(200)を超えたものがあれば、見出しの下に「上限を超えて束に入らなかった依頼が N 件(M セッション)あり、判定しません」と出します。
    - 絞り込みに合わせて集計し直します。1 セッションの先頭 200 依頼までを数えます。依頼があるのに依頼ごとの記録が無いセッション(古い集計など)は件数を断ります(「集計し直す」で入ります)。
- **AI 投入量 vs 推定人手工数**(判定結果があるときだけ): 判定済みのセッションについて、LLM が推定した人手工数(幅と平均確信度つき)と、同じセッションで AI が使った実働時間・トークンを全体とプロジェクト別に並べます。「推定人手工数 ÷ AI の実働」は目安で、削減量の実測ではありません。確信度が 30% 以下の推定は、合計・幅・中央値・「推定人手工数 ÷ AI の実働」に入れず、「確信度が 30% 以下の推定 N セッション(計 H 時間、幅 …)は、合計にも…入れていません」と別に出します(プロジェクト別の表では「別枠 H 時間(確信度の低い N 件)」。全体サマリの推定人手工数の欄と、プロジェクト別集計の列にも短く出します)。AI が大量に生成して動くかを確かめられないセッションなど、推定の根拠が弱いものです。合計の横には中央値(1 セッションあたり)も出します。合計に入れたセッションが 5 件以上で、推定の大きい上位 5% のセッション(1 件に満たなければ 1 件)が合計の半分以上を占めるときは、「合計の N% は、推定の大きい上位 M セッション(計 H 時間)によるものです」と出します(全体サマリの推定人手工数の欄にも短く出します)。合計は和なので、AI が大量に生成したセッションの大きな推定が数件あるだけで、ほぼその値になるためです。
- **管理ツールのタスク**(設定に `tasks` があるか、タスクの記録があるときだけ。概況の「AI 投入量 vs 推定人手工数」の次): 管理ツールのタスクごとに、紐づいたセッションの工数を並べます。値は集計したときのもの(serve から開いた画面は、開いたときのサーバの値。`--task` などで絞って作ったレポートは、サーバの値で置き換えずに集計したときの値)で、上の絞り込みは掛かりません。

  - 欄の下に、3 つの値の意味を 1 行ずつ書きます(稼働時間帯の曜日と時刻、祝日は区別しないこと、完了を確認した時刻は、設定の `tasks.doneAt` で XML の完了日時を読めればその日時(記録)、無ければ XML で完了と分かった時刻(観測)で、観測は書き出しの間隔の分だけ遅れること。完了したタスクの、記録と観測の件数)。「比べられる完了タスク」の欄の注記にも、比べるもののうち記録と観測の件数を出します(全体サマリの表紙のタスクの工数の注記も同じ)。続けて「複数のタスクに紐づくセッションの実働時間と推定人手工数は、タスクの数で等分して数えます」と、そのセッションの数を書きます。

  - **詰まりの列**(Rust の `tasks::extras` が決め、画面は出すだけ): 紐づいたセッションすべてを 1 つずつ数えます(工数と違い、複数のタスクに紐づくセッションも等分しません。セッションの列と同じ数え方)。
    - 人数: 人の記録(送り先の人のフォルダ)のあるセッションの、人の数。どのタスクにも人の記録が無ければ列を出しません(この PC だけの集計)。

- **AI の変更の残存**(`atlas vcs` で照合してあるときだけ。`atlas.bat` の集計にも入る): AI が足した行が、その後の VCS のファイルに残っているかを、絞り込んだセッションで数えます。残っているかの記録で、採用の意図や良し悪しではなく、「見つからない」「照合不可」を不採用とはみなさないことを、節の説明に書いています(詳細ページの同じ節も)。見出しの横に、比べる版と照合した日時を出します。照合の範囲の下に、セッションの終わりから比べた時点までの日数(中央値と幅)を出します。設定の `vcs.note` があれば、その一文も出します。

  - プロジェクトごと: AI の変更があったプロジェクトの、状態別のまとまりの数と割合(照合できたセッションが 5 件未満のプロジェクトは件数だけ)。

  - プロジェクトは、ログの repository、無ければ git の origin(「所有者/リポジトリ」)で束ねます。同じリポジトリの別フォルダや worktree で開いたセッションも 1 つになります。ホームディレクトリそのもので開いたものは「(ホーム)」、一時フォルダ(`%TEMP%` 配下。scratchpad での試行など)は「(一時フォルダ)」、このツール自身の工数判定(`judge run` が作る `%TEMP%\atlas-judge-cwd-*`)は「(atlas の判定)」にまとめます。どれにも当たらないものは作業フォルダのパスのままです。
- **月別推移**: セッション数・出力トークン・入力トークン・AI 使用量(AIU)・premium request の月別の棒グラフ(月は UTC)。棒にマウスを乗せるかキーボードで選ぶと値が出ます。棒を押す(Enter / Space)と値の表示を固定でき、もう一度押すと外れます。「表で見る」で同じ値と変更行数を表で確認できます。AIU と premium request は記録のあるセッションだけの合計です。
- **モデル別**: モデルごとのトークンとリクエスト数。1 セッションで複数のモデルを使うことがあるため、セッション数の合計は全体と一致しません。表には推論強度別のリクエスト数(「high 120・medium 30」)も出ます。「推論強度で分ける」を押すと、棒と表が モデル × 推論強度 の行になります(強度の決め方は実行の性質の推論強度別と同じ。どちらも記録が無いリクエストは「不明」、強度を記録していない古い集計から作ったセッションは「強度の記録なし」。キャッシュ読取は強度別には数えません)。同じモデルがログの出所によって `claude-haiku-5-5` / `claude-haiku-5.5` / `<ID>/claude-haiku-5-5` のように書き分けられているため、`claude-haiku-5.5` の形にそろえています(`claude-<種類>-<数字>-<1 桁の数字>` で後ろに日付などが続かないものだけ。先頭の `<UUID>/` はプロバイダ設定の ID で、同じリクエストの記録にどちらの名前も残っていることを実データで確認しています)。
- **モデルと推論強度の効果**: モデル × 推論強度(「モデルごと」でモデルだけ)ごとに、使った量とコスト(セッション・リクエスト・1 リクエストあたりと 1 セッションあたりの AIU)と、効果(セッションの判定の達成率・品質・手戻り・1 AIU あたりの推定人手工数、依頼の判定の採用率・そのまま使えた割合、AI の変更の照合できたセッション(照合できた / AI の変更あり)と残っている割合、ツールの失敗率)を並べます。判定や照合をしていない効果の列は出ません。残っている割合は「比べる」と同じ数え方で、照合できたまとまり(照合不可を除く)のうち、残っている(そのまま + 直されて)ものの割合です。照合できたセッションが 5 件未満の行は割合を出しません(残存の節・「比べる」と同じ件数)。1 AIU あたりの推定人手工数には、確信度が 30% 以下の推定を入れません(「AI 投入量 vs 推定人手工数」の合計と同じ)。
  - 推論強度はリクエストごとに決まりますが、効果の記録はセッションや依頼ごとにしかないので、セッションの効果を、そのセッションのリクエストに占めるモデル × 推論強度の割合で按分して数えます(1 セッションの重みの合計は 1)。コストは按分せず、そのモデル × 推論強度のリクエストの実数です。
  - 表の上に読み取りを出します。同じモデルで、セッションが 5 件以上ある強度が 2 つ以上あれば、いちばん弱い強度といちばん強い強度のコストと効果の値を並べます(効果は、その記録があるセッションが按分して 5 件分以上あるものだけ)。モデルごとの 1 AIU あたりの推定人手工数も、リクエストの多い順に値を並べます(セッションが 5 件以上で、人手工数を数えた判定が按分して 5 件分以上あるモデルが 2 つ以上あるときだけ。大小の順には並べません)。5 件は「比べる」で割合と平均を出す件数と同じです。按分した値はセッションを単位にした差の幅(95%)を出せないので、読み取りは値を並べるだけで、差の向きを言い切りません(文にも「差の幅は出していません」と書きます)。「比べる」の推論強度(本体の推論強度が決まったセッションだけを並べる)で差の幅が出るのは、手戻りのないセッションの割合やテストの結果の割合など、セッションを単位にした割合と平均の行だけです(達成率・品質・依頼の採用率の行は無く、ツールの失敗率と AI の変更の残存の割合には幅を出しません)。
  - 人の記録が 2 人以上あれば、見出しの横に「人」の選択(すべて / 人ごと / 人の記録なし)を出し、表と読み取りを選んだ人のセッションだけで作ります(上の絞り込みの後に掛けます。選んでいた人が絞り込みでいなくなったときと、人が 1 人以下になって選択欄が消えたときは、すべてに戻します)。
  - 難しい作業ほど強い推論強度や上位のモデルを選びやすいので、差がそのまま強度やモデルの効果とは限りません。セッションが 5 件未満の行には ※ が付きます(読み取りに使う件数と同じ)。
- **セッション一覧**: 1 ページ 50 件。左端はチェック欄で、チェックした行は薄い緑になり、一覧の上の「N 件を選択中」と「選んだ N 件だけ集計」「選択を解除」が使えます(下記「[セッションの選択](#セッションの選択)」)。「開始」はセッションを始めた日時、「最終更新」は最後に更新された日時(更新日時の無いセッションは開始日時)で、どちらも列見出しを押すと新しい順・古い順に並べ替えられます。「変更行」列は追加行数(下に削除行数)。一覧の上の「セッションを探す」に、セッション ID の先頭(4 文字以上)か ID 全体、または題名(セッション名と、最初の依頼の文の先頭 160 字)の一部を入れると、合う行だけに絞ります。ID を含むパスや URL は、空白や引用符が入っていてもそのまま貼れます。ID の途中の文字では探せません(16 進の語や数字で、題名に無い行が偶然出ないように)。空白で区切ると、すべての語に合う行だけになります。全角と半角、大文字と小文字は区別しません。絞るのは一覧の行だけで、上の集計とチェックした選択は変えません(見つけた行にチェックを付けて「選んだ N 件だけ集計」を押せば、その行だけで集計できます)。ID で当たった行には ID を、名前に無く最初の依頼にだけあった語で当たった行には、最初の依頼のその辺りを出します。今の絞り込みで外れているセッションにも合うものがあれば、その件数を出します(「空のセッションを含める」だけで出る空のセッションは、別に数えます)。Esc で検索語を消せます(漢字に変換している途中の Esc では消しません)。詳細ページを開いてから戻ると、検索語も戻ります。管理ツールのタスクの記録があるときは、「セッション」の列の右に「タスク」の列を出します。紐づいたタスクの ID と名前(1 タスク 1 まとまり。ID は折り返さず、名前が長ければ 2 行で切る)と、下に小さく「紐づけ: 機械 / LLM / 手動」。3 つ以上のタスクに紐づいたセッションは 2 つまで出して「+N 件」とし、重ねると全部のタスクと紐づけの理由が出ます。紐づけが無ければ「紐づけなし」、「どのタスクでもない」と決めたものはそう出します。列見出しを押すと、最初のタスクの名前(同じなら ID)の順に並べ替えます(初めは 50 音・ABC の順、もう一度押すと逆)。タスクの無いセッションは、どちらの向きでも後ろに並びます。推定人手工数は LLM による判定を実行するまで「未判定」です。判定した日付があれば、その下に「判定 2026-11-14」のように出します(時間に重ねると、幅と、判定したモデル・日時が出ます)。依頼ごとの判定がレポートに 1 件でもあれば、「依頼」の列の件数の下に、そのセッションの依頼ごとの判定の済み具合(「未判定」「判定 n / m」「✓ 判定済み」。m は依頼ごとの記録がある依頼の数)が出ます。空のセッションを含めているときは、空のものに「空」の印が付きます。名前を押すと[セッション詳細](#セッション詳細ページ)を開きます。一覧の中に書き出しが 20 字以上同じ題名が他にあるときは、共通の書き出しを先頭の数文字だけ残して「…」に縮め(薄い色)、違いが始まるところから見せます。題名がまったく同じ行には「同じ題名 ×N」の印が付きます(開始時刻やプロジェクトで見分けてください)。全文は名前に重ねると出ます。

### skill・llm-wiki・MCP サーバー・推論強度の違いを確かめる

skill・llm-wiki・MCP サーバー・推論強度が役に立っているかは、問いを 3 つに分けて確かめます。

1. **使われているか**: 普段のログの件数で分かります。
2. **選んだ課題で、条件によって結果が変わるか**: この道具には、条件を割り当てた実行を並べる場所がありません(前の版の「課題 × 条件」の節は、タスクタグと一緒にやめました)。
3. **普段の作業全体で役に立っているか**: この道具では分かりません。

| 普段のログで分かること(相関まで) |
|---|
| **skill**: 改善点の「skill の傾向」(呼んだセッションと呼ばなかったセッションの失敗率)と、失敗の台帳の集計のページ(skill ごとの失敗) |
| **llm-wiki**: 件数まで(集計明細・プロジェクト別・改善点の「llm-wiki の利用」)。参照あり / なしの率は並べません。ページごとの参照率と、LLM の見立ての役立った率は改善点の「llm-wiki のページごとの参照率と役立った率」(どのページが読まれ、読んだ後に使われたと見立てられたか。wiki が結果を変えたかは分かりません) |
| **MCP サーバー**: 利用ランキングの回数と、失敗の台帳の集計のページ。使った / 使わなかったセッションを並べる場所はありません |
| **推論強度**: 「モデルと推論強度の効果」は、観察したセッションを強度ごとに按分したもので、題の「効果」は相関の意味です。「比べる」の強度どうしも同じです(週ごとに強度を割り当てて使ったときは、割り当てどおりかを詳細ページの実行の性質で見ます) |

普段のログの差は、何をしたセッションかの違いが混ざるので、原因は分かりません。

- **言えること**(範囲をつけて): 「この期間の普段のログでは、wiki を参照したセッションが N 件あった」。
- **言えないこと**: 「wiki を入れる前と後の期間を比べた差を、wiki のおかげとする」(その間に変わったもの、たとえば作業の種類やモデルが混ざります)。「改善点の skill の傾向で、呼んだセッションの失敗率が低いので、skill が効いている」。

## セッション詳細ページ

- **タスク**(管理ツールのタスクの記録があるときだけ): 表題の下の 1 行に、紐づいたタスクの名前(ID)・状態(XML の状態と、完了 / 未完了)・紐づけの出所(機械 / LLM / 手動と、理由。LLM なら確度)を出します。いくつかのタスクに紐づいていれば、タスクを 1 行ずつ並べ、「N つのタスクに紐づいています。実働と推定人手工数は、K つのタスクで等分して数えます」と添えます。タスクの一覧に無いタスクと、完了を確認した後に始めたセッションのタスクには工数を数えず、その行に「一覧にないタスク(工数に数えない)」「完了を確認した後に始めたセッション(工数に数えない)」の印を付けます。紐づけが無ければ「紐づけなし」、手で「どのタスクでもない」にしたものはそう出します。`atlas.bat` から開いたこの PC の画面では、行の「変える…」で紐づけを直せます(上の「[画面からの操作](#画面からの操作)」)。送り先から集計した読むだけの画面では、送った人の紐づけを出すだけです。

- **中身**: 時系列、依頼ごとの経過(下記)、ツール内訳と成功・失敗・拒否、実行の性質(モード・推論強度・起点・ツール定義・モデル別の待ち時間・ツールの所要時間・摩擦の詳細・失敗したサブエージェントの理由・todo)、skills(呼んだ側)/ agents / hooks、指示文と skill(下記)、llm-wiki の参照(vault に触れたセッションでは、索引・個別ページ・wiki の skill・書き込み・その他の回数と、「このセッションの扱い: 参照した」か「書き込みだけ(参照したセッションには数えません)」の 1 行。vault を指定せずに集計したレポートでは、参照が無いとは書かずに数えていない理由を出します)、摩擦、変更行数、変更したファイル。セッション ID は表題の下の印の列の末尾にあります。同じ印の列に、LLM 判定の済み具合が出ます。「LLM 判定(工数)」は「✓ 済み」か「未判定」(依頼の記録が無いセッションには出ません)、「LLM 判定(依頼ごと)」は判定した依頼の数 / 依頼ごとの記録がある依頼の数(全部済めば ✓、0 件なら「未判定」)です。`atlas.bat` から開いたときは、その下でこのセッションだけを判定できます(上の「[画面からの操作](#画面からの操作)」)。
- **LLM による判定(推定)**(工数を判定したセッションだけ): 「判定」の欄に、判定の方法と、判定したモデル・日時(「claude-sonnet-5-5・2026-11-14 10:23 に判定」)を出します。日時はセッションごとに `judgments.json` に残した時刻で、チャットの返答を取り込んだときは、返答に日時(`judge.ranAt`)が書いてあればその時刻、無ければ取り込んだ時刻です。セッションごとの記録が無い古い判定は、ファイル全体の記録からモデルだけを出し、日時は出しません(ファイル全体の日時は最後に書き込んだ回のもので、そのセッションを判定した日時とは限らないため)。モデルも分からなければ「判定した日時の記録なし」と出します。
- **依頼ごとの経過**: 依頼 1 件 1 行の表。開始時刻、依頼文の先頭、依頼の種類、工程、実働、ツール・失敗・拒否・中断・エラー・再編集・文脈圧縮の回数、AI 使用量。失敗の台帳のある記録では、「拒否」の右に「失敗・拒否の内訳」(ツール・要因か拒否・回数。失敗の数があるのに台帳の行が無い依頼は「記録なし」)の欄が付きます。詰まりのあった依頼には左端の印と「詰まり」、次の依頼が修正・差し戻しだったものには「次で修正」などの印を付けます。規則はレポートの「工程と詰まり」と同じです。依頼ごとの判定があれば、右端に「採用(LLM)」(判定の理由の要約つき)、「合わなかった点」、「工程(普段)」の列が付きます。
- **テストの推移**(テストの実行ファイルが印つきの行 `ATLAS_TEST_RESULT` を書いたセッションだけ。書き方は [outputs.md の「テストの結果」](outputs.md#テストの結果印つきの-1-行-json)): 上の欄に、結果(全部通った / 未達 / 通った後に不合格)、テストの実行の数、最初に全部通った実行(何回目か。その依頼の番号)、通るまでの実働と AI 使用量。下の表は実行 1 回 1 行で、完了の時刻・依頼の番号・ツール・合格 / 結果の数・落ちたテストの名前・まだ通っていないテストの数(0 なら「全部通った」)・件数の合計(テストの実行ファイルが書いた名前ごと。8 種類まで)・そこまでの実働と AI 使用量の累計。「全部通った」は、これまでに出たテストごとのいちばん新しい結果がすべて合格のことです。AI 使用量は、リクエストごとの記録が無いセッションでは「記録なし」です。読めなかった印の行などがあれば、表の下に件数を出します。
- **失敗と拒否(1 件ごと)**(失敗の台帳に行があるときだけ): ツールの失敗と拒否 1 件 1 行の表。依頼の番号(最初の依頼より前は「—」)、開始時刻、ツール(MCP サーバーとサブエージェントの名前の印つき)、種類と要因、エラー文(400 字まで)、引数(200 字まで)、その後(次に呼んだツールとその結果。同じ引数なら「同じ引数で呼び直し」の印)。表の下に、失敗・拒否のあったサブエージェントへの依頼文を 1 回ずつ載せます。以前の版で集計した記録にはこの節が無く、失敗があるときは「依頼ごとの経過」の下に断りが出ます(集計し直すと入ります)。
- **指示文と skill の表**: 注入された指示ファイルと、そのセッションで使えた skill の一覧に呼んだ回数を添えた表。呼んだものが先、一覧に無い skill を呼んだときは「一覧に無し」。使えた skill の一覧はシステムメッセージの `<available_skills>` から読むので、Copilot CLI 1.0.77 より前の版や `copilot -p` のセッションでは「一覧はこのセッションの記録にありません」と出て、呼んだものだけになります。置き場所はログの値で、user / project / builtin は「ユーザー / プロジェクト / 組み込み」、それ以外(`custom` など)はそのまま。
- **目次**: 幅 768px 以上では左のサイドバーに「レポート(セッション一覧)に戻る」(レポートから開いたときはブラウザの「戻る」と同じ動きで、絞り込みを保ったまま戻ります。詳細ページを直接開いたときや新しいタブではレポートの先頭を開きます)、節の目次(概要・トークン内訳・…・ログの状態。読んでいる節に印)、「用語の説明」、配色の切り替えが上から並びます。記録を作ってあれば(`atlas.bat`・`all`・`export`)「記録の .md をそのまま開く ↗」(別のウィンドウで開きます。整形して読むなら表題の下の「記録を読む」)「記録を .md で保存」も入ります(素の `build` では出ません)。「このセッションの指示文と skill」は、指示文と skill のページをそのセッションで使われた版だけに絞って開きます。768px 未満では上部の帯に戻る・リンク・配色、その下に固定した目次の行(横に流れ、現在地に印)が出ます。
- 詳細の「変更したファイル」は、変更・作成・削除に分けて載せます。相対パスは作業フォルダ基準の絶対パスにそろえ、同じファイルは 1 回だけ載せます(Windows では大文字小文字を区別しない)。途中で削除したファイルは、終了時の記録(`codeChanges.filesModified`)に残っていても「削除」のままにします。Copilot 自身のセッション用ファイル(`~/.copilot/session-state/` 配下の plan.md など)は一覧から外し、件数だけ書きます。
- 応答の件数には、サブエージェントの応答を含めません。

## セッションの選択

### 選んだセッションだけ集計する

セッション一覧の左端の欄にチェックを付け(見出し行のチェックでそのページの 50 件をまとめて)、一覧の上の「選んだ N 件だけ集計」を押すと、その N 件だけで全体サマリ・要点・内訳・一覧が集計し直されます(他の条件とは AND。サイドバーの条件の数にも 1 つとして数えます)。一覧の上に「この選択で集計中」と出て、サイドバーの「解除」か一覧の上の「選択を解除」で外れます。チェックは画面の中だけのもので保存されません(選んだ id は URL の `#ids=…` に残るので、再読み込み・ブックマーク・共有では保てます)。「選択を解除」はチェックを全部外し、選択で集計中ならその条件も外します。

- CLI では `--session <id,...>` で特定のセッションだけを対象にできます(`build` / `export` / `metrics` / `bundle` に効きます)。
- 前の版のタスクタグ(`atlas-notes/groups.json` と、URL の `#group=…`)は読みません。ファイルは消さずに残します。

## セッションのメモ

セッションごとに、自分用のメモ(Markdown と画像)を残せます。数字だけでは残らない「なぜこのセッションが良かった / 悪かったか」を書くためのものです。

**書き方**: `atlas.bat`(または `atlas serve`)から開いた画面で、セッションの詳細ページの「メモを書く」を押します。

- 保存は「保存」か Ctrl+S。本文を空にして保存すると、確認のうえメモを削除します(画像は残ります)。
- 画像は貼り付け、ドロップ、または「画像を追加」で入れられます(png / jpeg / gif / webp、1 枚 10MB まで。svg は不可。手で置いた画像も 10MB を超えると表示しません)。
- 開いている間に Obsidian や `atlas memo` で同じメモが書き換えられていたら、上書きせずに知らせます。入力は残るので「上書きして保存」を選べます。

**見え方**: メモは詳細ページの先頭に出ます。一覧ではセッション名の下に先頭の 1 行が出て、「その他の条件」の「メモのあるセッションだけ」で絞り込めます。`atlas.html` に埋め込むのは先頭の 1 行だけで、全文は詳細ページにあります。

**置き場**: `atlas-notes/memos/<id>.md`(素の Markdown)と、画像の `atlas-notes/memos/<id>/`。`--notes-dir` で変えられます。本文からは `![説明](<id>/<ファイル名>)` で参照するので、Obsidian や VS Code でもそのまま読め、手で置いたファイルも同じように扱います。`atlas-notes/` は Git の対象外なので、消すと元に戻せません。バックアップが必要なら自分で管理してください。

**制限**:

- `file://` で開いた画面は閲覧だけで、メモは前回の build の時点の内容です。atlas.bat から開いた画面は常に最新です。
- 生の HTML は文字として表示します。リンクは http / https / mailto だけが有効で、外部の画像は読み込みません(リンクとして出します)。
- メモは評価バンドル(`bundle` / `judge`)、セッション記録、全文記録には入りません(自由記述を LLM に流さないためです)。レポートには入ります(`atlas.html` に先頭の 1 行、詳細ページに全文と画像)。レポートを人に渡すと、メモも一緒に渡ります。

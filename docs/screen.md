# 画面の見方と操作

[README](../README.md) に戻る。コマンドで使うときは [cli.md](cli.md) を見てください。

## サーバと黒い窓

`atlas.bat` は、依存が足りないときだけ `npm install` を実行したあと、`~/.copilot` を `out\snapshot` に複製して集計し、`out\atlas.html` と各セッションの記録(`out\sessions\<id>.md`。詳細ページからリンク)を作ります(実データ約 800 セッションで十数秒。うち記録の生成に 5 秒ほど)。そのあと`out/` をローカルサーバ(`127.0.0.1` だけに公開。ポートは空いているものを自動で取ります)で配信し、既定のブラウザで開きます。

- 黒い窓はブラウザを閉じるまで残り、atlas の画面(一覧・詳細・用語)をすべて閉じると約 15 秒後にサーバも止まります(ページを移るだけなら止まりません。窓を閉じても止まります)。別のタブで作業している間やスリープの後でも止まりません(閉じたことを知らせずに画面が消えたときは、合図が 30 分届かなければ止まります)。フォルダを選ぶ画面を出している間やアップロードの途中など、サーバが画面の求めに応えている最中は、終わるまで止まりません(終わってから約 15 秒後に止まります)。サーバが止まると、画面の上に「サーバが止まっています」と出ます。
- atlas を更新した(`git pull` など)後も、前から開いている黒い窓のサーバは更新前のまま動きます。画面を作ったときの atlas とサーバの版が違うと、画面の上に「画面とサーバの版が違います」と出ます(それまでは、新しく入った操作が使えないことがあります)。その黒い窓を閉じてから、もう一度 `atlas.bat` を実行し、新しく開いた画面を使ってください。サーバが新しく、ページのほうが前の版のまま(前の版で作って残っている指示文のページ、開いたままのタブ)のときも同じ帯が出ます。直し方は同じです(`atlas.bat` はページを作り直し、サーバも起動し直します)。版は、atlas のソースと、画面の作り方・依存を決めるファイル(各パッケージの設定と `package.json`、`package-lock.json`)の中身から作る目印で比べます(画面を作るときにページへ埋め込み、サーバは起動したときの目印を返します。エディタの作業ファイルや改行の違いでは変わりません)。`atlas serve` をコマンドで実行して前のサーバを使い回すときは、版が違えば、そのターミナルにも同じことを出します(`atlas.bat` をダブルクリックしたときは、すぐ窓が閉じるので画面の帯で知らせます)。
- もう一度 `atlas.bat` を実行すると集計し直し、サーバが動いていればブラウザを開くだけにします。
- 画面から「集計し直す」や判定を実行している最中は、同じ `out/` に並行して書かないよう `atlas.bat` の集計を止めて理由を出します(終わってから実行してください)。
- 逆に、`atlas` のコマンド(`all`・`build`・`judge` など out/ に書くもの)や `npm run atlas:judge` が動いている間は、画面からの処理も始めずに理由を出します。動いている印は `out\.job.json` で、処理が落ちて残っても、そのプロセスが無ければ次の実行が自動で無視します。
- サーバ無しで開いた画面(`out\atlas.html` を直接開いたもの)は閲覧だけで、タスクタグの編集・メモ・画面からの操作は出ません。

## 画面からの操作

`atlas.bat` から開いた画面(ローカルサーバ経由)では、次の操作ができます。`file://` で開いた画面と伏せ字版には出ません。画面から動かす処理は同時に 1 つだけで、動いている間は他の操作のボタンが押せません。処理の出力は `atlas.bat` の黒い窓にも流れます。

| 画面の操作 | 場所 | すること |
|---|---|---|
| 集計し直す | レポート(`atlas.html`)の右上 | `atlas.bat` と同じ集計(`all`: snapshot → extract → metrics → export)をやり直す。終わると本文の上の帯に「新しい集計ができました」と「再読み込み」が出る。自動では読み直さない(メモの入力中などを消さないため)。集計中は詳細ページと記録が作り直しの途中なので、開くと「集計し直している最中です」と出ることがある |
| 判定する… | レポートの右上 | ダイアログで「判定するもの」(工数 = セッションごとの推定人手工数 / 依頼ごとの採用)と「判定の方法」を選ぶ。選んだものはブラウザに覚える。工数で「このツールが判定する」を選んだとき: 確認を出してから、未判定のセッションを LLM で判定し(bundle → judge run → export)、レポートを作り直す。確認には件数(未判定のうち上限まで。上限の既定は 10)・判定に使うもの(GitHub Copilot CLI の `copilot -p`)・「AI クレジットを消費します」を出す。「やめる」・Esc では何も実行しない。従量課金の `anthropic` とモデルの指定は画面からはできない(Copilot の既定のモデルを使う) |
| 判定する… →「依頼ごとの採用」 | 同じダイアログで判定するものを切り替える | 依頼ごとに、AI の成果の扱い・合わなかった点・普段の工程を LLM に判定させる([judge.md の 3](judge.md#3-依頼ごとの採用段階-2))。「このツールが判定する」では GitHub Copilot CLI(`copilot -p`)を使い、件数(依頼の数。既定 60)を決めて実行すると、未判定の依頼を数件ずつ判定してレポートを作り直す(`turns bundle` → `turns run` → `export`)。「チャットに貼って判定する」は下の行と同じ 4 つの手順で、添付ファイルは `out/turn-bundle/parts/`(ダウンロードの名前は `turns-part-01.txt` など)、取り込み先は `out/turn-judgments.json` |
| 判定する… →「チャットに貼って判定する」 | 同じダイアログで方法を切り替える | M365 Copilot のように、ファイルの添付と貼り付けしかできないチャットで判定する流れ。添付ファイル(`out/bundle/parts/`)を未判定のセッションだけで作り、次のファイルのダウンロード(`.txt` で保存)・本文のコピー・依頼文のコピーを出す。チャットの返答を貼って「取り込む」と `judgments.json` に入れ、形が合わなければ何も取り込まずに、何件目のどのセッションのどの欄が違うかを出す(「直す点をコピー」でチャットに渡せる)。「レポートに反映する」でレポートを作り直す(`export`)。どの手順も AI クレジットを使わない。選んだ方法はブラウザに覚える([judge.md の 2a](judge.md#2a-外部の-llm-で判定するm365-copilot-など)) |
| 設定… | レポートの右上 | `setup.bat` と同じ設定を画面で決める(どれも押した時点で `atlas.config.json` に書く。設定ファイルを読めないときは理由を出して変えさせない)。**llm-wiki の vault**: 「エクスプローラーで選ぶ…」かフォルダ名・パスの入力で調べ、実在すればフォルダ名だけにして中の `index.md` と `wiki/` を見る。個別ページのフォルダ(既定は `wiki/` があればそれ)・索引のファイル名(`index.md` が無いとき)・wiki の skill として数えるもの(インストール済みの skill のうち名前に `wiki` を含むもの)を確かめてから足す。外すこともできる。変えたら「集計し直す」で反映される(ダイアログにも「集計し直す」が出る)。**普段の工程名**: `/` か `,` で区切って 2 つ以上。「既定に戻す」もある。**アップロード先**: タスクタグの見出しの「場所を決める…」と同じ。**まとめて送るプロジェクト**: 「プロジェクト別」の表の「まとめて送る」と同じ印を、名前で絞り込んで付け外しする(空のセッションだけのプロジェクトは出さない。送れるものが無いため) |
| 記録を読む ↗ | 詳細ページの表題の下 | そのセッションの記録(`out/sessions/<id>.md`)を別のウィンドウで読む。見出しの目次つき。詳細ページはそのまま残る |
| 全文を作って読む ↗ | 詳細ページの表題の下 | そのセッションの全文記録だけを作って(`out/full/<id>.md` と `out/full/assets/<id>/`。他のファイルは作り直さない)、別のウィンドウで読む(押すとすぐ空のウィンドウが開き、できたらそこに表示。もう一度開くときは状態の行の「全文記録を開く」) |

- **実行中**: 帯に経過時間と、出力の最後の 1 行が出ます。「止める」で止められます。判定は 1 件ずつ `judgments.json` に確定しているので、止めても判定済みの分は残り、次の「集計し直す」でレポートに出ます。集計を途中で止めたときは、レポートが作り直しの途中かもしれないので、もう一度「集計し直す」を押してください。
- **失敗したとき**: 帯に終了コードと、出力の末尾(200 行まで)を開けるログが出ます。判定で一部のセッションが失敗したときも、判定できた分はレポートに反映されるので「再読み込み」が出ます。
- **画面を閉じても処理は最後まで続きます**。サーバは処理が終わってから、画面が開いていなければ止まります。
- **記録の表示**は、メモと同じ規則で描きます。生の HTML は文字のまま(atlas 自身が書く `<small>` `<details>` `<summary>` の属性の無い形だけはタグとして描きます)、リンクは http / https / mailto だけ、外部の画像は読み込みません。全文記録だけは、そのセッションの `out/full/assets/<id>/` にある画像とファイルへのリンクを通します。20MB を超える `.md` は描かず、大きさと「.md を開く」を出します。
- 記録の本文はサーバに token を付けて取りに行くので、`atlas.bat` から開いた画面からしか読めません(表示のアドレス `/view/<id>` を他のページから開いても本文は出ません)。
- 画面から集計し直すときは `atlas.bat` に渡した引数(`--since` など)を引き継ぎません(既定の `all`)。絞り込んだ集計はコマンドで行ってください。

## 画面の見方

- **上部**: 生成日時、記録期間、「記録 N 件のうち M 件を集計対象にしています(空のセッション K 件を除外)」の 1 文、配色の切り替え(自動 / ライト / ダーク)。
- **目次と件数**: 幅 768px 以上では左にサイドバーが固定され、各欄へのリンクを 概況(全体・要点・改善点・工程と詰まり・集計明細)/ 内訳(利用ランキング・実行の性質・プロジェクト別・月別推移・モデル別)/ 一覧(セッション一覧)/ 付録(用語の説明、別ページ)の 4 群に分けて並べ、その下に「タスクタグ」の群(下記「[タスクタグとセッションの選択](#タスクタグとセッションの選択)」)が続きます。スクロールに合わせて読んでいる欄に印が付き、下に「表示中 N / 集計対象 M セッション」、絞り込みが効いているときは「K 条件で絞り込み中」の印と「解除」が出ます。768px 未満ではサイドバーの代わりに上部に細い目次の行が固定され(横に流れます。現在地に印)、右端に件数と「解除」が出ます。母数の M は上部の 1 文の M と揃えています。
- **絞り込み**: 1 行目に期間(開始日・終了日・直近 30 / 90 日)・プロジェクト・クライアント・モデル、「その他の条件」を開くとブランチ・入力トークン記録の有無・タスク分類・空のセッションの切り替えが出ます(どれかが効いている間は閉じられず、効いている数を印で出します)。絞ると下の欄がすべてその条件で集計し直され、サイドバー(狭い画面では上部の固定行)の「表示中 N / 集計対象 M セッション」が今の件数です。絞り込み行そのものは固定せず、スクロールすると流れます(条件を変えるときは上に戻ります)。キーボードでは Tab で順に移り、押した部品に緑の枠が出ます(日付入力は年・月・日の 3 区画で Tab を使うブラウザの仕様です)。**空のセッション**(依頼・ツール呼び出し・応答がどれも無い、開いただけのもの)は既定で集計・一覧・プロジェクト表・中央値のすべてから外しています。「その他の条件」の「空のセッションを含める」にチェックすると含めます(このときの「集計対象 M」は空を含めた件数)。条件は URL の `#` 以降に残るので、ブックマークすれば同じ絞り込みで開けます。タスク分類は LLM による判定(judgments.json)があるときだけ選べます(無いときは理由を欄の下に出します)。
- **要点**: 絞り込み後の集計から決まった規則で選んだ短い一覧です(LLM は使いません)。AI 使用量(AIU)の大きいセッション上位 3 件(AIU の記録が無い条件では出力トークンの多い順)、失敗率の高いツール(結果の記録が 5 回以上で失敗・拒否のあったもの)、compaction の多いセッション、インストール済みで未使用の skill。各項目にはリンクがあり、セッションならその詳細ページ、ツールなら今の絞り込みに「そのツールを使ったセッション」を足した状態(URL の `#…&tool=<ツール名>`)、未使用の skill なら利用ランキングの未使用一覧に移ります。ツールで絞っているときは絞り込み行に「<ツール名> を使った ×」が出て、押すと外れます。
- **全体サマリ(表紙)**: 規模の 4 欄(セッション数、期間、実働時間、推定人手工数)。帳票の「表紙 → 摘要(要点)→ 明細」の順に並べているので、この下に要点、その下に集計明細が来ます。空のセッションを外しているときは、その件数を「空のセッション N 件を除外」と出します。
- **集計明細**(要点の下): 4 列 × 3 行の 12 欄。トークン(入力・出力・うち推論・キャッシュ読取)、AI 使用量(AIU)、premium request、API リクエスト、ツール呼び出し(失敗率つき)、変更行数、skill・agent・hook の件数、指示ファイルと llm-wiki の利用(対象の vault は「[wiki の指定](cli.md#wiki-の指定)」)、摩擦の合計。各欄の下の注記は 1 行程度に抑え、摩擦の内訳の続きは「実行の性質」へのリンクにしています。**入力トークン・AI 使用量・premium request・変更行数は記録が残っているセッションだけの合計**で、欄の下に「記録あり N / M セッション」を出します。
  - AI 使用量は nano AIU を 10 億で割った AIU で、桁区切りで表示します。金額には換算しません。premium request は旧来の課金単位で、記録のある(主に 2026 年 7 月以前の)セッションだけの合計です。
  - 変更行数(追加 / 削除)は、セッション終了時の累計(`session.shutdown` の `codeChanges`)を優先し、無ければツールごとの行数(`toolTelemetry`)を合計したものです。
  - 依頼の回数には、autopilot が自分で作業を続けるときの自動継続(ログ上はユーザーのメッセージとして残る)を含めず、別に「自動継続 N 回」と出します。
  - ツール呼び出しの回数には、作業の途中経過を画面に出すための内部ツール(`report_intent`)を含めず、件数だけ別に出します。
  - 摩擦の内訳では「ツール失敗」(個々のツール呼び出しの失敗)と「エラー」(`session.error`。利用上限・通信エラーなどセッション全体のエラー)を分けています。
  - その下の「入力トークン記録の内訳」で、明細あり / 終了時の累計のみ / 出力のみ / **記録なし(欠測)** の件数を確認できます。記録なし(欠測)は、依頼や応答があるのにトークン量の記録がどこにも無いセッションです(2026 年 9 月以降のログは `assistant.message` に出力トークン数を書かなくなったため、session-store.db・usage_record・終了時の累計のどれも無いと出力トークンも分かりません)。0 として足さず、件数で示します。帯の欠測の区画は色に加えて斜線で区別しています。
  - 帯の下に、画面で使う欠測の語の凡例を置いています: **記録なし**(ログにその項目の記録が無い)/ **推計不可**(出力トークンだけ記録があり入力は求められない)/ **未判定**(LLM の工数判定をまだ実行していない)/ **不明**(記録はあるが分類できない。クライアント・モデルなど)/ **—**(該当なし)。用語の説明ページの先頭にも同じ凡例があります。
- **工程と詰まり**(改善点の下): 依頼(ターン。利用者の 1 回の依頼から次の依頼の直前まで)ごとに、AI が主にしたこと(工程)とその間のつまずきを数えた表です。工程はその依頼で使ったツール(サブエージェントの分を含む)から決めます: 編集があれば実装、無くてテスト・ビルドを実行していれば検証、git のコミット・push などがあれば運用、計画・確認だけなら計画、ツールを使わなければ回答のみ、それ以外は調査。LLM は使いません。
    - **工程別**: 依頼の数と割合、実働時間、AI 使用量、詰まりのあった依頼(ツールの失敗・拒否・中断・エラー・前の依頼で編集したファイルの再編集・文脈圧縮のどれかがあったもの)の数と割合、それぞれの回数(エラーの括弧内は利用上限・速度制限によるもの)、「次の依頼で直し・差し戻し」(次の依頼が「直して」「戻して」などだった依頼 / 次の依頼があった依頼)。最後の行が合計です。
    - **依頼の種類 × 工程**: 依頼文の語で粗く分けた種類(作業 / 質問 / 修正 / 差し戻し / 続行)が、どの工程で起きたかの件数。「どこで聞いているか」を見る表です。言い回しの違う修正は「作業」に入ることがあります。
    - **採用(LLM の判定)**(依頼ごとの判定があるときだけ。無いときは判定のしかたの案内): 普段の工程別に、判定した依頼の数、作業の依頼の扱い(そのまま / 中身を修正 / 体裁を修正 / 不採用)と採用率(判定できた作業の依頼のうち「そのまま」の割合)、質問の依頼の扱い(役に立った / 追加で聞いた / 的外れ)と役に立った率、判定不能。その下に、合わなかった点(意図・要件の取り違え / 誤り・不具合 / 品質・体裁・決まりごと / やり過ぎ・足りない / 環境・ツール・権限 / その他)× 普段の工程の件数。どれも次の依頼の文から LLM が決めた推定です。
    - 絞り込みに合わせて集計し直します。1 セッションの先頭 200 依頼までを数えます。依頼があるのに依頼ごとの記録が無いセッション(古い集計など)は件数を断ります(「集計し直す」で入ります)。
- **AI 投入量 vs 推定人手工数**(判定結果があるときだけ): 判定済みのセッションについて、LLM が推定した人手工数(幅と平均確信度つき)と、同じセッションで AI が使った実働時間・トークンを全体とプロジェクト別に並べます。「推定人手工数 ÷ AI の実働」は目安で、削減量の実測ではありません。
- **利用ランキング**: 絞り込んだセッションで「何を使ったか」を、ツール / MCP サーバー / skill / agent / hook / 指示ファイルの切り替えで上位 10 件の棒グラフにし、「全件を表で見る」で全件を表にします。絞り込みを変えると集計し直されます。
  - ツール: 呼び出し回数と失敗率(失敗 + 拒否 ÷ 結果の記録がある回数)。MCP のツールは「MCP」の印を付けてサーバーごとに 1 行にまとめます。「並べ方」で失敗率の高い順(結果 5 回以上のツールだけ)にもできます。表では成功・失敗・拒否・結果なしの内訳が見られます。
  - MCP サーバー: サーバーごとの呼び出し回数と、よく使ったツール。
  - skill: 回数と、利用者が呼んだ(`trigger: user-invoked`)/ エージェントが呼んだ(`agent-invoked` と skill ツールの呼び出し)/ 不明(trigger を記録しない古いログ)の内訳。その下に「**インストール済みで未使用の skill**」(`~/.copilot/skills/` とプラグインの skill のうち、絞り込んだ期間に一度も呼ばれなかったもの。`settings.json` で無効にしたものには「無効」)を出します。
  - agent: 起動回数・失敗・使ったトークン。hook: 種類ごとの実行回数。指示ファイル: 注入されたセッション数(「(user)」はユーザー単位の指示ファイル)。
- **実行の性質**: 絞り込んだセッションを「どう動かしたか」「どこで時間と文脈を使ったか」で見る欄です。値は記録のあるものだけの集計です。
  - モード別の依頼: 依頼(ユーザーのターン)ごとのモード(対話 interactive / 計画 plan / autopilot)。`user.message` の `agentMode`、無ければ直前の `session.mode_changed` で決めます。どちらも無い依頼は既定の interactive とみなし、その回数を欄の下に出します(実データでは最初のモード変更の変更前は全件 interactive でした)。
  - 推論強度別: リクエストの `reasoningEffort`(session-store.db / usage_record)、無ければその時点のセッションの設定(`session.start` / `session.model_change`)ごとのリクエスト数・入力・出力・AIU。終了時の累計しか無いセッションは、設定が 1 種類ならその強度に、それ以外は「不明」に入れます。
  - リクエストの起点: API リクエストを誰が起こしたか(`initiator`: 利用者の依頼 / エージェント / サブエージェント / compaction / 記録なし)。リクエスト単位の明細があるセッションだけです。
  - 文脈の内訳(ツール定義): 毎リクエストの文脈に入るツール定義のトークン(セッションの最後の値。`session.shutdown` か `session.compaction_complete` の `toolDefinitionsTokens`、無ければ usage_record の `toolTokenCount`)の平均・中央値と、文脈(system・会話・ツール定義)に占める割合、使えるツールの数、プロジェクト別の平均。
  - モデル別の待ち時間: 最初のトークンまで(`time_to_first_token_ms` / `timeToFirstTokenMs`)とリクエスト全体(`duration_ms` / `duration`)の中央値と p90(遅い方から 1 割の境目)。
  - ツールの所要時間: 開始から完了まで(`toolCallId` で対応)。5 回以上記録のあるツールを p90 の長い順に出し、「全件を表で見る」で全ツールを見られます。**1 時間を超えたもの(放置や利用者の返答待ち。1 日近いものもある)は外れ値として中央値・p90 から除き、件数だけ出します。**
  - 摩擦の詳細: 権限の確認の結果(承認 = `approved` / `approved-for-location`、拒否 = `denied…`)、エラーの種別(`session.error` の `errorType`: quota / rate_limit など)、サブエージェント失敗の理由(`subagent.failed` の `error` を 利用上限(402)/ 回数制限(429)/ 中断 / 応答なし / その他 に分類。詳細ページには本文を短く出します)、compaction 自体が使ったトークンと compaction で減ったトークン。
  - todo: `session.db` の todo の状態別件数(完了 / 進行中 / 未着手 / 保留)、完了率(完了 ÷ 全件。セッション終了時点)、依存関係の数。
- **プロジェクト別**: プロジェクトごとの集計表。列見出しで並べ替え、プロジェクト名を押すとそのプロジェクトに絞り込みます(行に「絞り込み中」の印が付き、もう一度押すと解除。名前はリンクなので Ctrl+クリックで別タブにも開けます)。入力トークンの下の小さな「5/30」は、記録のあるセッション数 / 全セッション数です。「変更行」は追加行数(下に削除行数)、「指示」「wiki」は該当セッション数 / セッション数、「摩擦」の下には内訳の多い順 3 つを小さく出します。表が幅に収まらないときは横にスクロールでき、続きがある側の端に影が出ます(他の表も同じ)。
  - **まとめて送る**(`atlas.bat` から開いたときだけ): プロジェクト名の隣の列の印です。印を付けたプロジェクトは、`upload-project.bat` が番号を聞かずにまとめて送ります(送る前の確認はあります。README の「[プロジェクトのセッションをまとめて送る](../README.md#プロジェクトのセッションをまとめて送るupload-projectbat)」)。印は押した時点で `atlas.config.json` の `uploadProjects` に書かれ、外すと消えます(全部外すと項目ごと消え、bat は番号で選ぶ形に戻ります)。表の上に今の件数を出し、絞り込みの外のもの・今の集計に無いものがあればその件数も出します。設定ファイルを読めないなどで書けなければ、理由を出して印を元に戻します。開いたときに設定ファイルを読めなければ、印を 0 件と見せずに理由を出し、印を押せないようにします(直してから開き直します)。
  - プロジェクトは、ログの repository、無ければ git の origin(「所有者/リポジトリ」)で束ねます。同じリポジトリの別フォルダや worktree で開いたセッションも 1 つになります。ホームディレクトリそのもので開いたものは「(ホーム)」、一時フォルダ(`%TEMP%` 配下。scratchpad での試行など)は「(一時フォルダ)」、このツール自身の工数判定(`judge run` が作る `%TEMP%\atlas-judge-cwd-*`)は「(atlas の判定)」にまとめます。どれにも当たらないものは作業フォルダのパスのままです。
- **月別推移**: セッション数・出力トークン・入力トークン・AI 使用量(AIU)・premium request の月別の棒グラフ(月は UTC)。棒にマウスを乗せるかキーボードで選ぶと値が出ます。棒を押す(Enter / Space)と値の表示を固定でき、もう一度押すと外れます。「表で見る」で同じ値と変更行数を表で確認できます。AIU と premium request は記録のあるセッションだけの合計です。
- **モデル別**: モデルごとのトークンとリクエスト数。1 セッションで複数のモデルを使うことがあるため、セッション数の合計は全体と一致しません。同じモデルがログの出所によって `claude-haiku-5-5` / `claude-haiku-5.5` / `<ID>/claude-haiku-5-5` のように書き分けられているため、`claude-haiku-5.5` の形にそろえています(`claude-<種類>-<数字>-<1 桁の数字>` で後ろに日付などが続かないものだけ。先頭の `<UUID>/` はプロバイダ設定の ID で、同じリクエストの記録にどちらの名前も残っていることを実データで確認しています)。
- **セッション一覧**: 1 ページ 50 件。左端はチェック欄で、チェックした行は薄い緑になり、一覧の上の「N 件を選択中」と「選んだ N 件だけ集計」「選択を解除」「タスクタグを付ける ▾」「このタスクタグを外す」(後の 2 つは `atlas.bat` から開いたときだけ)が使えます(下記「[タスクタグとセッションの選択](#タスクタグとセッションの選択)」)。「変更行」列は追加行数(下に削除行数)。推定人手工数は LLM による判定を実行するまで「未判定」です。空のセッションを含めているときは、空のものに「空」の印が付きます。名前を押すと[セッション詳細](#セッション詳細ページ)を開きます。一覧の中に書き出しが 20 字以上同じ題名が他にあるときは、共通の書き出しを先頭の数文字だけ残して「…」に縮め(薄い色)、違いが始まるところから見せます。題名がまったく同じ行には「同じ題名 ×N」の印が付きます(開始時刻やプロジェクトで見分けてください)。全文は名前に重ねると出ます。
- **クライアントが「不明」のセッション**: 次のどちらかで、記録からはクライアントを決められません(推測では埋めていません)。
  - Copilot 1.0.54 以前(2026 年 5 月以前)のセッション。`workspace.yaml` に `client_name` がまだ記録されていませんでした(実データで `client_name` が初めて現れるのは 1.0.56)。
  - `session-store.db` にだけあるセッション。DB の `sessions` 表にはクライアントの列が無く、`host_type` は CLI と autopilot のどちらでも `github` か空なので区別できません。実データではこの種類はすべて空のセッションでした。
- **用語の説明**(別ページ `out/glossary.html`。上部のリンクと各詳細ページの上部から開く): 53 語を 6 つの分類に分けて載せています。**消費の単位**(nano AIU / AIU、premium request、入力 / 出力 / キャッシュ読取トークン、リクエストの起点、文脈の内訳)/ **時間と待ち**(所要時間 / 実働時間、ツールの所要時間、待ち時間)/ **記録の由来と欠測**(トークン記録なし、空のセッション、内部ツール、モデル名の表記、変更行数、プロジェクトのまとめ方。欠測の語の凡例もここ)/ **動かし方と拡張の仕組み**(モード、推論強度、compaction、skill とその呼んだ側、未使用の skill、MCP サーバー、agent、hook、指示ファイル、llm-wiki)/ **工数と判定**(推定人手工数とその ÷ AI の実働、依頼(ターン)と工程、依頼の種類、詰まりと次の依頼で直し・差し戻し、摩擦、ツールの失敗率、権限の確認の結果、todo、要点)/ **改善点の指標**(手戻り率、余分な編集、失敗の連続、スキル化の候補など)。目次は分類だけで、レポート・詳細ページと同じく 768px 以上では左のサイドバー(分類の 1 行の説明つき。読んでいる分類に印)、未満では上部に固定した分類の行です。「レポートに戻る」と配色の切り替えも同じ場所にあります。各用語への直接リンク `glossary.html#<id>` は従来のままです。レポートを初めて読む人向けです。

## セッション詳細ページ

- **中身**: 時系列、依頼ごとの経過(下記)、ツール内訳と成功・失敗・拒否、実行の性質(モード・推論強度・起点・ツール定義・モデル別の待ち時間・ツールの所要時間・摩擦の詳細・失敗したサブエージェントの理由・todo)、skills(呼んだ側)/ agents / hooks、指示文と skill(下記)、llm-wiki の参照、摩擦、変更行数、変更したファイル。セッション ID は表題の下の印の列の末尾にあります。
- **依頼ごとの経過**: 依頼 1 件 1 行の表。開始時刻、依頼文の先頭(伏せ字版では出しません)、依頼の種類、工程、実働、ツール・失敗・拒否・中断・エラー・再編集・文脈圧縮の回数、AI 使用量。詰まりのあった依頼には左端の印と「詰まり」、次の依頼が修正・差し戻しだったものには「次で修正」などの印を付けます。規則はレポートの「工程と詰まり」と同じです。依頼ごとの判定があれば、右端に「採用(LLM)」(判定の理由の要約つき。伏せ字版では理由を出しません)、「合わなかった点」、「工程(普段)」の列が付きます。
- **指示文と skill の表**: 注入された指示ファイルと、そのセッションで使えた skill の一覧に呼んだ回数を添えた表。呼んだものが先、一覧に無い skill を呼んだときは「一覧に無し」。使えた skill の一覧はシステムメッセージの `<available_skills>` から読むので、Copilot CLI 1.0.77 より前の版や `copilot -p` のセッションでは「一覧はこのセッションの記録にありません」と出て、呼んだものだけになります。置き場所はログの値で、user / project / builtin は「ユーザー / プロジェクト / 組み込み」、それ以外(`custom` など)はそのまま。伏せ字版では使えた skill の名前を出さず件数だけ。
- **目次**: 幅 768px 以上では左のサイドバーに「レポート(セッション一覧)に戻る」(レポートから開いたときはブラウザの「戻る」と同じ動きで、絞り込みを保ったまま戻ります。詳細ページを直接開いたときや新しいタブではレポートの先頭を開きます)、節の目次(概要・トークン内訳・…・ログの状態。読んでいる節に印)、「用語の説明」、配色の切り替えが上から並びます。記録を作ってあれば(`atlas.bat`・`all`・`export`)「記録の .md をそのまま開く ↗」(別のウィンドウで開きます。整形して読むなら表題の下の「記録を読む」)「記録を .md で保存」も入ります(素の `build` と伏せ字版の `all` では出ません)。「このセッションの指示文と skill」は、指示文と skill のページをそのセッションで使われた版だけに絞って開きます(伏せ字版では出ません)。768px 未満では上部の帯に戻る・リンク・配色、その下に固定した目次の行(横に流れ、現在地に印)が出ます。
- 詳細の「変更したファイル」は、変更・作成・削除に分けて載せます。相対パスは作業フォルダ基準の絶対パスにそろえ、同じファイルは 1 回だけ載せます(Windows では大文字小文字を区別しない)。途中で削除したファイルは、終了時の記録(`codeChanges.filesModified`)に残っていても「削除」のままにします。Copilot 自身のセッション用ファイル(`~/.copilot/session-state/` 配下の plan.md など)は一覧から外し、件数だけ書きます。
- 応答の件数には、サブエージェントの応答を含めません。

## タスクタグとセッションの選択

タスクタグは、セッションに付ける名前です(例: `Player-Weapon`)。1 つのセッションに複数付けられます。保存先とコマンドでは「グループ」と呼びます(`atlas-notes/groups.json`、`atlas group …`)。

一覧で選んだセッションだけを集計したり、タスクタグを付けて残したりできます。

### 選んだセッションだけ集計する

セッション一覧の左端の欄にチェックを付け(見出し行のチェックでそのページの 50 件をまとめて)、一覧の上の「選んだ N 件だけ集計」を押すと、その N 件だけで全体サマリ・要点・内訳・一覧が集計し直されます(他の条件とは AND。サイドバーの条件の数にも 1 つとして数えます)。サイドバー(狭い幅では目次行の「タスクタグ」)には「選んだ N 件」の印が出て、「すべて」に戻すか「解除」で外れます。チェックは画面の中だけのもので保存されません(選んだ id は URL の `#ids=…` に残るので、再読み込み・ブックマーク・共有では保てます)。「選択を解除」はチェックを全部外し、選択で集計中ならその条件も外します。

### タスクタグで絞り込む

- タスクタグの居場所はサイドバーの「タスクタグ」の群です(幅 768px 未満では上部の固定した目次行の「タスクタグ N」を押して開く一覧。外を押すか Esc で閉じます)。「すべて」と各タスクタグ(名前・件数・説明)が並び、押すとそのタスクタグで絞り込まれ、現在のタスクタグに印が付きます。外すのは「すべて」か、本文の見出しの「絞り込みを外す」です。ここは切り替えだけで、編集の操作は置いていません。
- タスクタグが無いときは「タスクタグはまだありません。一覧でセッションを選ぶと作れます」と出ます。
- タスクタグで絞り込んでいる間は、本文の先頭(絞り込みの行の下)にタスクタグの見出し(名前・件数・説明)と「絞り込みを外す」が出ます。記録に無い id が混じっていれば件数は「m / n」です。
- セッションに付いているタスクタグは、一覧の行の題名の下(「タスクタグ: 名前、名前」)と、`atlas.bat` から開いた詳細ページの表題の下(名前を押すとそのタスクタグで絞り込んだレポートに移ります)に出ます。
- 詳細ページでは、そのセッションのタスクタグを付け外しできます(`atlas.bat` から開いたときだけ)。「×」で外し(タグは 0 件でも残ります)、入力欄にタグの名前を入れて「付ける」で付けます(今あるタグは候補に出ます。無い名前なら新しく作ります)。

### タスクタグを作る・直す(`atlas.bat` から開いたときだけ)

- **作る・足す**: セッション一覧でチェックして、一覧の上の「タスクタグを付ける ▾」を開きます。既存のタスクタグを選べばその場で追加します(重複は足さず「N 件を「名前」に追加しました。チェックは外しました」と出ます。絞り込みは変わりません)。末尾の「新しいタスクタグ…」で名前と説明を入れて作成すると、そのタスクタグで絞り込んだ状態になります。
- タスクタグや「選んだ N 件」の絞り込みを外す(「すべて」「解除」)とチェックも外れるので、続けて別のタスクタグを作っても前のセッションは混ざりません。
- **外す**: タスクタグで絞り込み中は「このタスクタグを外す」でチェックした分を外せます(0 件になってもタスクタグは残ります)。
- **表と記録を書き出す**: 見出しの「表と記録を書き出す」で、そのタスクタグのセッションだけの表(依頼ごとの `turns.csv`・セッションごとの `sessions.csv`)・集計(`metrics.json`)・セッション記録(`records/`)を `out\groups\<タスクタグ名>\` に書き出します(いつものレポートは変わりません。前回の書き出しは消してから書きます)。書き出した場所が見出しの下に出て、「場所をコピー」で写せます。CSV は Excel でそのまま開けます(UTF-8、BOM 付き)。依頼文や記録にはパスや本文がそのまま入るので、共有する前に中身を確かめてください。CLI では `atlas group export <名前>` です。
- **アップロード**: タスク(タスクタグ)ごとのセッションの生ログを、決めておいた場所へ写します。見出しの下に「アップロード先 `E:\dev\atlas-logs\Player-Weapon\`」のように写す先が出ていて、見出しの「アップロード」を押すと、タスクタグのセッションごとに `<アップロード先>\<タスクタグ名>\<セッション ID>\` のフォルダを作って写します。
  - 写すもの: Copilot のセッションのフォルダ(`events.jsonl`・`workspace.yaml`・`session.db`・`plan.md`・`checkpoints\`・`files\` など)と、`session-store.db` と `data.db`(デスクトップアプリ。資格情報を含まない許可リストの列だけ)のそのセッションの行(`atlas-session-store.json`。トークン数・題名・モデルなどは DB にしか無いことがあるため)。元の `~\.copilot` ではなく、前回の集計(`atlas.bat` の起動時か「集計し直す」)で複製したものを写します。結果の文に、いつの集計の時点のログかが出ます。新しい作業を含めたいときは、先に「集計し直す」を押してください。
  - タスクタグの説明とメモも残します。タスクタグのフォルダの `README.md` に、タスクタグ名・タスクタグの説明・写した日時・何時点の集計か・今回写したセッションの一覧(題名・タスクタグ・最終更新・メモの有無)・タスクタグごとの一覧・集計し直すコマンドを書きます(写すたびに書き直します)。プログラムや AI が読むための索引 `atlas-index.json`(セッションごとのタスクタグ・題名・作成と最終更新の日時・プロジェクト)も同じフォルダに書き、各セッションのフォルダにはそのセッションの分を `atlas-session.json` で添えます(タグの無いセッションは空の一覧。プロジェクト名とその決め方 `projectSource` も入れ、集計し直すときはここからプロジェクト名を取ります)。セッションのメモは、そのセッションのフォルダに `atlas-memo.md`、画像は `atlas-memo\` に入れます(本文の画像の参照も `atlas-memo/…` に直すので、Markdown のビューアでそのまま読めます)。集計し直した画面にはメモは出ないので、ファイルを開いて読みます。
  - 同じセッションのフォルダは丸ごと置き換えます(メモを消してから写し直すと、前に添えたメモも消えます)。前のフォルダの中のファイルが開かれていて置き換えられないときは、前のフォルダをそのまま残して止まります(開いている画面を閉じてからもう一度押してください)。
  - 写さずに止まるとき: タスクタグのセッションが前回の集計に 1 件も無いとき(フォルダも README も作りません)、フォルダ名に直すと同じになる別のタスクタグがあるとき(`Player/Weapon` と `player_weapon` など。どちらかの名前を変えてください)。タスクタグから外したセッションや、ほかの回・ほかの PC から写したセッションのフォルダには触れません(消しません)。前回の集計に無いセッションは写さず、件数を結果の文に出します。
  - 写し終えると、写した先と「エクスプローラーで開く」が出ます。
  - **アップロード先を決める・変える**: 見出しの下の「場所を決める…」/「場所を変える…」で記入欄が開きます。「エクスプローラーで選ぶ…」でフォルダを選ぶ画面が出るので、基底のフォルダ(例: `E:\dev\atlas-logs`)を選びます(画面がブラウザの後ろに隠れたときはタスクバーを見てください)。パスを入力して「入力したパスにする」でも決められます。決めた場所は `atlas.config.json` の `uploadRoot` に書かれ、すべてのタスクタグで共通です(`setup.bat` でも決められます)。基底のフォルダが無いときは写さずに止まります(ネットワークドライブの切断などで、思わぬ場所に作らないため)。先が決まっていないまま「アップロード」を押すと記入欄が開き、決めるとそのまま写します。
  - タスクタグ名にフォルダ名に使えない文字(`/ \ : * ? " < > |`)があれば `_` にします(`Player/Weapon` → `Player_Weapon`)。見出しの下の表示がそのまま写す先です。
  - 写したタスクタグのフォルダは、そのまま集計できます: `npm run atlas -- all --home "E:\dev\atlas-logs\Player-Weapon" --out out-player-weapon`([cli.md の「snapshot と extract が読むもの」](cli.md#snapshot-と-extract-が読むもの))。出力先の `sessions\<セッション ID>.md` に、セッションごとの読みやすい記録もできます(記録は生ログから作れるので、送るものには含めません。送り先の容量を使わないため)。
    - 出力先(`--out`)は、集計するフォルダごとに分けてください。いつもの `out` や、別のタスクタグのフォルダを集計した出力先を指定すると、セッションが混ざるので書かずに止まります。
    - `--home` に指定するのはタスクタグのフォルダです。基底のフォルダ(`E:\dev\atlas-logs`)を指定すると、その下のフォルダの名前を挙げて止まります。
    - プロジェクト名は、送った PC で決めた名前のままです(読む PC に同じ作業フォルダが無くても変わりません)。
  - 生ログには依頼文・応答・ツールの結果・ファイルのパスがそのまま入ります。写す先を見られる人を確かめてから写してください。
  - 写す前に、合計の大きさと秘密らしい文字列(GitHub・OpenAI / Anthropic・AWS・Slack・Google のキーやトークン、秘密鍵、JWT、Bearer トークンの形)を調べます。写す前に毎回、見出しの中に確認が出ます(送り先・セッション数・大きさ・置き換える件数。100 MB を超えるときは大きいフォルダも)。「写す」で写し、「やめる」か Esc でやめます。「送り先を変える…」でエクスプローラーから選び直せます。秘密らしい文字列が見つかったときは、件数・種類・見つかったファイルも出し、焦点は「やめる」に置きます(ボタンは「それでも写す」)。偽陽性もありえます。本物の鍵なら、写すかどうかに関わらず作り直してください。バイナリのファイル(session.db・画像など)は中身を調べません。
  - 写している間は、見出しの下に写した量(セッション数とバイト数)が出ます。
  - 写している途中に別のタスクタグへ切り替えても、進み具合と結果は写しているタグの見出しにだけ出ます(ほかのタグの見出しには「「A」をアップロードしています」と出て、終わるまでほかのタグは写せません)。ほかのタグを見ている間に終わったときは、その見出しに「「A」のアップロードが終わりました」(失敗なら「アップロードできませんでした」と理由)とだけ出し(画面の読み上げでも読みます)、写したタグへ戻ると結果を出します。「すべて」へ外して戻ったときも同じです。そのとき見ているタグ自身の直近の結果(ほかのページで写したもの)も、写し終えた時点で出します(編集などの欄を開いているときは出さず、次に開いたときに出します)。知らせは、そのタグで写し始めると消えます。確かめている間・書き出している間に別のタグへ切り替えたときは、前のタグの確認や書き出しの結果を出しません。写している途中に別のページへ移って戻ったときは、続いていれば進み具合を、終わっていれば直近の結果(成功なら写した件数、失敗なら理由。10 分以内のもの)を一度だけ出します。
  - 確かめてから「写す」を押すまでの間に、集計し直してログが変わったときは、写さずに理由を出します。もう一度「アップロード」を押して確かめてください(確かめていない中身を写さないため)。
  - 送り先のフォルダに、フォルダ名が同じになる別のタスクタグやプロジェクトがすでに送られているときは、混ざるので写しません(タグの名前か送り先を変えてください)。
  - CLI では `atlas group upload <名前> [--to <基底フォルダ>] [--force]` です。写す前に大きさを出し、秘密らしい文字列が見つかったら写さずに止まります(`--force` で写します)。
- **名前・説明の変更と削除**: 見出しの「編集」で名前と説明を 1 つの欄で直せます。削除は編集欄の右端の「このタスクタグを削除…」から確認を 1 回挟んで行います(タスクタグだけが消え、セッションと記録は残ります)。Esc で 1 段ずつ戻ります(確認 → 編集 → 見出し)。
- これらの操作は `atlas.bat`(= `atlas serve`)で開いたときだけ使えます。`out\atlas.html` を直接開いたときはタスクタグを選んで絞り込むことだけができ、「このファイルは閲覧用です」と出ます。サーバが止まると画面の上に「サーバが止まっています」の帯が出て、編集の操作だけが消えます(閲覧はそのまま)。
- コマンドでは `npm run atlas -- group add <名前> <id...>` でも追記できます([cli.md](cli.md#コマンド))。

### ファイルと共有

- ファイルは `atlas-notes/groups.json`(リポジトリ直下。`--notes-dir` で変更可)で、形式は `{ "version": 1, "groups": [ { "name": "<名前>", "note": "<任意の説明>", "ids": ["<session id>", …] } ] }`、名前は一意です。手で書いてもよく、壊れていても `build` / `export` / `judge` は止まらず、無視した箇所を全体サマリの集計明細と脚注に出します(壊れている間は画面からも書き換えません)。
- `atlas-notes/` は `.gitignore` に入っているので Git では管理されません。消すと元に戻せないので、残したいときは自分でバックアップしてください。
- タスクタグの条件は URL の `#` に名前と id の両方で残るので、ブックマークや共有で保てます(相手にその名前のタスクタグが無ければ id だけで「選んだ N 件」として絞り込まれます)。
- CLI では `--group <名前>` で同じ絞り込みができ、`--session <id,...>` で特定のセッションだけを対象にできます(`build` / `export` / `metrics` / `bundle` に効きます)。
- 伏せ字版ではタスクタグ名と説明は出さず「タスクタグ 1, 2, …」になり、画面からの編集もできず、URL にも名前は出ません。

## セッションのメモ

セッションごとに、自分用のメモ(Markdown と画像)を残せます。数字だけでは残らない「なぜこのセッションが良かった / 悪かったか」を書くためのものです。

**書き方**: `atlas.bat`(または `atlas serve`)から開いた画面で、セッションの詳細ページの「メモを書く」を押します。

- 保存は「保存」か Ctrl+S。本文を空にして保存すると、確認のうえメモを削除します(画像は残ります)。
- 画像は貼り付け、ドロップ、または「画像を追加」で入れられます(png / jpeg / gif / webp、1 枚 10MB まで。svg は不可。手で置いた画像も 10MB を超えると表示しません)。
- 開いている間に Obsidian や `atlas memo` で同じメモが書き換えられていたら、上書きせずに知らせます。入力は残るので「上書きして保存」を選べます。

**見え方**: メモは詳細ページの先頭に出ます。一覧ではセッション名の下に先頭の 1 行が出て、「その他の条件」の「メモのあるセッションだけ」で絞り込めます。`atlas.html` に埋め込むのは先頭の 1 行だけで、全文は詳細ページにあります。

**置き場**: `atlas-notes/memos/<id>.md`(素の Markdown)と、画像の `atlas-notes/memos/<id>/`。`--notes-dir` で変えられます。本文からは `![説明](<id>/<ファイル名>)` で参照するので、Obsidian や VS Code でもそのまま読め、手で置いたファイルも同じように扱います。`atlas-notes/` は Git の対象外なので、消すと元に戻せません。バックアップが必要なら自分で管理してください。

**制限**:

- `file://` で開いた画面は閲覧だけで、メモは前回の build の時点の内容です。atlas.bat から開いた画面は常に最新です。
- 生の HTML は文字として表示します。リンクは http / https / mailto だけが有効で、外部の画像は読み込みません(リンクとして出します)。
- `--anonymize` の伏せ字版にはメモを一切出しません(本文・先頭の 1 行・件数のどれも)。
- メモは評価バンドル(`bundle` / `judge`)、セッション記録、全文記録には入りません。自由記述を LLM や共有用の出力に流さないためです。

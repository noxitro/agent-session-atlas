# 画面の見方と操作

[README](../README.md) に戻る。コマンドで使うときは [cli.md](cli.md) を見てください。

## サーバと黒い窓

`atlas.bat` は、`bin\atlas.exe` が無いか版が違うときだけ用意し直したあと(README の「atlas.exe の用意と更新」)、`~/.copilot` を `out\snapshot` に複製して集計し、`out\atlas.html` と各セッションの記録(`out\sessions\<id>.md`。詳細ページからリンク)を作ります(実データ約 800 セッションで十数秒。うち記録の生成に 5 秒ほど)。そのあと`out/` をローカルサーバ(`127.0.0.1` だけに公開。ポートは空いているものを自動で取ります)で配信し、既定のブラウザで開きます。

- 黒い窓はブラウザを閉じるまで残り、atlas の画面(一覧・詳細・用語)をすべて閉じると約 15 秒後にサーバも止まります(ページを移るだけなら止まりません。窓を閉じても止まります)。別のタブで作業している間やスリープの後でも止まりません(閉じたことを知らせずに画面が消えたときは、合図が 30 分届かなければ止まります)。フォルダを選ぶ画面を出している間やアップロードの途中など、サーバが画面の求めに応えている最中は、終わるまで止まりません(終わってから約 15 秒後に止まります)。サーバが止まると、画面の上に「サーバが止まっています」と出ます。
- atlas を更新した(`git pull` など)後も、前から開いている黒い窓のサーバは更新前のまま動きます。画面を作ったときの atlas とサーバの版が違うと、画面の上に「画面とサーバの版が違います」と出ます(それまでは、新しく入った操作が使えないことがあります)。その黒い窓を閉じてから、もう一度 `atlas.bat` を実行し、新しく開いた画面を使ってください。サーバが新しく、ページのほうが前の版のまま(前の版で作って残っている指示文のページ、開いたままのタブ)のときも同じ帯が出ます。直し方は同じです(`atlas.bat` はページを作り直し、サーバも起動し直します)。版は、atlas のソースと、画面の作り方・依存を決めるファイル(各パッケージの設定と `package.json`、`package-lock.json`)の中身から作る目印で比べます(画面を作るときにページへ埋め込み、サーバは起動したときの目印を返します。エディタの作業ファイルや改行の違いでは変わりません)。`atlas serve` をコマンドで実行して前のサーバを使い回すときは、版が違えば、そのターミナルにも同じことを出します(`atlas.bat` をダブルクリックしたときは、すぐ窓が閉じるので画面の帯で知らせます)。
- もう一度 `atlas.bat` を実行すると集計し直し、サーバが動いていればブラウザを開くだけにします。
- 画面から「集計し直す」や判定を実行している最中は、同じ `out/` に並行して書かないよう `atlas.bat` の集計を止めて理由を出します(終わってから実行してください)。
- 逆に、`atlas` のコマンド(`all`・`build`・`judge` など out/ に書くもの)や `bin\atlas.exe judge-flow` が動いている間は、画面からの処理も始めずに理由を出します。動いている印は `out\.job.json` で、処理が落ちて残っても、そのプロセスが無ければ次の実行が自動で無視します。
- サーバ無しで開いた画面(`out\atlas.html` を直接開いたもの)は閲覧だけで、タスクタグの編集・メモ・画面からの操作は出ません。

## 画面からの操作

`atlas.bat` から開いた画面(ローカルサーバ経由)では、次の操作ができます。`file://` で開いた画面には出ません。画面から動かす処理は同時に 1 つだけで、動いている間は他の操作のボタンが押せません。処理の出力は `atlas.bat` の黒い窓にも流れます。

| 画面の操作 | 場所 | すること |
|---|---|---|
| 集計し直す | レポート(`atlas.html`)の右上 | `atlas.bat` と同じ集計(`all`: snapshot → extract → metrics → export)をやり直す。終わると本文の上の帯に「新しい集計ができました」と「再読み込み」が出る。自動では読み直さない(メモの入力中などを消さないため)。集計中は詳細ページと記録が作り直しの途中なので、開くと「集計し直している最中です」と出ることがある |
| 別のフォルダを開く… | レポートの右上 | この PC のセッションとは別に、選んだフォルダ(アップロード先 = 全員の分、その下の人のフォルダ = その人の分、プロジェクトやタスクタグのフォルダ)を集計して、新しいタブで開く。集計は別のプロセスが行い、この画面はそのまま使える(下記「[別のフォルダを開く](#別のフォルダを開く)」) |
| 判定する… | レポートの右上 | ダイアログで「判定するもの」(工数 = セッションごとの推定人手工数 / 依頼ごとの採用)と「判定の方法」を選ぶ。選んだものはブラウザに覚える。工数で「このツールが判定する」を選んだとき: 確認を出してから、未判定のセッションを LLM で判定し(bundle → judge run → export)、レポートを作り直す。確認には件数(未判定のうち上限まで。上限の既定は 10)・判定に使うもの(GitHub Copilot CLI の `copilot -p`)・「AI クレジットを消費します」を出す。「やめる」・Esc では何も実行しない。従量課金の `anthropic` とモデルの指定は画面からはできない(Copilot の既定のモデルを使う) |
| 判定する… →「依頼ごとの採用」 | 同じダイアログで判定するものを切り替える | 依頼ごとに、AI の成果の扱い・合わなかった点・普段の工程を LLM に判定させる([judge.md の 3](judge.md#3-依頼ごとの採用))。「このツールが判定する」では GitHub Copilot CLI(`copilot -p`)を使い、件数(依頼の数。既定 60)を決めて実行すると、未判定の依頼を数件ずつ判定してレポートを作り直す(`turns bundle` → `turns run` → `export`)。「チャットに貼って判定する」は下の行と同じ 4 つの手順で、添付ファイルは `out/turn-bundle/parts/`(ダウンロードの名前は `turns-part-01.txt` など)、取り込み先は `out/turn-judgments.json`。添付ファイルは採用を判定できる依頼(次の依頼がある依頼)が先で、手順 1 に「先頭の M ファイルに入っています」と出る。その後ろはセッションの最後の依頼だけ(一覧に「最後の依頼だけ」と付く)で、採用率だけを見たいときは先頭の M ファイルで止められる |
| 判定する… →「チャットに貼って判定する」 | 同じダイアログで方法を切り替える | M365 Copilot のように、ファイルの添付と貼り付けしかできないチャットで判定する流れ(相手は M365 Copilot に限らない。ファイルの添付か貼り付けができる LLM なら使える)。添付ファイル(`out/bundle/parts/`)を未判定のセッションだけで作り、次のファイルのダウンロード(`.txt` で保存)・本文のコピー・依頼文のコピーを出す。チャットの返答を貼って(返答を保存したファイルを選んで欄に入れてもよい)「取り込む」と `judgments.json` に入れ、形が合わなければ何も取り込まずに、何件目のどのセッションのどの欄が違うかを出す(「直す点をコピー」でチャットに渡せる)。「レポートに反映する」でレポートを作り直す(`export`)。どの手順も AI クレジットを使わない。サーバが Windows なら、手順 2 に「M365 Copilot で自動で判定する」が出て、開いている M365 Copilot のアプリを操作して残りのファイルを 1 つずつ送り(Think Deeper)、返答を取り込んでレポートに反映する(動いている間は上の帯に出て、ログをダイアログに出す)。選んだ方法はブラウザに覚える([judge.md の 2a](judge.md#2a-外部の-llm-で判定するm365-copilot-など)) |
| 判定する… →「ZIP にまとめてエージェントに渡す」 | 同じダイアログで方法を切り替える(工数の判定だけ。依頼ごとの判定では選べず、理由を下に出す) | フォルダやファイルを読めるエージェントやローカルの LLM に、バンドルを 1 つの ZIP で渡す流れ([judge.md の「エージェントやローカルの LLM に渡す」](judge.md#エージェントやローカルの-llm-に渡す))。手順は 4 つ。(1) 「未判定 N 件で ZIP を作る」で、未判定のセッションのバンドルと `out/bundle.zip` を同じ回に作る(`bundle --unjudged --zip`。「チャットに貼って判定する」の添付ファイルも作り直される)。(2) 「bundle.zip をダウンロード」と依頼文のコピーを出す(保存した ZIP を展開し、できた `bundle` フォルダだけをエージェントに開かせる。依頼文は、結果をそのフォルダの中の `judgments.json` に書かせる。ターミナルの返答を写すと、行の折り返しで JSON が壊れて取り込めないことがあるため。出力先の中の ZIP の場所は出さない)。(3) エージェントに書かせた `judgments.json` か返答を保存したファイルを選んで(貼り付けてもよい)「取り込む」。(4) 「レポートに反映する」。手順の上に、中身を渡してよい相手か確かめることと、ツールを使えるエージェントにはシェルの実行と Web へのアクセスを許可しないこと、書き込みを許可するのは結果の `judgments.json` だけにすること、出力先(`out/`)を開かせないことを出す。前のバンドルから作った ZIP は出さない(`--zip` なしで作り直すと消える)。どの手順も AI クレジットを使わない(費用は渡した相手の側で決まる) |
| 設定… | レポートの右上 | `setup.bat` と同じ設定を画面で決める(どれも押した時点で `atlas.config.json` に書く。設定ファイルを読めないときは理由を出して変えさせない)。**llm-wiki の vault**: 「エクスプローラーで選ぶ…」かフォルダ名・パスの入力で調べ、実在すればフォルダ名だけにして中の `index.md` と `wiki/` を見る。個別ページのフォルダ(既定は `wiki/` があればそれ)・索引のファイル名(`index.md` が無いとき)・wiki の skill として数えるもの(インストール済みの skill のうち名前に `wiki` を含むもの)を確かめてから足す。外すこともできる。変えたら「集計し直す」で反映される(ダイアログにも「集計し直す」が出る)。**普段の工程名**: `/` か `,` で区切って 2 つ以上。「既定に戻す」もある。**アップロード先**: タスクタグの見出しの「場所を決める…」と同じ。**まとめて送るプロジェクト**: 「プロジェクト別」の表の「まとめて送る」と同じ印を、名前で絞り込んで付け外しする(空のセッションだけのプロジェクトは出さない。送れるものが無いため) |
| 記録を読む ↗ | 詳細ページの表題の下 | そのセッションの記録(`out/sessions/<id>.md`)を別のウィンドウで読む。見出しの目次つき。詳細ページはそのまま残る |
| 全文を作って読む ↗ | 詳細ページの表題の下 | そのセッションの全文記録だけを作って(`out/full/<id>.md` と `out/full/assets/<id>/`。他のファイルは作り直さない)、別のウィンドウで読む(押すとすぐ空のウィンドウが開き、できたらそこに表示。もう一度開くときは状態の行の「全文記録を開く」) |

- **実行中**: 帯に経過時間と、出力の最後の 1 行が出ます。「止める」で止められます。判定は 1 件ずつ `judgments.json` に確定しているので、止めても判定済みの分は残り、次の「集計し直す」でレポートに出ます。集計を途中で止めたときは、レポートが作り直しの途中かもしれないので、もう一度「集計し直す」を押してください。
- **失敗したとき**: 帯に終了コードと、出力の末尾(200 行まで)を開けるログが出ます。判定で一部のセッションが失敗したときも、判定できた分はレポートに反映されるので「再読み込み」が出ます。
- **画面を閉じても処理は最後まで続きます**。サーバは処理が終わってから、画面が開いていなければ止まります。
- **記録の表示**は、メモと同じ規則で描きます。生の HTML は文字のまま(atlas 自身が書く `<small>` `<details>` `<summary>` の属性の無い形だけはタグとして描きます)、リンクは http / https / mailto だけ、外部の画像は読み込みません。全文記録だけは、そのセッションの `out/full/assets/<id>/` にある画像とファイルへのリンクを通します。20MB を超える `.md` は描かず、大きさと「.md を開く」を出します。
- 記録の本文はサーバに token を付けて取りに行くので、`atlas.bat` から開いた画面からしか読めません(表示のアドレス `/view/<id>` を他のページから開いても本文は出ません)。
- 画面から集計し直すときは `atlas.bat` に渡した引数(`--since` など)を引き継ぎません(既定の `all`)。絞り込んだ集計はコマンドで行ってください。

### 別のフォルダを開く

管理する人が、アップロード先(NAS や共有フォルダ)に集まったセッションを見るための操作です。いつもの画面(この PC のセッション)はそのまま残り、選んだフォルダのレポートが新しいタブで開きます。

- **選べるフォルダ**: 送り先が `<送り先>\<名前>\<プロジェクト>\<セッション ID>\` の形なら、`<送り先>` を選ぶと全員の分、`<名前>` を選ぶとその人の分、`<プロジェクト>` を選ぶとそのプロジェクト(かタスクタグ)の分になります。読むのは 2 段下までです。`~/.copilot` の形のフォルダ(別の PC から写したものなど)も選べます。
- **初めからフォルダを選んで開く**: いつもの画面を開かずに始めるときは、`open-folder.bat` を使います(選ぶ画面が出て、選んだフォルダを集計して開きます。出力先とメモは、この画面から開いたときと同じです。[README](../README.md#アップロードされたセッションを集計する別のフォルダを開く))。
- **フォルダを選ぶ**: 「エクスプローラーで選ぶ…」(Windows だけ)か、フルパスを入れて「調べる」。調べると、フォルダ名と、何を読むか(人のフォルダなら「下のフォルダ 2 件をまとめて集計します(proj-a、proj-b)」、送り先なら「2 段下まで読み、2 個のフォルダ(person-a、person-b)の下にある 3 件のフォルダをまとめて集計します」のように、入る人のフォルダの名前)が出ます。集計できないとき(フルパスでない・見つからない・セッションが無い)は、その理由が出ます。エクスプローラーの「パスのコピー」で付く `"…"` は付けたままで構いません。
- **集計して開く**: 押すと、「開いたことのあるフォルダ」にそのフォルダが「集計しています…」(進み具合の最後の 1 行つき)で並びます。終わると「開いています」に変わり、新しいタブで開きます。タブが開かなかったときは、行の「表示する」を押してください。ダイアログやこの画面を閉じても集計は続きます。
- **開いたことのあるフォルダ**: 新しく開いた順に 30 件まで並びます。行の状態は次のとおりです。

  | 状態 | 出るもの |
  |---|---|
  | 集計しています… | 進み具合。終わるまで操作は出ません |
  | 開いています | 「表示する」(新しいタブ) |
  | 前に開いた日時 | 「集計して開く」(フォルダを読み直してから開きます。前に集計したときから何も変わっていなければ、作り直さずにそのときのレポートを開くので、すぐに開きます) |
  | 失敗しました: <理由> | 理由(分からないときは、記録 `open.log` の場所)と、「もう一度開く」 |
  | この画面で表示中 | そのフォルダの画面で見ているとき。操作は出ません |

  「一覧から外す」は一覧から消すだけで、集計の出力とメモは残ります(もう一度同じフォルダを開くと、同じ場所を使います)。
- **開いた先の画面**: 上部に「対象: <フォルダ名>」が出て(カーソルを合わせるとフルパス)、タブの題名が「<フォルダ名> | Copilot Session Atlas」になります。この PC のセッションの画面には、どちらも出ません。「別のフォルダを開く…」を開くと、今のフォルダと、「この PC のセッションを表示する」(いつもの画面が開いているとき。閉じていれば、`atlas.bat` で開けることを出します)が出ます。そこから別のフォルダも開けます。
- **サーバと置き場**: フォルダごとに別のサーバ(`127.0.0.1` だけ。黒い窓は出ません)が立ち、そのタブを閉じると、いつもの画面と同じ決まりで止まります。いつもの画面を閉じても、開いたフォルダの画面は残ります。集計は `out-folders\<キー>\out\` に分けて置き、いつもの `out\` と `atlas-notes\` には混ぜません([cli.md の「別のフォルダを開く(open)」](cli.md#別のフォルダを開くopen))。開いた先の画面で「集計し直す」を押すと、同じフォルダを読み直します。読み直すたびに、フォルダから無くなったセッション(送り先から消したセッション・プロジェクト・人のフォルダ)は、前に写した複製も消して、レポートから外します。前にあったフォルダを読めなかったとき(アクセス権・つながらない共有フォルダ)などは、無くなったとみなさずに前の複製で数え、レポートの警告に出します([cli.md の「snapshot と extract が読むもの」](cli.md#snapshot-と-extract-が読むもの) の「元のフォルダから無くなったセッションは、複製も消します」)。「設定…」は、いつもの画面と同じ `atlas.config.json` を書きます。
- **開いた先は読むだけ**: 上部に「読むだけ」と出ます。タスクタグとメモは、送った人が付けていたもの(アップロードしたときに各セッションのフォルダに入った `atlas-session.json` の `tags` と `atlas-memo.md`。送った時点のもの)を出します。タスクタグは人ごとに分け、「<名前> / <タグ>」の名前にします(送り先の全体を開いたとき。同じ名前のタグでも、別の人のものは別のタスクタグです)。人のフォルダやプロジェクトのフォルダを開いたときは、タグの名前だけです。古い版で送ったセッションには、タスクタグがありません。
  - 出さない操作: タスクタグを作る・付ける・外す・名前と一文を変える・消す・書き出す・アップロードする、メモを書く、「まとめて送る」の印(表と設定)。詳細ページのタスクタグは「送った人が付けたもの」と出し、外す・付けるは出しません。サーバも、これらの書き換えを断ります(画面を通さずに呼んでも)。
  - 使える操作: 「集計し直す」「判定する…」(この PC の出力先 `out-folders\<キー>\out\` に書くだけで、送り先は書き換えません)、「全文を作って読む」、「設定…」(いつもの画面と同じ `atlas.config.json`)、「別のフォルダを開く…」。
  - 前の版で、開いた先の画面に書いたメモとタスクタグ(`atlas-notes\folders\<キー>\`)は、ファイルには残りますが、画面には出しません。
- **送った atlas の版**: 送り先から集計した画面の上部に「送った atlas: すべて最新」か、「送った atlas: 対応が要る人 3 人」のような注意(色付き)が出ます。数えるのは人です(送り先をまとめて開いたとき。同じ人が何件送っていても 1 人)。カーソルを合わせると、理由ごとの人数(「5 人のうち 対応が要る人 3 人(古い atlas で送った人 2 人・書き換えた atlas で送った人 1 人)」)、最新の atlas、対応が要る人の一覧(1 人 1 行。理由とセッションの数、当てはまるフォルダ、使った atlas、そのフォルダを送った日付)、理由ごとの頼むこと、最新の atlas で送った人、この PC の atlas が出ます。理由は次の 5 つです。「古い atlas で送った」は、最新より前の atlas で送った人です。`atlas.bat` を開いてもらう(開くと最新になります)か、定期の自動送信(送る前に最新にします)を待ってから、送り直してもらってください。「書き換えた atlas で送った」は、atlas のフォルダのファイル(git が管理しているもの)を書き換えたまま送った人です。書き換えたファイルを元に戻してから(`git status` で分かります。戻すまで自動の更新も止まります)、送り直してもらってください。「版の記録が無い」は、版を記録する前の atlas で送ったか、atlas を使わずに置いたセッションです(今の atlas で一度送れば、変わっていないセッションにも記録が付きます。ログは写し直しません)。「版の新旧が分からない」は、git で取得していないフォルダの atlas で送った人です。「送った記録を読めない」は、フォルダの索引を読めなかった人で、送っている最中に集計したときに出ることがあり、集計し直すと消えることがあります。セッションがすべて最新でも、最後に送ったときの atlas が最新でない(または書き換えた atlas だった)フォルダがあれば、その人を同じ理由で数えます。最新の atlas は、送った atlas とこの PC の atlas のうち、コミットの日時がいちばん後のものです。人のフォルダやプロジェクトのフォルダを開いたときは、送った人が 1 人なので、タグはセッションの数(「古い atlas で送ったセッション 3 件」)、内訳はフォルダごとになります。数え方は [cli.md の「snapshot と extract が読むもの」](cli.md#snapshot-と-extract-が読むもの)の「送った atlas の版を数えます」。
  - `atlas all --home <送り先>` で集計した画面も、`atlas serve`(`atlas.bat`)で開くと同じく読むだけです。
  - 送った人のメモは、本文 1 MB まで・画像は 1 セッションで合計 100 MB までを出します(超えるものは写しません)。
- **もう開いているフォルダ**をもう一度「集計して開く」と、集計し直さずに、一覧の見出しの下に「<フォルダ名> はもう開いています」と出て、その行の「表示する」に移ります(そこから開けます)。集計し直すには、開いた先の画面で「集計し直す」を押します。
- **一覧の読み直し**: このダイアログを開いている間、集計中のフォルダがあれば 1.5 秒ごと、開いているフォルダがあれば 5 秒ごとに一覧を読み直します(開いた先のタブを閉じてサーバが止まると、「開いています」が「前に開いた日時」に変わり、「表示する」が「集計して開く」に変わります。見出しの下の「表示するを押してください」の知らせも消えます)。ほかのタブからこの画面に戻ったときにも読み直します。
- **判定(工数・依頼ごとの採用)** は、開いた先の画面でもそのフォルダの出力先に対して動きます。「このツールが判定する」は、ほかの人のログを LLM に送ることになるので、送ってよいかを確かめてから使ってください。

## 画面の見方

- **上部**: 生成日時、記録期間、「記録 N 件のうち M 件を集計対象にしています(空のセッション K 件を除外)」の 1 文、配色の切り替え(自動 / ライト / ダーク)。
- **目次と件数**: 幅 768px 以上では左にサイドバーが固定され、各欄へのリンクを 概況(全体・要点・改善点・工程と詰まり・集計明細・AI の変更の残存(照合してあるときだけ)・比べる・課題 × 条件(名前の決まりに合うタスクタグがあるときだけ))/ 内訳(利用ランキング・実行の性質・プロジェクト別・月別推移・モデル別・モデルと推論強度の効果。送り先の全体を集計したレポートでは、プロジェクト別の前に人別)/ 一覧(セッション一覧)/ 付録(失敗の台帳の集計、指示文と skill、用語の説明。どれも別ページ)の 4 群に分けて並べ、その下に「タスクタグ」の群(下記「[タスクタグとセッションの選択](#タスクタグとセッションの選択)」)が続きます。スクロールに合わせて読んでいる欄に印が付き、下に「表示中 N / 集計対象 M セッション」、絞り込みが効いているときは「K 条件で絞り込み中」の印と「解除」が出ます。768px 未満ではサイドバーの代わりに上部に細い目次の行が固定され(横に流れます。現在地に印)、右端に件数と「解除」が出ます。母数の M は上部の 1 文の M と揃えています。
- **絞り込み**: 1 行目に期間(開始日・終了日・直近 30 / 90 日)・プロジェクト・クライアント・モデル(送り先の全体を集計したレポートでは、プロジェクトの前に「人」。下記「人別」)、「その他の条件」を開くとブランチ・入力トークン記録の有無・タスク分類・空のセッションの切り替えが出ます(どれかが効いている間は閉じられず、効いている数を印で出します)。絞ると下の欄がすべてその条件で集計し直され、サイドバー(狭い画面では上部の固定行)の「表示中 N / 集計対象 M セッション」が今の件数です。絞り込み行そのものは固定せず、スクロールすると流れます(条件を変えるときは上に戻ります)。キーボードでは Tab で順に移り、押した部品に緑の枠が出ます(日付入力は年・月・日の 3 区画で Tab を使うブラウザの仕様です)。**空のセッション**(依頼・ツール呼び出し・応答がどれも無い、開いただけのもの)は既定で集計・一覧・プロジェクト表・中央値のすべてから外しています。「その他の条件」の「空のセッションを含める」にチェックすると含めます(このときの「集計対象 M」は空を含めた件数)。条件は URL の `#` 以降に残るので、ブックマークすれば同じ絞り込みで開けます。タスク分類は LLM による判定(judgments.json)があるときだけ選べます(無いときは理由を欄の下に出します)。
- **要点**: 絞り込み後の集計から決まった規則で選んだ短い一覧です(LLM は使いません)。AI 使用量(AIU)の大きいセッション上位 3 件(AIU の記録が無い条件では出力トークンの多い順)、失敗率の高いツール(結果の記録が 5 回以上で失敗・拒否のあったもの。失敗の要因の記録があれば、いちばん多い要因を添えます)、compaction の多いセッション、インストール済みで未使用の skill。各項目にはリンクがあり、セッションならその詳細ページ、ツールなら今の絞り込みに「そのツールを使ったセッション」を足した状態(URL の `#…&tool=<ツール名>`)、未使用の skill なら利用ランキングの未使用一覧に移ります。ツールで絞っているときは絞り込み行に「<ツール名> を使った ×」が出て、押すと外れます。
- **全体サマリ(表紙)**: 規模の 4 欄(セッション数、期間、実働時間、推定人手工数)。帳票の「表紙 → 摘要(要点)→ 明細」の順に並べているので、この下に要点、その下に集計明細が来ます。空のセッションを外しているときは、その件数を「空のセッション N 件を除外」と出します。
- **集計明細**(要点の下): 4 列 × 3 行の 12 欄。トークン(入力・出力・うち推論・キャッシュ読取)、AI 使用量(AIU)、premium request、API リクエスト、ツール呼び出し(失敗率つき)、変更行数、skill・agent・hook の件数、指示ファイルと llm-wiki の利用(llm-wiki は参照したセッションの数で、書き込みだけのセッションは入れません。数え方は用語の説明の「llm-wiki」。対象の vault は「[wiki の指定](cli.md#wiki-の指定)」。vault を指定せずに集計したレポートでは wiki の欄を出さず、見出しの下に数えていない理由を出します)、摩擦の合計。各欄の下の注記は 1 行程度に抑え、摩擦の内訳の続きは「実行の性質」へのリンクにしています。**入力トークン・AI 使用量・premium request・変更行数は記録が残っているセッションだけの合計**で、欄の下に「記録あり N / M セッション」を出します。
  - AI 使用量は nano AIU を 10 億で割った AIU で、桁区切りで表示します。金額には換算しません。premium request は旧来の課金単位で、記録のある(主に 2026 年 7 月以前の)セッションだけの合計です。
  - 変更行数(追加 / 削除)は、セッション終了時の累計(`session.shutdown` の `codeChanges`)を優先し、無ければツールごとの行数(`toolTelemetry`)を合計したものです。
  - 依頼の回数には、autopilot が自分で作業を続けるときの自動継続(ログ上はユーザーのメッセージとして残る)を含めず、別に「自動継続 N 回」と出します。
  - ツール呼び出しの回数には、作業の途中経過を画面に出すための内部ツール(`report_intent`)を含めず、件数だけ別に出します。
  - 摩擦の内訳では「ツール失敗」(個々のツール呼び出しの失敗)と「エラー」(`session.error`。利用上限・通信エラーなどセッション全体のエラー)を分けています。
  - その下の「入力トークン記録の内訳」で、明細あり / 終了時の累計のみ / 出力のみ / **記録なし(欠測)** の件数を確認できます。記録なし(欠測)は、依頼や応答があるのにトークン量の記録がどこにも無いセッションです(2026 年 9 月以降のログは `assistant.message` に出力トークン数を書かなくなったため、session-store.db・usage_record・終了時の累計のどれも無いと出力トークンも分かりません)。0 として足さず、件数で示します。帯の欠測の区画は色に加えて斜線で区別しています。
  - 帯の下に、画面で使う欠測の語の凡例を置いています: **記録なし**(ログにその項目の記録が無い)/ **推計不可**(出力トークンだけ記録があり入力は求められない)/ **未判定**(LLM の工数判定をまだ実行していない)/ **不明**(記録はあるが分類できない。クライアント・モデルなど)/ **—**(該当なし)。用語の説明ページの先頭にも同じ凡例があります。
- **改善点の「llm-wiki のページごとの参照率と役立った率」**: 改善点の「絞り込みに従う」群の最後に、幅いっぱいの箱で出します(列が多いので、ほかの箱と横に並べません)。ページ 1 行の表で、列は ページ / 読んだセッション / 参照率 / 役立った / 役立たなかった / 分からない / 未判定 / 役立った率。読んだセッションの多い順(同じならページの名前の順)に上位 10 行を出し、残りは「全件を表で見る」で開きます。上の絞り込みに従います。中身は [outputs.md](outputs.md#改善点規則による分析) の表のとおりです。
  - **参照率** = そのページを読んだセッション ÷ wiki を参照したセッション(集計明細・改善点の「llm-wiki の利用」と同じ数え方。書き込みだけのセッションは入れません)。分母の件数を表の題に出します。ログで分かるのは「読んだ」ことまでなので、言葉は「引用」でなく「参照率」で、注に「回答の中で引用したかは見ていません」と書きます。
  - **役立った・役立たなかった・分からない** は、判定を回したセッションの LLM の見立ての件数です([judge.md の「llm-wiki のページごとの判定」](judge.md#llm-wiki-のページごとの判定))。**未判定** は、判定していないセッション、ページごとの判定が無い前の版の判定、判定に載せなかったページ(1 セッション 10 ページまで)、返答の形が崩れていたページです。**役立った率** = 役立った ÷(役立った + 役立たなかった)で、分からない・未判定は分母に入れません。注に「役立ったかは LLM の見立てで、判定役は読んだページの名前と、ログにあれば抜粋を見たうえで答えています。測った値ではありません」と書きます。
  - 率は、分母(参照率は wiki を参照したセッション、役立った率は役立った + 役立たなかった)が改善点のほかの率と同じ閾値(`packages/report/src/lib/insights.ts` の `THRESHOLDS.MIN_SESSIONS`)に届かなければ「—」です。参照率(ログ)と役立った率(LLM の見立て)は別の列のままで、1 つの点数にまとめません。セッション全体の判定の「llm-wiki の効果」(−2〜+2)はそのまま残り、この表には使いません。
  - vault を指定せずに集計したレポート・指定の記録が無い古い集計では、表を出さずに「llm-wiki の利用」の箱と同じ理由の文だけを出します。ページの名前を記録する前の版(埋め込みの版 17 以前)で作った `atlas.html` でも表を出さず、集計し直すと出ることを書きます。詳細ページの「LLM による判定(推定)」には、そのセッションのページごとの見立てと理由を出します。
- **工程と詰まり**(改善点の下): 依頼(ターン。利用者の 1 回の依頼から次の依頼の直前まで)ごとに、AI が主にしたこと(工程)とその間のつまずきを数えた表です。工程はその依頼で使ったツール(サブエージェントの分を含む)から決めます: 編集があれば実装、無くてテスト・ビルドを実行していれば検証、git のコミット・push などがあれば運用、計画・確認だけなら計画、ツールを使わなければ回答のみ、それ以外は調査。LLM は使いません。
    - **工程別**: 依頼の数と割合、実働時間、AI 使用量、詰まりのあった依頼(ツールの失敗・拒否・中断・エラー・前の依頼で編集したファイルの再編集・文脈圧縮のどれかがあったもの)の数と割合、それぞれの回数(エラーの括弧内は利用上限・速度制限によるもの)、「次の依頼で直し・差し戻し」(次の依頼が「直して」「戻して」などだった依頼 / 次の依頼があった依頼)。最後の行が合計です。
    - **依頼の種類 × 工程**: 依頼文の語で粗く分けた種類(作業 / 質問 / 修正 / 差し戻し / 続行)が、どの工程で起きたかの件数。「どこで聞いているか」を見る表です。言い回しの違う修正は「作業」に入ることがあります。
    - **採用(LLM の判定)**(依頼ごとの判定があるときだけ。無いときは判定のしかたの案内): 普段の工程別に、判定した依頼の数、作業の依頼の扱い(そのまま / 中身を修正 / 体裁を修正 / 不採用)と採用率(判定できた作業の依頼のうち「そのまま」の割合)、質問の依頼の扱い(役に立った / 追加で聞いた / 的外れ)と役に立った率、判定不能。その下に、合わなかった点(意図・要件の取り違え / 誤り・不具合 / 品質・体裁・決まりごと / やり過ぎ・足りない / 環境・ツール・権限 / その他)× 普段の工程の件数。どれも次の依頼の文から LLM が決めた推定です。
    - 絞り込みに合わせて集計し直します。1 セッションの先頭 200 依頼までを数えます。依頼があるのに依頼ごとの記録が無いセッション(古い集計など)は件数を断ります(「集計し直す」で入ります)。
- **AI 投入量 vs 推定人手工数**(判定結果があるときだけ): 判定済みのセッションについて、LLM が推定した人手工数(幅と平均確信度つき)と、同じセッションで AI が使った実働時間・トークンを全体とプロジェクト別に並べます。「推定人手工数 ÷ AI の実働」は目安で、削減量の実測ではありません。確信度が 30% 以下の推定は、合計・幅・中央値・「推定人手工数 ÷ AI の実働」に入れず、「確信度が 30% 以下の推定 N セッション(計 H 時間、幅 …)は、合計にも…入れていません」と別に出します(プロジェクト別の表では「別枠 H 時間(確信度の低い N 件)」。全体サマリの推定人手工数の欄と、プロジェクト別集計の列にも短く出します)。AI が大量に生成して動くかを確かめられないセッションなど、推定の根拠が弱いものです。合計の横には中央値(1 セッションあたり)も出します。合計に入れたセッションが 5 件以上で、推定の大きい上位 5% のセッション(1 件に満たなければ 1 件)が合計の半分以上を占めるときは、「合計の N% は、推定の大きい上位 M セッション(計 H 時間)によるものです」と出します(全体サマリの推定人手工数の欄にも短く出します)。合計は和なので、AI が大量に生成したセッションの大きな推定が数件あるだけで、ほぼその値になるためです。
- **AI の変更の残存**(`atlas vcs` で照合してあるときだけ。`atlas.bat` の集計にも入る): AI が足した行が、その後の VCS のファイルに残っているかを、絞り込んだセッションで数えます。残っているかの記録で、採用の意図や良し悪しではなく、「見つからない」「照合不可」を不採用とはみなさないことを、節の説明に書いています(詳細ページの同じ節も)。見出しの横に、比べる版と照合した日時を出します。照合の範囲の下に、セッションの終わりから比べた時点までの日数(中央値と幅)を出します。設定の `vcs.note` があれば、その一文も出します。
  - 4 つの欄: 照合できたセッションの数と、そのまま残る・直されて残る・見つからない、の割合(分母は照合できたまとまり)。
  - **割合を出す条件**: 照合できたセッションが 5 件未満のときは、割合と帯を出さず、件数だけ出します(1 つのセッションのまとまりだけで割合が大きく動くため。「比べる」と「モデルと推論強度の効果」の残存の割合も同じ件数)。最初の欄の「AI の変更があったセッションのうち照合できた割合」も、AI の変更があったセッションが 5 件未満なら件数で書きます。工程ごと・プロジェクトごとの表は、行ごとに同じ決まりを掛けます。
  - まとまりの内訳: 4 つの状態の帯と凡例(照合不可は斜線で、分母に入れない)。
  - 照合の範囲: 表示中・AI の変更なし・照合していない・AI の変更あり・照合できた・照合不可(理由別)の件数と、ログから変更を取り出せなかった AI の編集の件数。
  - 工程ごと: 照合できたセッションのまとまりを、作った編集の時刻にその依頼が進んでいた工程(「工程と詰まり」と同じ決め方)で分けた、状態別の数と割合。その工程に照合できたまとまりのあるセッションの数を並べ、5 件未満の工程は割合を出しません。依頼の記録が無いセッションは入れず、件数を出します。
  - プロジェクトごと: AI の変更があったプロジェクトの、状態別のまとまりの数と割合(照合できたセッションが 5 件未満のプロジェクトは件数だけ)。
  - 状態の名前は設定の `vcs.labels` で差し替えられます。数え方は [outputs.md の「AI の変更の残存」](outputs.md#ai-の変更の残存vcs-の照合)。
- **比べる**: 2 つの条件(タスクタグ・期間・プロジェクト・工程・推論強度)を A・B で選び、セッション数・手戻りのないセッションの割合(推論強度を選んだときは、依頼 2〜4 件・5 件以上に分けたものも)・採点できたセッション・依頼 / セッション・実働 / セッション・リクエスト / セッション・AIU / セッション・AIU / リクエスト・ツールの失敗・拒否の率・同じファイルを編集し直したセッションの割合と、AI の変更の残存(照合してあるとき)を並べ、差(B − A。割合はポイント)と差の幅(95%)を出します。手戻りのないセッションは、依頼の記録が 2 件以上あるセッション(採点できたセッション)のうち、2 件目以降の依頼に直し・差し戻しが無く、どの依頼にも中断が無かったものです(依頼 1 件のセッションは採点できないので分母に入れません)。差の幅は、セッションを単位にした割合の行が Newcombe の方法(Wilson の区間から作る)、平均の行が Welch の方法(差 ± t × 標準誤差。t は件数とばらつきから決まる自由度での値で、件数が少ないほど 1.96 より大きい)で、件数・中央値・AIU / リクエストの比と、ツール呼び出し・まとまりの単位の割合には出しません。どちらかの側が 5 件未満なら「—」、幅が 0 をまたぐときは「(0 をまたぐ)」と文字で書きます。同じ人のセッションの似かたを入れていないので、実際の幅はこれより広くなります。推論強度を選んだときは、モデル(本体のリクエストがあるもの。既定はセッションのいちばん多いもの)・A と B の強度(既定は medium と xhigh、無ければ多い順の 2 つ)・期間(A と B に同じ期間。空なら限らない)を選び、本体の推論強度がその強度と決まったセッションを並べます(本体のリクエストの 90% 以上が同じ強度。サブエージェントは数えない。A と B に同じ強度を選ぶと、両側に同じセッションが出ます)。表の下に、選んだモデル・期間の中で本体の強度が混在のセッションと記録の無いセッションの件数を 1 行で出し、利用者(送り先の人のフォルダ)が記録されていれば利用者 × 週(月曜始まり、ローカルの日付)ごとの A・B・混在・記録なしのセッション数の表を出します(利用者の記録が無ければ週ごと)。上の絞り込みには従わず、全セッション(空のセッションを含めるかの条件だけ)から選びます。割合は、その側が 5 セッション未満のとき「—」です。平均は、実際に割る数(実働・AIU は記録のあるセッション。AIU / リクエストは、AIU とリクエストの両方の記録があるセッション)が 5 未満のとき「—」です(残存の割合は、照合できたセッションが 5 未満のとき)。期間は上の絞り込みと同じく、ローカルの日付で、作成日時(無ければ更新日時)で決めます。各行に数え方を書いています。期間の既定は、最後の日までの 30 日(B)とその前の 30 日(A)、タスクタグとプロジェクトの既定は先頭の 2 つです(選んでいたタスクタグの名前を変えた・消したなどで選択肢から無くなったら、選び直します)。差は相関で、条件の違いが原因とは限りません。 工程を選んだときは依頼(ターン)の単位で、依頼の数・実働 / 依頼・ツールの失敗・拒否の率・詰まりのあった依頼の割合・次の依頼で直し・差し戻しの割合・AIU / 依頼と、その工程の依頼で AI が足したまとまりの残存を並べます(依頼かまとまりが 5 件未満の割合と平均は「—」)。
- **課題 × 条件**(名前の決まりに合うタスクタグがあるときだけ): 同じ課題を、条件(素 / wiki あり / コード参照ツールあり など)を変えて何度も実行したセッションを、タスクタグの名前で分けて並べます。条件が 3 つ以上でも 1 つの表になります。
  - **名前の決まり**: タスクタグの名前を `課題__条件` か `課題__条件__番号` にします(区切りは半角の `_` を 2 つ、番号は半角の数字だけ。例 `render__wiki`、`render__wiki__1`)。番号が違っても、課題と条件が同じなら同じ行で、回数はセッションの数で数えます。1 つのタグに繰り返しの全セッションを入れても(`課題__条件`)、1 回ごとにタグを分けても(`課題__条件__番号`)同じ結果です(分けると、その数だけサイドバーのタスクタグが増えます)。並びは名前の順(数字は数として比べます)なので、先頭に置きたい条件は名前の頭に数字を付けます(例 `0-plain`)。大文字小文字・全角半角の違う名前は別の名前です(あれば表の下で知らせます)。
  - **表は 2 つ**: 「条件ごと(課題をまとめた行)」は、その条件のセッションをすべての課題から集めた行で、「課題」の列に、その条件のセッションがある課題の数 / 表の課題の数を出します(セッションの無い課題がある条件には ※)。課題が 1 つだけのときは出しません。「課題ごと」は、課題ごとに全部の条件を同じ順で並べます(その課題に無い条件は 0 件の行)。課題やセッションの数が条件でそろっていないと、課題の難しさの違いが条件の差に混ざるので、同じ課題の行どうしで読みます。
  - **列**: 件数、テストの記録なし(テストの結果の行を 1 回も読めなかったセッション。未達にも分母にも入れません)、最後に全部通った(最後の実行の後に通っていないテストが無いセッション ÷ テストの記録があるセッション)、通った後に不合格、未達の件数。「最初に全部通るまで(中央値)」のテストの実行・実働・AIU。「セッション全体」の実働と AIU の中央値、ツールの失敗・拒否の率(「比べる」と同じ数え方)。テストの数え方は [outputs.md の「テストの結果」](outputs.md#テストの結果印つきの-1-行-json)。テストの記録が 1 件も無いレポートでは、テストの列を出さず、件数とセッション全体の列だけにします。
  - **「—」と割った数**: 割合と中央値は、割る数(テストの記録があるセッション、AI 使用量の記録があるセッションなど)が 5 件未満なら「—」です。件数はいつも出し、割合と中央値のセルの下には、割った数(「4 / 6 件」「6 件」)を小さく添えます。ツールの失敗・拒否だけは、「比べる」と同じくセッションが 5 件未満なら「—」です。この決まりは、課題をまとめた行にも同じように掛かります。
  - **「最初に全部通るまで」の中央値**は、通ったセッションだけでなく、テストの記録があるセッション全部で取ります。一度も全部通らなかった(未達の)セッションをどの値よりも後ろに並べるので、全部通ったことのあるセッションが半分以下の行は「未達」と出ます(通ったセッションだけで取ると、未達の多い条件ほど小さく見えるためです)。AIU は、リクエストごとの記録があるセッションだけで取ります。
  - **表に入れないもの**: 課題か条件の違うタグが 2 つ以上付いたセッションは、どの条件の結果か決められないので、どの行にも入れません。`__` を含むのに決まりに合わないタスクタグと合わせて、表の下に件数を出します。`__` を含まないふつうのタスクタグには触れません。
  - **表**: 同じ表は、集計のたびに `out/tables/conditions.csv`(と `atlas.sqlite` の `conditions`)にも書きます。`sessions.csv` には、セッションごとの課題・条件とテストの列が入ります([outputs.md の「表(CSV)」](outputs.md#表csv))。
  - **利用の確認**: 条件が実際に効いたか(wiki ありの条件で wiki を読んだか、など)を確かめます。「確かめるもの」で llm-wiki の参照・skill・MCP サーバー・ツールのどれかを選ぶと(選べるのは、この表のセッションで使われたものだけ。llm-wiki はいつも選べます)、条件ごとに、それを使ったセッションと使わなかったセッションの数が出ます。それを使うはずの条件の「使うはず」に印を付けると、その条件で使わなかったセッションと、ほかの条件で使ったセッションを一覧にします(セッションの名前から詳細ページへ移れます。多いときは先頭の 50 件)。印は確かめるものごとに覚えますが、画面の中だけのもので保存しません(どの条件で使うはずかは、条件の名前から推測しません)。llm-wiki の参照は、索引・個別ページを読んだ回数、wiki の skill の呼び出し、vault の検索・一覧などそのほかの呼び出しで(集計明細・プロジェクト別・改善点の「参照した」と同じ数え方です)、書き込みだけのセッションは使わなかったに入ります。llm-wiki の参照は、集計した PC の設定で vault を指定したときだけ数えるので、指定せずに集計したレポートでは、llm-wiki を選んでも使った・使わなかった・割合と一覧を出さず、数えていない理由だけを出します。このときは「確かめるもの」の既定を llm-wiki 以外の最初のもの(skill・MCP サーバー・ツールの順)にし、llm-wiki は「(数えていません)」を付けて選択肢に残します。vault を指定していたかの記録が無い古い集計で、参照したセッションも無いときも同じで、選択肢には「(記録なし)」を付けます(数えていないのか、参照していないのか分からないため。[cli.md の「wiki の指定」](cli.md#wiki-の指定))。
  - 送り先の全体を集計したレポートでは、送った人が違っても、課題と条件の名前が同じなら同じ行にまとめます(2 人以上のセッションが入った行があれば、表の下に人数を出します)。上の絞り込みには従わず、全セッション(空のセッションを含めるかの条件だけ)から数えます。差や順位は出しません。差は相関で、条件の違いが原因とは限りません。列ごとの数え方は、表の下の「表の読み方」にあります。
- **利用ランキング**: 絞り込んだセッションで「何を使ったか」を、ツール / MCP サーバー / 失敗の要因 / skill / agent / hook / 指示ファイルの切り替えで上位 10 件の棒グラフにし、「全件を表で見る」で全件を表にします。絞り込みを変えると集計し直されます。
  - ツール: 呼び出し回数と失敗率(失敗 + 拒否 ÷ 結果の記録がある回数)。MCP のツールは「MCP」の印を付けてサーバーごとに 1 行にまとめます。「並べ方」で失敗率の高い順(結果 5 回以上のツールだけ)にもできます。表では成功・失敗・拒否・結果なしの内訳と、主な失敗の要因が見られます。
  - MCP サーバー: サーバーごとの呼び出し回数と、よく使ったツール。表では、サーバーの中のツールごとに失敗の回数と要因を出します。
  - 失敗の要因: ツールの失敗(拒否を除く)を、エラーの種類と文の 1 行目から決まった規則で分けた要因(時間切れ・上限や回数制限・通信や取得の失敗・アクセス権・一致なし・対象が見つからない・既にある・引数や書式の誤り・道具が使えない・応答なし・ツール内部のエラー・その他)の多い順です。各要因に、その要因で失敗したツール(MCP はサーバーの中のツール)を多い順に添えるので、どこで何が詰まっているかを要因から追えます。エラーの文は、秘密らしい文字列を伏せたうえで先頭 1000 字までを、失敗 1 件ごとの記録(sessions.json の失敗の台帳)に残します。ツール・MCP サーバー・エージェント・skill・指示文の版ごとの集計と、同じ文で繰り返している失敗は、別ページの「失敗の台帳の集計」(`out/failures.html`。[outputs.md の「失敗の台帳」](outputs.md#失敗の台帳))にあります(レポートに入れた記録の全体で計算し、画面の絞り込みは掛かりません)。以前の版で集計したセッションの失敗には要因の記録が無いので、その回数を別に出します(集計し直すと付きます)。
  - skill: 回数と、利用者が呼んだ(`trigger: user-invoked`)/ エージェントが呼んだ(`agent-invoked` と skill ツールの呼び出し)/ 不明(trigger を記録しない古いログ)の内訳。その下に「**インストール済みで未使用の skill**」(`~/.copilot/skills/` とプラグインの skill のうち、絞り込んだ期間に一度も呼ばれなかったもの。`settings.json` で無効にしたものには「無効」)を出します。送り先の全体を開いて人で絞っているときは、その人が送ったときに添えた記録で出します(記録の無い人なら全員分)。
  - agent: 起動回数・失敗・使ったトークン。hook: 種類ごとの実行回数。指示ファイル: 注入されたセッション数(「(user)」はユーザー単位の指示ファイル)。
- **実行の性質**: 絞り込んだセッションを「どう動かしたか」「どこで時間と文脈を使ったか」で見る欄です。値は記録のあるものだけの集計です。
  - モード別の依頼: 依頼(ユーザーのターン)ごとのモード(対話 interactive / 計画 plan / autopilot)。`user.message` の `agentMode`、無ければ直前の `session.mode_changed` で決めます。どちらも無い依頼は既定の interactive とみなし、その回数を欄の下に出します(実データでは最初のモード変更の変更前は全件 interactive でした)。
  - 推論強度別: リクエストの `reasoningEffort`(session-store.db / usage_record)、無ければその時点のセッションの設定(`session.start` / `session.model_change`)ごとのリクエスト数・入力・出力・AIU。終了時の累計しか無いセッションは、設定が 1 種類ならその強度に、それ以外は「不明」に入れます。

  - モデル別の待ち時間: 最初のトークンまで(`time_to_first_token_ms` / `timeToFirstTokenMs`)とリクエスト全体(`duration_ms` / `duration`)の中央値と p90(遅い方から 1 割の境目)。

  - todo: `session.db` の todo の状態別件数(完了 / 進行中 / 未着手 / 保留)、完了率(完了 ÷ 全件。セッション終了時点)、依存関係の数。

- **プロジェクト別**: プロジェクトごとの集計表。列見出しで並べ替え、プロジェクト名を押すとそのプロジェクトに絞り込みます(行に「絞り込み中」の印が付き、もう一度押すと解除。名前はリンクなので Ctrl+クリックで別タブにも開けます)。「最終更新」は、そのプロジェクトのセッションのうち、いちばん後に更新された日時です(更新日時の無いセッションは開始日時で数えます)。押すと新しい順、もう一度押すと古い順に並びます。入力トークンの下の小さな「5/30」は、記録のあるセッション数 / 全セッション数です。「変更行」は追加行数(下に削除行数)、「指示」「wiki」は該当セッション数 / セッション数(wiki は参照したセッションで、書き込みだけのセッションは入れません。vault を指定せずに集計したレポートでは wiki の列を出さず、見出しの下に「wiki の列は出していません」の短い断りを出します。理由の全文は集計明細にあります。人別も同じ)、「摩擦」の下には内訳の多い順 3 つを小さく出します。表が幅に収まらないときは横にスクロールでき、続きがある側の端に影が出ます(他の表も同じ)。
  - **まとめて送る**(`atlas.bat` から開いたときだけ): プロジェクト名の隣の列の印です。印を付けたプロジェクトは、`upload-project.bat` が番号を聞かずにまとめて送ります(送る前の確認はあります。`schedule-upload.bat` で登録した毎日の自動送信も、印のあるものだけを確認なしで送ります。README の「[プロジェクトのセッションをまとめて送る](../README.md#プロジェクトのセッションをまとめて送るupload-projectbat)」)。印は押した時点で `atlas.config.json` の `uploadProjects` に書かれ、外すと消えます(全部外すと項目ごと消え、bat は番号で選ぶ形に戻ります)。表の上に今の件数を出し、絞り込みの外のもの・今の集計に無いものがあればその件数も出します。設定ファイルを読めないなどで書けなければ、理由を出して印を元に戻します。開いたときに設定ファイルを読めなければ、印を 0 件と見せずに理由を出し、印を押せないようにします(直してから開き直します)。
  - プロジェクトは、ログの repository、無ければ git の origin(「所有者/リポジトリ」)で束ねます。同じリポジトリの別フォルダや worktree で開いたセッションも 1 つになります。ホームディレクトリそのもので開いたものは「(ホーム)」、一時フォルダ(`%TEMP%` 配下。scratchpad での試行など)は「(一時フォルダ)」、このツール自身の工数判定(`judge run` が作る `%TEMP%\atlas-judge-cwd-*`)は「(atlas の判定)」にまとめます。どれにも当たらないものは作業フォルダのパスのままです。
- **月別推移**: セッション数・出力トークン・入力トークン・AI 使用量(AIU)・premium request の月別の棒グラフ(月は UTC)。棒にマウスを乗せるかキーボードで選ぶと値が出ます。棒を押す(Enter / Space)と値の表示を固定でき、もう一度押すと外れます。「表で見る」で同じ値と変更行数を表で確認できます。AIU と premium request は記録のあるセッションだけの合計です。
- **モデル別**: モデルごとのトークンとリクエスト数。1 セッションで複数のモデルを使うことがあるため、セッション数の合計は全体と一致しません。表には推論強度別のリクエスト数(「high 120・medium 30」)も出ます。「推論強度で分ける」を押すと、棒と表が モデル × 推論強度 の行になります(強度の決め方は実行の性質の推論強度別と同じ。どちらも記録が無いリクエストは「不明」、強度を記録していない古い集計から作ったセッションは「強度の記録なし」。キャッシュ読取は強度別には数えません)。同じモデルがログの出所によって `claude-haiku-5-5` / `claude-haiku-5.5` / `<ID>/claude-haiku-5-5` のように書き分けられているため、`claude-haiku-5.5` の形にそろえています(`claude-<種類>-<数字>-<1 桁の数字>` で後ろに日付などが続かないものだけ。先頭の `<UUID>/` はプロバイダ設定の ID で、同じリクエストの記録にどちらの名前も残っていることを実データで確認しています)。
- **モデルと推論強度の効果**: モデル × 推論強度(「モデルごと」でモデルだけ)ごとに、使った量とコスト(セッション・リクエスト・1 リクエストあたりと 1 セッションあたりの AIU)と、効果(セッションの判定の達成率・品質・手戻り・1 AIU あたりの推定人手工数、依頼の判定の採用率・そのまま使えた割合、AI の変更の照合できたセッション(照合できた / AI の変更あり)と残っている割合、ツールの失敗率)を並べます。判定や照合をしていない効果の列は出ません。残っている割合は「比べる」と同じ数え方で、照合できたまとまり(照合不可を除く)のうち、残っている(そのまま + 直されて)ものの割合です。照合できたセッションが 5 件未満の行は割合を出しません(残存の節・「比べる」と同じ件数)。1 AIU あたりの推定人手工数には、確信度が 30% 以下の推定を入れません(「AI 投入量 vs 推定人手工数」の合計と同じ)。
  - 推論強度はリクエストごとに決まりますが、効果の記録はセッションや依頼ごとにしかないので、セッションの効果を、そのセッションのリクエストに占めるモデル × 推論強度の割合で按分して数えます(1 セッションの重みの合計は 1)。コストは按分せず、そのモデル × 推論強度のリクエストの実数です。
  - 表の上に読み取りを出します。同じモデルで、セッションが 3 件以上ある強度が 2 つ以上あれば、いちばん弱い強度といちばん強い強度のコストと効果を比べます(効果は、その記録があるセッションが按分して 1 件分以上あるものだけ)。モデルごとに、1 AIU あたりの推定人手工数のいちばん大きいモデルと小さいモデルも出します。
  - 難しい作業ほど強い推論強度や上位のモデルを選びやすいので、差がそのまま強度やモデルの効果とは限りません。セッションが 3 件未満の行には ※ が付きます。
- **セッション一覧**: 1 ページ 50 件。左端はチェック欄で、チェックした行は薄い緑になり、一覧の上の「N 件を選択中」と「選んだ N 件だけ集計」「選択を解除」「タスクタグを付ける ▾」「このタスクタグを外す」(後の 2 つは `atlas.bat` から開いたときだけ)が使えます(下記「[タスクタグとセッションの選択](#タスクタグとセッションの選択)」)。「開始」はセッションを始めた日時、「最終更新」は最後に更新された日時(更新日時の無いセッションは開始日時)で、どちらも列見出しを押すと新しい順・古い順に並べ替えられます。「変更行」列は追加行数(下に削除行数)。一覧の上の「セッションを探す」に、セッション ID の先頭(4 文字以上)か ID 全体、または題名(セッション名と、最初の依頼の文の先頭 160 字)の一部を入れると、合う行だけに絞ります。ID を含むパスや URL は、空白や引用符が入っていてもそのまま貼れます。ID の途中の文字では探せません(16 進の語や数字で、題名に無い行が偶然出ないように)。空白で区切ると、すべての語に合う行だけになります。全角と半角、大文字と小文字は区別しません。絞るのは一覧の行だけで、上の集計とチェックした選択は変えません(見つけた行にチェックを付けて「選んだ N 件だけ集計」を押せば、その行だけで集計できます)。ID で当たった行には ID を、名前に無く最初の依頼にだけあった語で当たった行には、最初の依頼のその辺りを出します。今の絞り込みで外れているセッションにも合うものがあれば、その件数を出します(「空のセッションを含める」だけで出る空のセッションは、別に数えます)。Esc で検索語を消せます(漢字に変換している途中の Esc では消しません)。詳細ページを開いてから戻ると、検索語も戻ります。推定人手工数は LLM による判定を実行するまで「未判定」です。空のセッションを含めているときは、空のものに「空」の印が付きます。名前を押すと[セッション詳細](#セッション詳細ページ)を開きます。一覧の中に書き出しが 20 字以上同じ題名が他にあるときは、共通の書き出しを先頭の数文字だけ残して「…」に縮め(薄い色)、違いが始まるところから見せます。題名がまったく同じ行には「同じ題名 ×N」の印が付きます(開始時刻やプロジェクトで見分けてください)。全文は名前に重ねると出ます。

### skill・llm-wiki・MCP サーバー・推論強度の違いを確かめる

skill・llm-wiki・MCP サーバー・推論強度が役に立っているかは、問いを 3 つに分けて確かめます。

1. **使われているか**: 普段のログの件数で分かります。
2. **選んだ課題で、条件によって結果が変わるか**: 同じ課題を条件を変えて繰り返し実行し、上の「課題 × 条件」で確かめます(下の手順)。
3. **普段の作業全体で役に立っているか**: この道具では分かりません。

| 普段のログで分かること(相関まで) | 割り当てて確かめる場所 |
|---|---|
| **skill**: 改善点の「skill の傾向」(呼んだセッションと呼ばなかったセッションの失敗率)と、失敗の台帳の集計のページ(skill ごとの失敗) | 課題 × 条件と、その中の利用の確認 |
| **llm-wiki**: 件数まで(集計明細・プロジェクト別・改善点の「llm-wiki の利用」)。参照あり / なしの率は並べません。ページごとの参照率と、LLM の見立ての役立った率は改善点の「llm-wiki のページごとの参照率と役立った率」(どのページが読まれ、読んだ後に使われたと見立てられたか。wiki が結果を変えたかは分かりません) | 同上 |
| **MCP サーバー**: 利用ランキングの回数と、失敗の台帳の集計のページ。使った / 使わなかったセッションを並べる場所はありません | 同上 |
| **推論強度**: 「モデルと推論強度の効果」は、観察したセッションを強度ごとに按分したもので、題の「効果」は相関の意味です。「比べる」の強度どうしも同じで、週ごとに強度を割り当てて使ったときだけ右の列に入ります | 同上(利用の確認では推論強度を選べないので、割り当てどおりかは詳細ページの実行の性質で見ます) |

普段のログの差は、何をしたセッションかの違いが混ざるので、原因は分かりません。条件で結果が変わるかを確かめるときは、次の手順で、条件だけを変えた実行を並べます。どれも今ある画面の部品だけで行えます。

1. 先に、見る指標(例: 最後に全部通ったか)・比べる 2 つの条件・回数を決めて書き留めます(結果を見てから選び直さないため)。
2. タスクタグを `課題__0-plain` と `課題__wiki` のように付けます(回ごとに分けるなら `課題__wiki__1`。名前の決まりは上の「課題 × 条件」)。
3. 最初の依頼文を一字一句同じにし、途中で追加の依頼はしません。
4. モデル・推論強度・指示文・作業ツリー(同じコミットから始める)をそろえ、条件を交互に実行します(片方をまとめて先に流すと、その間に変わったものが条件の差に混ざります)。
5. 実験の間は vault を変えず、取り込みの skill を呼びません(wiki の中身が回ごとに変わるため)。
6. 「課題 × 条件」の利用の確認で確かめるもの(llm-wiki など)を選び、使うはずの条件に印を付けて、割り当てどおりだったか(素の条件で wiki が参照されていないか、wiki の条件で参照されているか)を見ます。食い違ったセッションがあれば、その数も結果と一緒に書き留めます。
7. テストの合格は「課題 × 条件」の表(最後に全部通った・最初に全部通るまで)で見比べます。この表に差と差の幅は出ません。テストの結果を出すには、テストの実行ファイルが印つきの行を書く必要があります([outputs.md の「テストの結果」](outputs.md#テストの結果印つきの-1-行-json))。

最初は 1 つの課題で両方の条件を 1 回ずつ流し、利用の確認が期待どおりに出るか(wiki の条件のセッションだけが「使った」に入るか)を確かめてから回数を増やすことを勧めます。条件ごとに 5 回ずつ流して分かるのは、片方がほぼ全部通り、もう片方がほぼ全部落ちるほどの違いだけです。

- **言えること**(範囲をつけて): 「課題 A では、同じ依頼文・同じモデルと推論強度・この時点の vault で、wiki ありの 5 回は 5 回とも最後に全部通り、素の 5 回は 1 回だけ通った」。「この期間の普段のログでは、wiki を参照したセッションが N 件あった」。
- **言えないこと**: 「wiki を入れる前と後の期間を比べた差を、wiki のおかげとする」(その間に変わったもの、たとえば作業の種類やモデルが混ざります)。「選んだ課題で通ったので、普段の作業でも役に立っている」。「改善点の skill の傾向で、呼んだセッションの失敗率が低いので、skill が効いている」。

## セッション詳細ページ

- **中身**: 時系列、依頼ごとの経過(下記)、ツール内訳と成功・失敗・拒否、実行の性質(モード・推論強度・起点・ツール定義・モデル別の待ち時間・ツールの所要時間・摩擦の詳細・失敗したサブエージェントの理由・todo)、skills(呼んだ側)/ agents / hooks、指示文と skill(下記)、llm-wiki の参照(vault に触れたセッションでは、索引・個別ページ・wiki の skill・書き込み・その他の回数と、「このセッションの扱い: 参照した」か「書き込みだけ(参照したセッションには数えません)」の 1 行。vault を指定せずに集計したレポートでは、参照が無いとは書かずに数えていない理由を出します)、摩擦、変更行数、変更したファイル。セッション ID は表題の下の印の列の末尾にあります。

- **テストの推移**(テストの実行ファイルが印つきの行 `ATLAS_TEST_RESULT` を書いたセッションだけ。書き方は [outputs.md の「テストの結果」](outputs.md#テストの結果印つきの-1-行-json)): 上の欄に、結果(全部通った / 未達 / 通った後に不合格)、テストの実行の数、最初に全部通った実行(何回目か。その依頼の番号)、通るまでの実働と AI 使用量。下の表は実行 1 回 1 行で、完了の時刻・依頼の番号・ツール・合格 / 結果の数・落ちたテストの名前・まだ通っていないテストの数(0 なら「全部通った」)・件数の合計(テストの実行ファイルが書いた名前ごと。8 種類まで)・そこまでの実働と AI 使用量の累計。「全部通った」は、これまでに出たテストごとのいちばん新しい結果がすべて合格のことです。AI 使用量は、リクエストごとの記録が無いセッションでは「記録なし」です。読めなかった印の行などがあれば、表の下に件数を出します。
- **失敗と拒否(1 件ごと)**(失敗の台帳に行があるときだけ): ツールの失敗と拒否 1 件 1 行の表。依頼の番号(最初の依頼より前は「—」)、開始時刻、ツール(MCP サーバーとサブエージェントの名前の印つき)、種類と要因、エラー文(400 字まで)、引数(200 字まで)、その後(次に呼んだツールとその結果。同じ引数なら「同じ引数で呼び直し」の印)。表の下に、失敗・拒否のあったサブエージェントへの依頼文を 1 回ずつ載せます。以前の版で集計した記録にはこの節が無く、失敗があるときは「依頼ごとの経過」の下に断りが出ます(集計し直すと入ります)。
- **指示文と skill の表**: 注入された指示ファイルと、そのセッションで使えた skill の一覧に呼んだ回数を添えた表。呼んだものが先、一覧に無い skill を呼んだときは「一覧に無し」。使えた skill の一覧はシステムメッセージの `<available_skills>` から読むので、Copilot CLI 1.0.77 より前の版や `copilot -p` のセッションでは「一覧はこのセッションの記録にありません」と出て、呼んだものだけになります。置き場所はログの値で、user / project / builtin は「ユーザー / プロジェクト / 組み込み」、それ以外(`custom` など)はそのまま。
- **目次**: 幅 768px 以上では左のサイドバーに「レポート(セッション一覧)に戻る」(レポートから開いたときはブラウザの「戻る」と同じ動きで、絞り込みを保ったまま戻ります。詳細ページを直接開いたときや新しいタブではレポートの先頭を開きます)、節の目次(概要・トークン内訳・…・ログの状態。読んでいる節に印)、「用語の説明」、配色の切り替えが上から並びます。記録を作ってあれば(`atlas.bat`・`all`・`export`)「記録の .md をそのまま開く ↗」(別のウィンドウで開きます。整形して読むなら表題の下の「記録を読む」)「記録を .md で保存」も入ります(素の `build` では出ません)。「このセッションの指示文と skill」は、指示文と skill のページをそのセッションで使われた版だけに絞って開きます。768px 未満では上部の帯に戻る・リンク・配色、その下に固定した目次の行(横に流れ、現在地に印)が出ます。
- 詳細の「変更したファイル」は、変更・作成・削除に分けて載せます。相対パスは作業フォルダ基準の絶対パスにそろえ、同じファイルは 1 回だけ載せます(Windows では大文字小文字を区別しない)。途中で削除したファイルは、終了時の記録(`codeChanges.filesModified`)に残っていても「削除」のままにします。Copilot 自身のセッション用ファイル(`~/.copilot/session-state/` 配下の plan.md など)は一覧から外し、件数だけ書きます。
- 応答の件数には、サブエージェントの応答を含めません。

## タスクタグとセッションの選択

タスクタグは、セッションに付ける名前です(例: `Player-Weapon`)。1 つのセッションに複数付けられます。名前を `課題__条件` か `課題__条件__番号` にすると、レポートの「課題 × 条件」の節で、課題と条件ごとに並びます(上の「[画面の見方](#画面の見方)」)。保存先とコマンドでは「グループ」と呼びます(`atlas-notes/groups.json`、`atlas group …`)。

一覧で選んだセッションだけを集計したり、タスクタグを付けて残したりできます。

### 選んだセッションだけ集計する

セッション一覧の左端の欄にチェックを付け(見出し行のチェックでそのページの 50 件をまとめて)、一覧の上の「選んだ N 件だけ集計」を押すと、その N 件だけで全体サマリ・要点・内訳・一覧が集計し直されます(他の条件とは AND。サイドバーの条件の数にも 1 つとして数えます)。サイドバー(狭い幅では目次行の「タスクタグ」)には「選んだ N 件」の印が出て、「すべて」に戻すか「解除」で外れます。チェックは画面の中だけのもので保存されません(選んだ id は URL の `#ids=…` に残るので、再読み込み・ブックマーク・共有では保てます)。「選択を解除」はチェックを全部外し、選択で集計中ならその条件も外します。

### タスクタグで絞り込む

- タスクタグの居場所はサイドバーの「タスクタグ」の群です(幅 768px 未満では上部の固定した目次行の「タスクタグ N」を押して開く一覧。外を押すか Esc で閉じます)。「すべて」と各タスクタグ(名前・件数・説明)が並び、押すとそのタスクタグで絞り込まれ、現在のタスクタグに印が付きます。外すのは「すべて」か、本文の見出しの「絞り込みを外す」です。ここは切り替えだけで、編集の操作は置いていません。
- タスクタグが無いときは「タスクタグはまだありません。一覧でセッションを選ぶと作れます」と出ます。
- タスクタグで絞り込んでいる間は、本文の先頭(絞り込みの行の下)にタスクタグの見出し(名前・件数・説明)と「絞り込みを外す」が出ます。記録に無い id が混じっていれば件数は「m / n」です。
- セッションに付いているタスクタグは、一覧の行の題名の下(「タスクタグ: 名前、名前」)と、`atlas.bat` から開いた詳細ページの表題の下(名前を押すとそのタスクタグで絞り込んだレポートに移ります)に出ます。
- 詳細ページでは、そのセッションのタスクタグを付け外しできます(`atlas.bat` から開いたときだけ)。「×」で外し(タグは 0 件でも残ります)、入力欄にタグの名前を入れて「付ける」で付けます(今あるタグは候補に出ます。無い名前なら新しく作ります)。

### タスクタグを作る・直す(`atlas.bat` から開いたときだけ)

- **作る・足す**: セッション一覧でチェックして、一覧の上の「タスクタグを付ける ▾」を開きます。既存のタスクタグを選べばその場で追加します(重複は足さず「N 件を「名前」に追加しました。チェックは外しました」と出ます。絞り込みは変わりません)。末尾の「新しいタスクタグ…」で名前と説明を入れて作成すると、そのタスクタグで絞り込んだ状態になります。
- タスクタグや「選んだ N 件」の絞り込みを外す(「すべて」「解除」)とチェックも外れるので、続けて別のタスクタグを作っても前のセッションは混ざりません。
- **外す**: タスクタグで絞り込み中は「このタスクタグを外す」でチェックした分を外せます(0 件になってもタスクタグは残ります)。
- **表と記録を書き出す**: 見出しの「表と記録を書き出す」で、そのタスクタグのセッションだけの表(依頼ごとの `turns.csv`・セッションごとの `sessions.csv`)・集計(`metrics.json`)・セッション記録(`records/`)を `out\groups\<タスクタグ名>\` に書き出します(いつものレポートは変わりません。前回の書き出しは消してから書きます)。書き出した場所が見出しの下に出て、「場所をコピー」で写せます。CSV は Excel でそのまま開けます(UTF-8、BOM 付き)。依頼文や記録にはパスや本文がそのまま入るので、共有する前に中身を確かめてください。CLI では `atlas group export <名前>` です。
- **アップロード**: タスク(タスクタグ)ごとのセッションの生ログを、決めておいた場所へ写します。見出しの下に「アップロード先 `E:\dev\atlas-logs\Player-Weapon\`」のように写す先が出ていて、見出しの「アップロード」を押すと、タスクタグのセッションごとに `<アップロード先>\<タスクタグ名>\<セッション ID>\` のフォルダを作って写します。
  - 写すもの: Copilot のセッションのフォルダ(`events.jsonl`・`workspace.yaml`・`session.db`・`plan.md`・`checkpoints\`・`files\` など)と、`session-store.db` と `data.db`(デスクトップアプリ。資格情報を含まない許可リストの列だけ)のそのセッションの行(`atlas-session-store.json`。トークン数・題名・モデルなどは DB にしか無いことがあるため)。元の `~\.copilot` ではなく、前回の集計(`atlas.bat` の起動時か「集計し直す」)で複製したものを写します。結果の文に、いつの集計の時点のログかが出ます。新しい作業を含めたいときは、先に「集計し直す」を押してください。
  - タスクタグの説明とメモも残します。タスクタグのフォルダの `README.md` に、タスクタグ名・タスクタグの説明・写した日時・何時点の集計か・今回写したセッションの一覧(題名・タスクタグ・最終更新・メモの有無)・タスクタグごとの一覧・集計し直すコマンドを書きます(写すたびに書き直します)。プログラムや AI が読むための索引 `atlas-index.json`(セッションごとのタスクタグ・題名・作成と最終更新の日時・プロジェクト)も同じフォルダに書き、各セッションのフォルダにはそのセッションの分を `atlas-session.json` で添えます(タグの無いセッションは空の一覧。プロジェクト名とその決め方 `projectSource` も入れ、集計し直すときはここからプロジェクト名を取ります)。セッションのメモは、そのセッションのフォルダに `atlas-memo.md`、画像は `atlas-memo\` に入れます(本文の画像の参照も `atlas-memo/…` に直すので、Markdown のビューアでそのまま読めます)。集計し直した画面にはメモは出ないので、ファイルを開いて読みます。
  - 同じセッションのフォルダは丸ごと置き換えます(メモを消してから写し直すと、前に添えたメモも消えます)。ただし、前に写したときから中身が変わっていないセッションは写し直さず、確認に「前に写したときから変わっていない N 件は写しません」と出します(タスクタグや題名だけが変わったときは、`atlas-session.json` と `README.md` だけを書き直します。README の「[2 回目からは変わったものだけを送る](../README.md#2-回目からは変わったものだけを送る)」)。送った人がインストールしている skill・プラグインの名前は、タスクタグのフォルダの `atlas-installed.json` に添えます(集計し直すと「インストール済みで未使用の skill」に使います)。前のフォルダの中のファイルが開かれていて置き換えられないときは、前のフォルダをそのまま残して止まります(開いている画面を閉じてからもう一度押してください)。
  - 写さずに止まるとき: タスクタグのセッションが前回の集計に 1 件も無いとき(フォルダも README も作りません)、フォルダ名に直すと同じになる別のタスクタグがあるとき(`Player/Weapon` と `player_weapon` など。どちらかの名前を変えてください)。タスクタグから外したセッションや、ほかの回・ほかの PC から写したセッションのフォルダには触れません(消しません)。前回の集計に無いセッションは写さず、件数を結果の文に出します。
  - 写し終えると、写した先と「エクスプローラーで開く」が出ます。
  - **アップロード先を決める・変える**: 見出しの下の「場所を決める…」/「場所を変える…」で記入欄が開きます。「エクスプローラーで選ぶ…」でフォルダを選ぶ画面が出るので、基底のフォルダ(例: `E:\dev\atlas-logs`)を選びます(画面がブラウザの後ろに隠れたときはタスクバーを見てください)。パスを入力して「入力したパスにする」でも決められます。決めた場所は `atlas.config.json` の `uploadRoot` に書かれ、すべてのタスクタグで共通です(`setup.bat` でも決められます)。基底のフォルダが無いときは写さずに止まります(ネットワークドライブの切断などで、思わぬ場所に作らないため)。先が決まっていないまま「アップロード」を押すと記入欄が開き、決めるとそのまま写します。
  - タスクタグ名にフォルダ名に使えない文字(`/ \ : * ? " < > |`)があれば `_` にします(`Player/Weapon` → `Player_Weapon`)。見出しの下の表示がそのまま写す先です。
  - 写したタスクタグのフォルダは、そのまま集計できます: `bin\atlas.exe all --home "E:\dev\atlas-logs\Player-Weapon" --out out-player-weapon`([cli.md の「snapshot と extract が読むもの」](cli.md#snapshot-と-extract-が読むもの))。出力先の `sessions\<セッション ID>.md` に、セッションごとの読みやすい記録もできます(記録は生ログから作れるので、送るものには含めません。送り先の容量を使わないため)。
    - 出力先(`--out`)は、集計するフォルダごとに分けてください。いつもの `out` や、別のタスクタグのフォルダを集計した出力先を指定すると、セッションが混ざるので書かずに止まります。
    - `--home` に指定するのはタスクタグのフォルダか、そのフォルダが並ぶ場所(`E:\dev\atlas-logs` など。下のフォルダをまとめて集計します)です。
    - プロジェクト名は、送った PC で決めた名前のままです(読む PC に同じ作業フォルダが無くても変わりません)。
  - 生ログには依頼文・応答・ツールの結果・ファイルのパスがそのまま入ります。写す先を見られる人を確かめてから写してください。
  - 写す前に、合計の大きさと秘密らしい文字列(GitHub・OpenAI / Anthropic・AWS・Slack・Google のキーやトークン、秘密鍵、JWT、Bearer トークンの形)を調べます。写す前に毎回、見出しの中に確認が出ます(送り先・セッション数・大きさ・置き換える件数。100 MB を超えるときは大きいフォルダも)。「写す」で写し、「やめる」か Esc でやめます。「送り先を変える…」でエクスプローラーから選び直せます。秘密らしい文字列が見つかったときは、件数・種類・見つかったファイルも出し、焦点は「やめる」に置きます(ボタンは「それでも写す」)。偽陽性もありえます。本物の鍵なら、写すかどうかに関わらず作り直してください。バイナリのファイル(session.db・画像など)は中身を調べません。
  - 写している間は、見出しの下に写した量(セッション数とバイト数)が出ます。
  - 写している途中に別のタスクタグへ切り替えても、進み具合と結果は写しているタグの見出しにだけ出ます(ほかのタグの見出しには「「A」をアップロードしています」と出て、終わるまでほかのタグは写せません)。ほかのタグを見ている間に終わったときは、その見出しに「「A」のアップロードが終わりました」(失敗なら「アップロードできませんでした」と理由)とだけ出し(画面の読み上げでも読みます)、写したタグへ戻ると結果を出します。「すべて」へ外して戻ったときも同じです。そのとき見ているタグ自身の直近の結果(ほかのページで写したもの)も、写し終えた時点で出します(編集などの欄を開いているときは出さず、次に開いたときに出します)。知らせは、そのタグで写し始めると消えます。確かめている間・書き出している間に別のタグへ切り替えたときは、前のタグの確認や書き出しの結果を出しません。写している途中に別のページへ移って戻ったときは、続いていれば進み具合を、終わっていれば直近の結果(成功なら写した件数、失敗なら理由。10 分以内のもの)を一度だけ出します。
  - 確かめてから「写す」を押すまでの間に、集計し直してログが変わったときは、写さずに理由を出します。もう一度「アップロード」を押して確かめてください(確かめていない中身を写さないため)。
  - 送り先のフォルダに、フォルダ名が同じになる別のタスクタグやプロジェクトがすでに送られているときは、混ざるので写しません(タグの名前か送り先を変えてください)。
  - CLI では `atlas group upload <名前> [--to <基底フォルダ>] [--force]` です。写す前に大きさを出し、秘密らしい文字列が見つかったら写さずに止まります(`--force` で写します)。
- **名前・説明の変更と削除**: 見出しの「編集」で名前と説明を 1 つの欄で直せます。削除は編集欄の右端の「このタスクタグを削除…」から確認を 1 回挟んで行います(タスクタグだけが消え、セッションと記録は残ります)。Esc で 1 段ずつ戻ります(確認 → 編集 → 見出し)。
- これらの操作は `atlas.bat`(= `atlas serve`)で開いたときだけ使えます。`out\atlas.html` を直接開いたときはタスクタグを選んで絞り込むことだけができ、「このファイルは閲覧用です」と出ます。サーバが止まると画面の上に「サーバが止まっています」の帯が出て、編集の操作だけが消えます(閲覧はそのまま)。
- コマンドでは `bin\atlas.exe group add <名前> <id...>` でも追記できます([cli.md](cli.md#コマンド))。

### ファイルと共有

- ファイルは `atlas-notes/groups.json`(リポジトリ直下。`--notes-dir` で変更可)で、形式は `{ "version": 1, "groups": [ { "name": "<名前>", "note": "<任意の説明>", "ids": ["<session id>", …] } ] }`、名前は一意です。手で書いてもよく、壊れていても `build` / `export` / `judge` は止まらず、無視した箇所を全体サマリの集計明細と脚注に出します(壊れている間は画面からも書き換えません)。
- `atlas-notes/` は `.gitignore` に入っているので Git では管理されません。消すと元に戻せないので、残したいときは自分でバックアップしてください。
- タスクタグの条件は URL の `#` に名前と id の両方で残るので、ブックマークや共有で保てます(相手にその名前のタスクタグが無ければ id だけで「選んだ N 件」として絞り込まれます)。
- CLI では `--group <名前>` で同じ絞り込みができ、`--session <id,...>` で特定のセッションだけを対象にできます(`build` / `export` / `metrics` / `bundle` に効きます)。

## セッションのメモ

セッションごとに、自分用のメモ(Markdown と画像)を残せます。数字だけでは残らない「なぜこのセッションが良かった / 悪かったか」を書くためのものです。

**書き方**: `atlas.bat`(または `atlas serve`)から開いた画面で、セッションの詳細ページの「メモを書く」を押します。

- 保存は「保存」か Ctrl+S。本文を空にして保存すると、確認のうえメモを削除します(画像は残ります)。
- 画像は貼り付け、ドロップ、または「画像を追加」で入れられます(png / jpeg / gif / webp、1 枚 10MB まで。svg は不可。手で置いた画像も 10MB を超えると表示しません)。
- 開いている間に Obsidian や `atlas memo` で同じメモが書き換えられていたら、上書きせずに知らせます。入力は残るので「上書きして保存」を選べます。

**見え方**: メモは詳細ページの先頭に出ます。一覧ではセッション名の下に先頭の 1 行が出て、「その他の条件」の「メモのあるセッションだけ」で絞り込めます。`atlas.html` に埋め込むのは先頭の 1 行だけで、全文は詳細ページにあります。

**置き場**: `atlas-notes/memos/<id>.md`(素の Markdown)と、画像の `atlas-notes/memos/<id>/`。`--notes-dir` で変えられます。本文からは `![説明](<id>/<ファイル名>)` で参照するので、Obsidian や VS Code でもそのまま読め、手で置いたファイルも同じように扱います。`atlas-notes/` は Git の対象外なので、消すと元に戻せません。バックアップが必要なら自分で管理してください。

**制限**:

- `file://` で開いた画面は閲覧だけで、メモは前回の build の時点の内容です。atlas.bat から開いた画面は常に最新です。
- 生の HTML は文字として表示します。リンクは http / https / mailto だけが有効で、外部の画像は読み込みません(リンクとして出します)。
- メモは評価バンドル(`bundle` / `judge`)、セッション記録、全文記録には入りません(自由記述を LLM に流さないためです)。レポートには入ります(`atlas.html` に先頭の 1 行、詳細ページに全文と画像)。レポートを人に渡すと、メモも一緒に渡ります。

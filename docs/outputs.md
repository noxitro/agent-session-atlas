# 出力ファイル

[README](../README.md) に戻る。コマンドの一覧は [cli.md](cli.md) にあります。

## セッション記録(Markdown)

セッションの経過を 1 ファイルの Markdown にして、LLM に渡して振り返ったり、自分で経過を読んだりするための出力です。依頼文や応答がそのまま入るので、人に渡すなら `--anonymize` で作り、中身を確かめてからにしてください。集計と同じスナップショットから作り、LLM は呼びません。

```
npm run atlas -- export                          # build と同じ絞り込みで、全セッションの .md を out/sessions/ に書く
npm run atlas -- export --since 2026-10-01       # 期間で絞る(--project / --client / --model / --branch も同じ)
npm run atlas -- export --tool-output all        # 成功したツールの結果も入れる(容量が数倍になる)
npm run atlas -- export --anonymize              # 伏せ字版(下の注意を読んでください)
```

`atlas.bat`(`all`)は既定の中身(`--tool-output fail`、上限 20,000 字)で記録も作ります。`atlas.bat` から開いた詳細ページの「記録を読む」で、その場で読めます([screen.md の「画面からの操作」](screen.md#画面からの操作))。中身を変えたいとき(`--tool-output all`、`--max-chars`、伏せ字版の記録 `--anonymize`)は上のコマンドで作り直します。

記録 1 件(`out/sessions/<セッション ID>.md`)の中身:

| 節 | 内容 |
|---|---|
| 概要 | ID・プロジェクト・クライアント・リポジトリ・作業フォルダ・Copilot の版・開始と所要時間・依頼と応答の数・トークンと AIU・ツール呼び出し(失敗・拒否)・摩擦・変更行数 |
| 役 × モデルの消費 | 本体とサブエージェント(名前)× モデルごとのリクエスト数・入力・出力・キャッシュ読取・AIU と、待ち時間(最初のトークンまで / 全体)の中央値と p90。`session-store.db` と `usage_record` のリクエスト単位の明細から |
| ツールの内訳 | ツール別の回数・失敗・拒否 |
| 経過 | 開始からの相対時刻つきの時系列。依頼(本文、モード)、応答(本文、モデル)、ツール呼び出し 1 回 1 行(名前・引数の要約・成否・所要時間・失敗の理由)、サブエージェントの開始と完了(`[agent:名前]` を付けた中の発言とツール)、compaction(要約は折りたたみ)、権限確認、エラー、中断、モード・モデルの変更、終了時の変更行数。5 分以上の空白は「待ち」。依頼ごとに本体の消費(リクエスト数・トークン・AIU・所要)を 1 行 |
| 変更したファイル | 変更・作成・削除の一覧 |
| 秘密情報の検査 | 伏せた件数(下記) |
| 分析の観点 | LLM に渡して振り返るときの定型の観点(時間とトークンの内訳、手戻り、失敗と回復、compaction、委譲、依頼の質) |

- **既定ではツールの結果は失敗したときだけ入れます**(`--tool-output fail`)。成功した結果はログの容量の大半を占めるためで、必要なら `--tool-output all`。内部ツール(`report_intent`)は書きません。
- 長い本文は上限(`--max-chars`、既定 20,000 字。ツールの結果は 4,000 字)で中略し、中略した箇所に字数を書きます。LLM に渡す前に全体の長さを確認してください(長いセッションは 1 件で数十万字になります)。
- **秘密情報**: API キーやトークンらしい文字列(GitHub / OpenAI・Anthropic / AWS / Slack / Google のキー、秘密鍵、JWT、Bearer)は形式で見つけて `[伏せました: 種類]` に置き換え、件数を記録の末尾と `export` のログに出します。形式で探しているだけなので偽陽性・見逃しがあります。本物が見つかったら元の記録(`~/.copilot`)にも残っているので鍵を作り直してください。共有する前に中身は必ず確認してください。
- **伏せ字モード(`--anonymize`)の記録**は、プロジェクト名・パス・リポジトリ名・ブランチを仮名に、絶対パスを `<path>` に置き換え、ファイル一覧を出しません。ただし依頼文や応答などの自由記述は機械的に置き換えるだけなので、本文中の相対パス・ファイル名・人名などは残りえます。HTML の伏せ字版(本文を出さない)より弱い保証です。記録の先頭にもその注意を書きます。
- スナップショットに `events.jsonl` が無いセッション(`session-store.db` にだけあるもの、`--since` で複製対象外だったもの)は、`sessions.json` に残る最初の依頼と最後の応答だけの記録になり、その旨を書きます。
- `export` は `build` を含むので、レポートと詳細ページも作り直されます。逆に素の `build` を実行すると `.md` は消え、詳細ページのリンクも消えます(フィルタで減ったセッションの古い記録を残さないため)。`all`(`atlas.bat`・`npm run atlas`・画面の「集計し直す」)と判定(画面の「工数を判定する」・`npm run atlas:judge`)は記録も作るので消えません。伏せ字版(`--anonymize`)の `all` は記録を作りません。
- 同じ目的の既存ツールとの関係: agent-toolkit の `copilot-session-export`(アプリの中から `/export` `/export-usage` でその場で書き出す)と `copilot-usage-export`(PowerShell だけで動く日次バッチ)は、1 セッションをその場で・自動で書き出すためのものです。atlas の `export` は、集計と同じ絞り込みと伏せ字でまとめて出すためのもので、節の構成は揃えていますが同じファイルにはなりません。

## 表(CSV)

依頼(ターン)ごと・セッションごとの表を、表計算ソフトで開ける CSV(UTF-8、BOM 付き、行末 CRLF)で書きます。集計(`metrics`、`atlas.bat`・`all` を含む)のたびに `out/tables/` に、グループの書き出し(画面のグループの見出しの「書き出す」、`atlas group export <名前>`)では `out/groups/<名前>/` に書きます。空のセッションは入れません。依頼文の先頭(200 字)とパスがそのまま入るので、共有する前に中身を確かめてください。`=` `+` `-` `@` で始まる文字列のセルには、表計算ソフトが式として読まないよう先頭に `'` を足します。

| ファイル | 1 行 | 主な列 |
|---|---|---|
| `turns.csv` | 依頼 1 件 | セッション ID・名前・プロジェクト、依頼番号・開始、依頼の種類・工程・次の依頼の種類、「次の依頼で直し・差し戻し」と「詰まり」(1 / 0)、実働と所要(秒)、ツールの数と種類別の回数(読む・編集・検証・git・シェル・計画・Web・委任・その他)、ツールの失敗・拒否・失敗の連続、編集・再編集(前の依頼で編集したファイル)・重ね編集(同じ依頼の中)、中断・エラー(うち利用上限)・サブエージェントの失敗・文脈圧縮・ask_user、入力 / 出力トークンと AIU(リクエストの記録の時刻で依頼に振り分けたもの。最初の依頼より前と 201 依頼目以降は含めない)、依頼文の先頭 |
| `sessions.csv` | セッション 1 件 | セッション ID・名前・プロジェクト・クライアント・ブランチ、開始・終了、所要と実働(分)、依頼の数と依頼ごとの記録の数、詰まりのあった依頼・次の依頼で直し・差し戻しの数、応答、モデル、トークン・AIU・premium request、ツール・摩擦の内訳、再編集したファイル・余分な編集・失敗の連続、追加 / 削除行、推定人手工数(判定済みのものだけ)、最初の依頼の先頭 |

工程と依頼の種類の決め方は [screen.md の「工程と詰まり」](screen.md#画面の見方) と同じです(LLM は使いません)。1 セッションの先頭 200 依頼までを載せます。グループの書き出しには、ほかに `metrics.json`(そのグループだけの集計。`turns` に工程別・依頼の種類別の集計)、`records/`(セッション記録の `.md`。作ってあるものだけ)、`README.md`(書き出した日時と件数)が入ります。

## 解析用の完全出力

出力データだけでローカルと同等の解析ができるようにするための出力です。**外部に出さない前提**で、原本の文字列をそのまま含みます。

```
npm run atlas -- export --full                   # snapshot / extract 済みの状態から、全件の全文記録と coverage.json を書く
npm run atlas -- snapshot --snapshot-all         # rewind-snapshots / 一覧に無いフォルダ / logs/ も写す
```

1 セッションだけなら、`atlas.bat` から開いた詳細ページの「全文を作って読む」で、そのセッションの `out/full/<id>.md`(と `out/full/assets/<id>/`)だけを作ってその場で読めます。このときは `atlas.html`・詳細ページ・他のセッションの全文・`coverage.json` は作り直しません(網羅の検査は全件の `export --full` だけが書きます)。

| 出力 | 中身 |
|---|---|
| `out/snapshot/` | 原本の複製(スナップショット)。セッションフォルダの `plan.md` / `checkpoints/` / `files/` / `rewind-file-snapshots/` / `policies/`、直下の `plans/` / `attachments/` / `chats/` の `*.md` も写す。写さなかったもの(`rewind-snapshots/` は 1 セッションで数十 MB、一覧に無い名前のフォルダ、`logs/`、`repos/`、`chats/` の `*.md` 以外)は `snapshot-manifest.json` の `extras.skipped` に名前と容量を残し、`--snapshot-all` で写す(`repos/` と `chats/` の `*.md` 以外は写さない) |
| `out/snapshot/desktop.json` | デスクトップアプリの `data.db` から、名前で固定した許可リストの列だけを読んだもの(下記) |
| `out/full/<id>.md` | 全文記録。依頼、応答、reasoningText、ツールの引数と結果(成功含む)、hook の入出力、system.message、compaction の要約、skill の本文、plan.md、チェックポイント、`files/` などの一覧、data.db の列を時系列で、上限なしで書く。除くのは暗号化・不透明データ(`encryptedContent`、`reasoningOpaque`、`reasoningBlocks` の中の base64 らしい値)と base64 の本体(画像などは `out/full/assets/<id>/` に書き出してリンク)だけで、除いた箇所に種別とバイト数を書く。hook の入力に入っているツールの結果がツールの結果と同一なら参照にする。API キーらしい文字列は形式検査で伏せて件数を末尾に書く |
| `out/coverage.json` | 網羅の検査。元データの event type × data のキーごとに件数・バイト数・扱い(`full` = 全文に出した / `ref` = 参照にした / `excluded` = 理由付きで除外)。扱いの表(`packages/report/src/coverage.ts`)に無いキーは `unclassified` として数え、`export` のログと全文記録の末尾にも出す(0 件なら欠損なし)。`data.db` の列も同じ表で(許可 = `full`、許可外 = `unclassified`、開かない表 = `excluded`) |
| `out/instructions.html` と `out/library/` | 指示文(AGENTS.md / CLAUDE.md / copilot-instructions.md 等の注入)と skill の本文を、重複なしで版(内容のハッシュ)ごとに置いたもの。見出しごとの版一覧、本文、使われたセッション、使われた期間・プロジェクト、前の版との差分。「版 N」は初回の利用日の順の通し番号(改善点の「版 N」と同じ)で、別のリポジトリの同じ見出しのファイルも同じ項目に入るため、番号が大きい版が今の版とは限らない。そのため最後に使われた版に印を付けて開き、項目の見出しにプロジェクトごとの最後の版を、期間が重なる版に「並行して使用」を出す。差分は同じプロジェクトで前に使われた版と比べる(無ければ 1 つ前の版と比べ、そう書く)。詳細ページの指示ファイルの行と skill からリンクし、サイドバーの付録にも入る。`instructions.html#session=<セッション ID>` で開くと(詳細ページの「このセッションの指示文と skill」)、そのセッションで使われた版だけを残し、上の帯に件数と「すべて表示」「セッションの詳細に戻る」が出る(使えただけで呼ばなかった skill は本文が無いので、詳細ページの表にだけ出る)。`--full` でなくても `export` で作る。伏せ字版では作らない |

`--full` を付けない `export` や素の `build` は、前回の `out/full/` と `out/coverage.json`(と `instructions.html` / `out/library/`)を消しません(ユーザーの生成物を黙って消さないため。残っているときはログに生成日時を出します)。古い全文記録が残っている点に注意し、消したいときはフォルダを手で消すか、`--anonymize` で作ります(伏せ字版の `out/` には残しません)。

**data.db(デスクトップアプリ)**: 資格情報の列を含むため、次の形で読みます。ファイルは複製せず、`file:///…/data.db?immutable=1` の読み取り専用で開きます(`-shm` / `-wal` に触れません)。読むのは名前で固定した許可リストの列だけで(`sessions` の非資格情報の列、`session_context_usage`、`session_checkpoints`、`activity_items`、`projects` と `workspaces` の非資格情報の列)、`select *` はせず、`accounts` / `settings` / `app_state` / `model_providers` / `remote_environments` は開きません。許可リストに無い列は名前だけ数えます(値は読みません)。immutable で開くため `-wal` の未反映分は読めず、最近の更新が欠けることがあります(`desktop.json` と全文記録に WAL の大きさと更新日時を書きます)。結果は `sessions.json` の `desktop` 欄、全文記録、詳細ページの「デスクトップアプリの記録(data.db)」に出ます。

## 改善点(規則による分析)

レポートの「改善点」の節(目次「概況」の「要点」の次)と、全件のページ `out/insights.html`、機械可読の `out/insights.json` です。LLM は使わず、決まった規則で集計します。**分かるのは相関まで**なので画面でも「傾向」と書いています。指示文の効果は直接は測れません(同じ版でも依頼が違う)。率は 5 セッション以上のものだけ出し、未満は「—」です(セッション数の列で分かります)。閾値は `packages/report/src/lib/insights.ts` の `THRESHOLDS` にまとめ、根拠は `docs/PLAN.md` の Phase 12 にあります。

レポートの節では、箱を計算の対象で 2 つの群に分けて並べます。上の群「絞り込みに従う」(指示文の傾向・skill の傾向・止まっている箇所)は上の絞り込みの対象だけで計算し直し、下の群「全記録で計算」(長いのに注入が少ない指示文・スキル化の候補)は絞り込んでも変わりません。1 つの箱に両方を混ぜません。

| 箱 | 中身 | 計算の場所 |
|---|---|---|
| 指示文の傾向 | 指示文(AGENTS.md / CLAUDE.md 等)の版(内容のハッシュ)ごとの字数・注入セッション数・ツールの失敗率・手戻り率(同じファイルを 2 回以上編集したセッションの割合)・compaction と出力トークン / セッション。「版を変えた前後で悪化」(前後とも 5 セッション以上で失敗率か手戻り率が 10 ポイント以上悪化)を挙げ、前後比較は判定できた組と判定できない組の数を常に出す。版の名前から `instructions.html` の版へ移動できる(`export` 後) | レポート内で絞り込みに従って再計算 |
| skill の傾向 | skill ごとの呼び出し(利用者 / エージェント)、本文の字数、呼んだセッションと呼ばなかったセッションの失敗率(5 セッション以上で呼ばれた skill が無ければ列を出さない)、インストール済みで未使用(今の設定で無効なものに印) | 同上 |
| 止まっている箇所 | 待ち時間(TTFT の中央値 20 秒以上)、失敗の連続(3 回以上)、余分な編集の多さ(同じファイルの 2 回目以降の編集の全ファイルの合計が 3 回以上)、権限確認の多さ(10 件以上)、compaction(3 回以上)のどれかに当たるセッション(理由の数の多い順、同数なら余分な編集・失敗の連続の多い順)と、プロジェクト別の該当数(`insights.html` は理由の内訳付きの表) | 同上 |
| 長いのに注入が少ない指示文 | 字数が全版の上位 25% で、注入されたのが 3 セッション未満の版(項目ごとに今の版=最後に読み込まれた版だけ、最後の読み込み日を添える)。全体での希少さの話なので絞り込みに従わない | レポート内で全記録から計算 |
| スキル化の候補 | (a) 似た依頼文の繰り返し: 依頼文を正規化(小文字、パス・URL・数字・id を印に)して文字 3-gram の Jaccard 類似度 0.6 以上を束ねる。(b) 同じツールの並びの繰り返し: 本体のターンごとのツール列から長さ 3〜6 の部分列(連続の重複は潰し、閲覧系以外のツールが 2 種類以上、周期的な繰り返しは除く)。どちらも 3 回以上・2 セッション以上。スコア = 回数 × 1 回の実働の中央値(分。1 分未満は 1 分、2 時間で頭打ち。実働はターンの中で 5 分を超えて出来事が無かった区間(返答待ちや放置)を除いた時間で、セッションの実働時間と同じ数え方)。相づち(OK / 続けて)と動作確認の定型文(行頭の reply with 等)、20 字未満は除く | `build` / `export` 時に全セッションで計算し、上位 30 件を埋め込む(箱には全件数を出す。全件は `insights.html`) |

伏せ字版(`--anonymize`)では依頼文の本文・指示文の見出し・代表文を出さず、件数とスコアだけになります(`insights.json` も同じ)。

### スキルの下書き(`atlas skill-draft`、任意)

```
npm run atlas -- skill-draft <番号>            # out/insights.json の候補の番号。--backend copilot-cli(既定)/ opencode / anthropic、--model、--timeout
```

候補の繰り返し回数・代表の依頼文・ツールの並びを LLM に渡し、SKILL.md の形の下書きを `out/skill-drafts/<番号>-<名前>.md` に書きます。**明示したときだけ動き、`build` / `export` / `all` では呼びません**。費用は 1 回の実行で判定 1 件と同じです。`copilot-cli` はモデル 1 リクエスト相当の AI クレジット、`opencode` は選んだモデルの料金、`anthropic` は Anthropic API の従量課金(`ANTHROPIC_API_KEY` が必要)を消費します。`copilot-cli` は判定と同じ安全策(`--no-custom-instructions`、`shell` / `write` / `url` の拒否、`--add-dir` なし)で動きます。`opencode` にはツールを拒否する引数を渡していないので、作業フォルダが空であることだけが歯止めです(判定と同じ)。下書きの作業フォルダは判定と同じ接頭辞にしており、次回の集計では「(atlas の判定)」に分類されて候補に戻りません。テストは偽の CLI(`ATLAS_COPILOT_BIN`、`ATLAS_OPENCODE_BIN`)と fetch の差し替えで行い、本物は呼びません。伏せ字版の `out/` では拒否します(本文が無いため)。下書きは案なので、使う前に読んで直してください。

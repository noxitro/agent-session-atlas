# コマンドとオプション

[README](../README.md) に戻る。起動と画面での使い方は README、画面の各欄の意味は [screen.md](screen.md) にあります。

```
npm install
npm run atlas                              # all と同じ: snapshot → extract → vcs → metrics → export(記録つき)
npm run atlas -- build --anonymize         # 伏せ字版の HTML を作り直す(共有用)
npm run atlas -- all --since 2026-07-01    # 7 月以降に更新されたセッションだけ
npm run atlas -- --help                    # 使い方
```

## コマンド

| コマンド | すること |
|---|---|
| `snapshot` | `~/.copilot` の必要部分(`session-store.db`、各セッションの `workspace.yaml` / `events.jsonl` / `session.db` / `plan.md` / `checkpoints/` / `files/` / `rewind-file-snapshots/` / `policies/`、直下の `plans/` / `attachments/` / `chats/` の `*.md`)を `out/snapshot/` へ複製する。`data.db`(デスクトップアプリ)は複製せず、許可リストの列だけを `desktop.json` に書く([outputs.md](outputs.md#解析用の完全出力) の「data.db」)。大きいもの(`rewind-snapshots/`、一覧に無い名前のフォルダ、`logs/`)は既定で写さず名前と容量を `snapshot-manifest.json` に残す(`--snapshot-all` で写す)。インストール済みの skill・プラグインは**名前だけ**を記録する(下記) |
| `extract` | スナップショットから `out/sessions.json` を作る。repository の記録が無いセッションは、作業フォルダの git の設定を読んでプロジェクトを束ねる(下記) |
| `metrics` | `out/metrics.json` と、表計算ソフトで開く表 `out/tables/turns.csv`・`sessions.csv`([outputs.md の「表(CSV)」](outputs.md#表csv))を作る。metrics.json は(全体・プロジェクト・クライアント・月・モデル別の集計。空のセッションは除き、件数を `emptySessions` に、トークンの出所別・欠測の件数を各集計の `tokenSources` / `sessionsMissingTokens` に、ツールの成否と失敗の要因別の回数を `tools.results`(要因は `causes`)、MCP サーバー別を `tools.mcp`、skill の呼んだ側を `skills.byTrigger`、agent の失敗とトークンを `agents.byNameDetail`、変更行数を `lines`、インストール済みで未使用の skill を `installedSkills`、モード・推論強度・リクエストの起点・ツール定義のトークンを `exec`、権限の結果・エラーの種別・サブエージェント失敗の理由・compaction 自体のトークンを `frictionDetail`、todo を `todos`、モデル別の待ち時間を `latency`、ツール別の所要時間を `toolDurations` に、依頼(ターン)単位の工程別・依頼の種類別の集計を `turns` に持つ) |
| `vcs` | AI が作った変更(編集・作成で足した行)が、その後の VCS(Git / SVN / Perforce)のファイルに残っているかを照合し、`out/vcs-retention.json` に書く([outputs.md の「AI の変更の残存」](outputs.md#ai-の変更の残存vcs-の照合))。VCS は読むだけで、書き込みや同期のコマンドは呼ばない(許可リストで止める)。アップロード先から集計したときは、ディスクを読まず、送った側の PC が照合して添えた結果を読む。`all` にも入る(失敗しても止めない) |
| `build` | `out/atlas.html` と `out/sessions/<id>.html`(セッション詳細)を作る |
| `export` | `build` に加えて、各セッションの記録(経過・消費)を `out/sessions/<id>.md` に書く。LLM での振り返り用(共有するなら `--anonymize` の記録を中身を確かめてから。[outputs.md の「セッション記録」](outputs.md#セッション記録markdown))。指示文と skill の閲覧ページ `out/instructions.html` も作る。`--full` で解析用の全文記録([outputs.md](outputs.md#解析用の完全出力))。LLM は呼ばない |
| `all` | `snapshot` → `extract` → `vcs` → `metrics` → `export` を順に実行する(コマンド省略時の既定)。`--anonymize` のときは記録を作らず `build` にする(記録の伏せ字は HTML より弱いため) |
| `bundle` | LLM に工数を判定させる評価バンドル `out/bundle/` を作る(LLM は呼ばない)。ZIP を渡せない相手用に、指示とパケット数件を 1 ファイルにまとめた `out/bundle/parts/part-<番号>.md` も書く |
| `judge run` | バンドルの各セッションを LLM で判定し `out/judgments.json` に追記する(**クレジットを消費します**) |
| `judge import <ファイル>` | 外部の LLM で作った判定(JSON か、JSON を含む Markdown)を検証して `out/judgments.json` に取り込む |
| `judge m365` / `turns m365` `[--model <名前>] [--limit <ファイル数>] [--timeout <秒>]` | 開いている M365 Copilot のアプリ(Windows)を UI Automation で操作し、未判定の添付ファイル(`bundle` / `turns bundle` で作ったもの)を 1 つずつ新しいチャットで送って、返答を取り込み、レポートに反映する。`--model` は M365 Copilot のモデルの選択の名前(既定 `Think Deeper`)、`--timeout` は 1 ファイルの待ち時間(既定 900 秒)。AI クレジットは使わない。添付は OneDrive に入る([judge.md の「M365 Copilot のアプリを自動で操作する」](judge.md#m365-copilot-のアプリを自動で操作するwindows)) |
| `serve` | `out/` をローカルサーバ(`127.0.0.1`)で配信してブラウザで開く。画面からグループとメモを書け、集計し直す・工数の判定・記録と全文記録の表示ができる([screen.md の「画面からの操作」](screen.md#画面からの操作))。ブラウザを閉じると止まる(画面から動かした処理の実行中は、終わるまで待ってから止まる)。`atlas.bat` はこれで終わる |
| `open <フォルダ>` | いつもの集計(この PC のデータ → `out/`)とは別に、指定したフォルダを集計して(`all` と同じ手順)、そのフォルダのサーバで開く。画面の「別のフォルダを開く…」と同じ([screen.md の「別のフォルダを開く」](screen.md#別のフォルダを開く))。指定できるのは、アップロード先(全員の分)・その下の人ごとのフォルダ(その人の分)・プロジェクトやタスクタグのフォルダ・`~/.copilot` の形のフォルダ(下記「[別のフォルダを開く(open)](#別のフォルダを開くopen)」) |
| `memo list` / `memo show <id>` / `memo set <id> <本文...>` / `memo set <id> --file <path>` / `memo remove <id>` | セッションごとのメモ(`atlas-notes/memos/<id>.md`)を一覧・表示・保存・削除する。id は先頭の数文字でよい。`remove` は画像を残す([screen.md の「セッションのメモ」](screen.md#セッションのメモ)) |
| `turns bundle [--unjudged]` / `turns run [--limit <n>] [--model <名前>]` / `turns import <ファイル>` | 依頼ごとの採用の判定(段階 2。[judge.md の 3](judge.md#3-依頼ごとの採用段階-2))。`bundle` は M365 Copilot などに添付する `<out>/turn-bundle/parts/` と、GitHub Copilot CLI に渡す塊を作る(LLM は呼ばない)。`run` は GitHub Copilot CLI で判定する(AI クレジットを消費。従量課金の API を直接呼ぶ `anthropic` は使わない)。`import` はチャットの返答を `<out>/turn-judgments.json` に取り込む |
| `group list` / `group add <名前> <id...> [--note <一文>]` / `group remove <名前>` / `group export <名前>` / `group upload <名前> [--to <基底フォルダ>] [--force]` | 名前付きグループ(`atlas-notes/groups.json`)を一覧・追加・削除する。`export` はそのグループの表(CSV)・集計・記録を `<out>/groups/<名前>/` に書き出す([outputs.md の「表(CSV)」](outputs.md#表csv))。`upload` はそのグループのセッションの生ログ(前回の集計で `<out>/snapshot/` に複製したもの)と `session-store.db`・`data.db`(許可リストの列だけ)のそのセッションの行(`atlas-session-store.json`)を `<基底>/<名前>/<セッション id>/` に写し、メモがあれば `atlas-memo.md`(画像は `atlas-memo/`)を添え、`<基底>/<名前>/README.md` にグループの説明とセッションの一覧を書き、送った人がインストールしている skill・プラグインの名前を `<基底>/<名前>/atlas-installed.json` に添える。同じセッションは置き換え、ほかのフォルダには触れない。前に送ったときから中身が変わっていないセッション(`atlas-session.json` に残した要約 `contents` が同じで、送り先のフォルダのファイルの並びと大きさもそのままのもの)は写し直さず、点検にも入れない([README の「2 回目からは変わったものだけを送る」](../README.md#2-回目からは変わったものだけを送る))。写す前に合計の大きさと秘密らしい文字列(API キー・トークンなど)を調べ、見つかれば写さずに止まる(`--force` で写す)。基底は `--to` か設定の `uploadRoot`(無いフォルダは作らずに止まる。[screen.md の「タスクタグを作る・直す」](screen.md#タスクタグを作る直すatlasbat-から開いたときだけ))。`add` は既存の名前なら id を追記(重複は除く)。id は先頭の数文字でよい(1 つに決まらなければエラー)。壊れたファイルは上書きしない([screen.md の「タスクタグとセッションの選択」](screen.md#タスクタグとセッションの選択)) |

## オプション

| オプション | 意味 |
|---|---|
| `--home <dir>` | Copilot のデータの場所(既定: 環境変数 `ATLAS_COPILOT_HOME`、無ければ `~/.copilot`) |
| `--out <dir>` | 出力先(既定: リポジトリ直下の `out/`) |
| `--since <date>` | この日時以降に更新されたセッションだけ |
| `--project <key>` | プロジェクトで絞る(完全一致、無ければ部分一致) |
| `--client <name>` / `--model <name>` / `--branch <name>` | クライアント・モデル・ブランチで絞る |
| `--group <名前>` | 名前付きグループ(`atlas-notes/groups.json`)に入っているセッションだけ。他の絞り込みと AND。無い名前はエラー |
| `--session <id,...>` | 特定のセッションだけ(カンマ区切り、複数回指定可)。id は先頭の数文字でよく、複数に当たればエラー |
| `--notes-dir <dir>` | メモとグループの置き場(既定: リポジトリ直下の `atlas-notes/`)。無ければ無いものとして動く |
| `--port <n>` / `--no-open` | `serve` と `open` で、ポートを固定する / 起動後にブラウザを開かない |
| `--anonymize` | プロジェクト名・パス・リポジトリ名(git の origin から決めたものを含む)・ブランチ・人のフォルダの名前(送り先の全体を集計したとき。`person-01` など)を `project-01` などの仮名にし、依頼本文・セッション名・ファイルパス・自由記述(タスク完了の要約、中断の理由、エラーやサブエージェント失敗のメッセージ本文。`rate_limit` のような種別名だけは出る)を出さない。「(ホーム)」「(一時フォルダ)」「(atlas の判定)」は固有名を含まないのでそのまま、MCP サーバー名・skill 名・ツール名・agent 名(カスタム agent を含む)・hook の種別も出ます。パスは途中のフォルダ名に空白があっても(`C:\Users\<名前 姓>\<空白を含むフォルダ>\…`)まとめて `<path>` にし、既知の固有名は大文字小文字を区別せずに置き換えます。使えるのは `build` / `export` / `all`(と `npm run atlas:judge` の最後のレポート)だけで、伏せ字に対応しない `bundle` や `judge` などに付けるとエラーになります(評価バンドルは伏せ字になりません) |
| `--judgments <file>` | LLM の判定結果 `judgments.json` の場所(既定: `out/judgments.json` があれば使う) |
| `--bundle <dir>` | 評価バンドルの場所(既定: `out/bundle/`) |
| `--include-empty` | `bundle` で、依頼の記録が無いセッションもパケットにする |
| `--per-part <n>` | `bundle` で、`parts/` の 1 ファイルに入れるパケットの数(既定 5) |
| `--unjudged` | `bundle` で、判定済み(`judgments.json` にある)セッションを入れない(画面の「チャットに貼って判定する」の「添付ファイルを作る」はこれを付ける) |
| `--tool-output <v>` | `export` で、ツールの結果を記録に入れる条件。`fail`(既定。失敗したときだけ)/ `all` / `none` |
| `--max-chars <n>` | `export` で、依頼・応答・要約 1 件の上限(文字、既定 20000)。超えた分は中略して字数を書く |
| `--full` | `export` で、解析用の全文記録 `out/full/<id>.md`(上限なし)と `out/coverage.json`(網羅の検査)も書く。`--anonymize` とは併用できない |
| `--snapshot-all` | `snapshot` / `all` / `export` で、既定で写さない大きなもの(`rewind-snapshots/`、一覧に無い名前のフォルダ、`logs/`)も写す |
| `--snapshot-prune` | `snapshot` / `all` / `export` で、前回 `--snapshot-all` で写したが今回は写さないものを消す(既定は残して `snapshot-manifest.json` の `extras.leftover` とログに日時を出す) |
| `--temp-dir <dir>` | `extract` で、このフォルダ配下を「(一時フォルダ)」にまとめる(複数指定可)。指定すると既定の判定(`%TEMP%` と `AppData\Local\Temp`・`/tmp` のパターン)を使わず、挙げたフォルダだけを一時フォルダとみなす。このリポジトリ自体を一時フォルダ配下に置いて試すときや、別のマシンのデータを読むとき用 |
| `--config <file>` | `extract`・`vcs`・`all`・`serve`・`open`・`group upload` で読む設定ファイル(既定: 環境変数 `ATLAS_CONFIG`、無ければリポジトリ直下の `atlas.config.json`。下記「[wiki の指定](#wiki-の指定)」と「[アップロード先の指定](#アップロード先の指定)」)。`serve` は画面で決めたアップロード先をこのファイルに書く |
| `--vcs-mode <v>` | `vcs` / `all` で、比べる版をどこで見るか。`worktree`(既定。照合した時点の作業ツリーで、まだ取り込んでいない変更も含む)/ `committed`(最後に取り込んだ版。git は HEAD、svn は BASE、p4 は手元の版)/ `fixed`(セッションの終わりから決まった日数後の時点で取り込まれていた版。日数は設定の `vcs.lagDays`、既定 7)。設定の `vcs.mode` より優先する |
| `--to <dir>` | `group upload` で、アップロード先の基底フォルダ(フルパス)。省略すると設定の `uploadRoot` |

`judge run` 専用のオプション(`--backend` `--limit` `--only` `--concurrency` `--force` `--no-allow-tools` `--timeout`)は [judge.md](judge.md) を見てください。`judge run` では `--model` は判定に使うモデルの指定になります。

## snapshot と extract が読むもの

`snapshot` は各セッションの `session-state/<id>/session.db`(エージェントが残す todo の記録)も `session-store.db` と同じ方法(元を開かずにバイト列をコピーし、コピー側から `VACUUM INTO`)で複製します。2 回目以降は元のサイズと更新時刻が同じなら複製し直しません。`extract` が読むのは todo の状態別の件数と依存関係の数だけで、タイトルや説明は読みません。壊れていて複製できない `session.db` はそのセッションだけ飛ばし、理由を警告に出します。`session-store.db` を、Copilot が書き続けているなどで何度か取り直しても一貫した状態で複製できなかったときは、集計を止めずに前回の複製を使い(前回の複製が無ければその内容を使わず)、理由を警告に出します。走査の途中で消されたセッションは飛ばします。

`snapshot` が `~/.copilot` から名前だけ記録するもの(中身は読みません): `skills/` のディレクトリ名、`installed-plugins/<マーケットプレイス>/<プラグイン>/` とその `skills/` のディレクトリ名、`settings.json` の `disabledSkills`(他のキーは記録しません)。読めなかったものは理由を `extract` の警告に出します。

`--home` には、`group upload` で写したグループのフォルダ(`<基底>\<グループ名>`。直下にセッション ID のフォルダが並ぶもの)も指定できます。`session-state\` と `session-store.db` が無く、直下に `events.jsonl` か `workspace.yaml` を持つフォルダがあれば、そのフォルダを `session-state\` とみなして写し(`snapshot-manifest.json` の `layout` が `flat`)、`extract` は各セッションのフォルダの `atlas-session-store.json`(`session-store.db` と `data.db` のそのセッションの行)も読みます(同じセッションの行が `session-store.db` や `data.db` にあればそちらを使います)。指示ファイルの名前はほかのセッションと突き合わせて決めるため、一部のセッションだけを集計すると「不明」になることがあります。それ以外は元から集計したのと同じになります。

写したフォルダを集計し直すときは、次のように読みます。

- **プロジェクト名は送った側の記録から取ります**: 各セッションのフォルダの `atlas-session.json` にある `project` と `projectSource`(送った PC で決めた名前と決め方)を使います。ログにあるパス(`cwd`・`gitRoot`)は送った PC のものなので、読む PC のディスクでは調べません(作業フォルダが無いか、同じパスに別のリポジトリがあるかもしれないため。`.git/config` も読みません)。`projectSource` が無い記録(前の版が写したもの)は、名前の形から決め方を決めます(`所有者/リポジトリ` の形なら git の origin、ほかはパス)。記録が無い・読めない・ほかのセッションのものなら、repository の記録か、パスのままにします。記録の名前は前後の空白を落として使い、改行などの制御文字を含む名前は使いません。まとめ用の名前(`(一時フォルダ)` `(ホーム)` `(atlas の判定)`)は決め方をその名前のものに揃え、ほかの名前にまとめ用の決め方が付いていたら、決め方は名前の形から決めます。
- **出力先は、集計するフォルダごとに分けます**: 前に別の場所(`~/.copilot` や別のタスクタグのフォルダ)から集計した `--out` を指定すると、両方のセッションが混ざるので、何も書かずに止まります(前の集計はそのまま残ります)。別の `--out` を指定してください。集計が途中で止まった出力先でも同じです(`snapshot` は、始めるときに元の場所を `<出力先>\snapshot\snapshot-source.json` に書きます)。同じ場所を指す別のパス(相対パス、大文字と小文字の違い、ジャンクションやシンボリックリンク)は、同じ元として通ります。フォルダを移したなど、元が同じものだと分かっているときは、`<出力先>\snapshot\` の `snapshot-manifest.json` と `snapshot-source.json` を消してからやり直すと、今の出力先を使い続けられます。前の集計が何も写していない出力先(場所を間違えて 0 件だったときなど)は、止めずにそのまま使えます。
- **インストール済みの skill は送った人の記録から取ります**: アップロードしたフォルダ(タスクタグやプロジェクトのフォルダ)に添えた `atlas-installed.json`(送った PC の `~/.copilot/skills/`・プラグイン・`settings.json` の `disabledSkills` の名前)を `snapshot-manifest.json` の `installed` にし、「インストール済みで未使用の skill」に使います。同じ人(人のフォルダの名前。人のフォルダの下に無いものは 1 人とみなします)の記録が何プロジェクト分かあれば、送った日時(`sentAt`)が新しいものだけを使います(印を外して送らなくなったプロジェクトに、前に入れていた skill が残り続けないように)。何人分かをまとめて読むときは、人ごとの記録を合わせます(誰かが入れている skill)。送り先の全体を集計したときは、人ごとの記録も `snapshot-manifest.json` と `sessions.json` の `installedByPerson` に書き、画面で人に絞ると、その人の記録で「未使用」を出します(伏せ字版では人の名前を仮名にするので入れず、全員分を使います)。記録のファイルは 1 MB までで、それより大きいものは読まずに警告を出します。名前は共有フォルダに置かれたファイルなので、長すぎるもの・制御文字や見えない書式の文字を含むものは使いません。添えた記録が 1 つも無い(この版より前の atlas で送った)ときは記録なしとし、0 件とは見せません。一部のフォルダに無いときは、その数を警告に出します。
- **送った atlas の版を数えます**: アップロードは、各セッションのフォルダの `atlas-session.json` と、まとまりのフォルダの `atlas-index.json` に、送った atlas の版を `atlas` として書きます(`commit` = git のコミットの全桁、`committedAt` = その日時、`dirty` = git が管理しているファイルを手で変えていたか(`package-lock.json` だけの変更は数えません)、`code` = コードの目印)。前に送ったときから変わっていないので写し直さないセッションも、`atlas-session.json` の版は送った版に書き直します(写し直さないのは、その版が作る中身(ログのファイルと、atlas が添える DB の行・照合の結果・メモ)が前に送ったものと同じだったときなので、送り先のフォルダはその版で送ったものと同じです)。送り先から集計すると、`extract` がセッションごとの版を `sessions.json` の `uploadAtlas` に入れ(記録の無い、前の版で送ったものは `null`)、いちばん新しい版(送った版とこの PC の版のうち、コミットの日時がいちばん後のもの)より古い版・版の記録なし・新旧を決められない版(git で取得していないフォルダから送ったもの)・手で変えた版の件数を、ログに出します(人ごとに分けてあるときは、送った人の名前も)。あわせて、各フォルダの `atlas-index.json` から最後に送ったときの日時と版を読み(`snapshot` が manifest の `uploads` に、`extract` が `sessions.json` の `source.uploads` に入れます。読むのは索引の先頭だけです)、最後に送ったときの版がいちばん新しい版でないフォルダ(古い版・版の記録なし・新旧を決められない版・索引を読めない)を、人(`<人>/<プロジェクト>` の `<人>`。人のフォルダの下に無いものはフォルダの名前)ごとにまとめて、理由ごとの数と、いちばん前に送った日付を出します(セッションの数だけでは、その人がいつ・どの版で最後に送ったかが分からないため。フォルダごとの全部は `sessions.json` の `source.uploads` にあります。索引はあるが読めない(送っている最中で書きかけ、壊れている)フォルダは、黙って外さずに「索引を読めない」と出します。絞り込んで作ったレポートでは、対象のセッションを数えたフォルダだけを見ます(セッションごとの `uploadFolder`)。送り直しを頼む相手を決めるのに使います)。フォルダの記録の版も、いちばん新しい版の候補にします。画面では、上部のタグ「atlas の版」に出ます。
- **アップロードしたフォルダが並ぶ場所も指定できます**: `--home` に、アップロードしたフォルダ(タスクタグやプロジェクトのフォルダ)が並ぶ場所を指定すると、下のフォルダをまとめて集計します。人ごとに分けてあるとき(`<送り先>\<名前>\<プロジェクト>\<セッション ID>\`)は、`<名前>` を指定するとその人の分、`<送り先>` を指定すると全員の分になります(読むのは 2 段下まで)。全員の分を集計したときは、セッションごとに、数えたフォルダの `<名前>` を `sessions.json` の `person` に書きます(数えたフォルダは `snapshot-manifest.json` の `merged.owners`。元から消えて出力先に複製だけが残ったセッションは、前の集計の値を引き継ぎます)。レポートはこれを使って、絞り込みの「人」と「人別」の表を出します。`<送り先>` の直下に置いたフォルダ(人のフォルダの下に無いもの)のセッションは `person` が `null` で、レポートでは「不明」にまとまります。`<名前>` やプロジェクトのフォルダを指定したとき、`~/.copilot` の形のフォルダでは、`person` はどれも `null` です。CLI の絞り込み(`--project` など)に人の指定は無く、`tables` の CSV / xlsx にも人の列はありません(人ごとに出したいときは、`<名前>` のフォルダを指定して集計します)。同じ id のセッションが複数のフォルダにあるときは、`events.jsonl` が大きいほうだけを数えます(数えなかったものは `snapshot-manifest.json` の `extras.skipped`)。アップロードしたフォルダかどうかは、索引(`atlas-index.json`)があるかで見分けます。索引の無いフォルダ(前の版が写したもの)は、名前の順で先頭の 20 個までを中まで見ます。2 段下まで読むかどうかは、直下の先頭の 20 個のフォルダについて、その下の先頭の 50 個に索引があるか(索引が無ければ、先頭の 3 個にセッションのフォルダが並ぶか)で決めます(関係のない大きなフォルダを指したときに、下を全部読まないため)。このため、索引の無いフォルダだけが 21 個以上並ぶ場所では、先頭の 20 個に入らないフォルダを見つけられないことがあります。集計できるセッションが見つからなかったときは、`snapshot` のログ(「snapshot: 注意」)と画面の「別のフォルダを開く…」に、指定のしかたとこの上限を出します。そのときは、セッションのフォルダが直下に並ぶフォルダを直接指定してください。
- **置き換えの途中・消し残しのフォルダは数えません**: `.<セッション ID>.uploading`(写している途中)と `.<セッション ID>.old`(置き換えた前のもの。送り先で開かれていて消せなかったとき)は、同じセッションの複製なので写さず、件数を警告に出します。ただし、置き換えの途中で止まって本体のフォルダ(`<セッション ID>`)が無いときは、そのセッションが集計から消えないように、写し終えている `.<セッション ID>.uploading`(送る側が最後に書く `atlas-session.json` まであるもの)から写します。初めて送っている途中の `.uploading` は使いません。写したことは `snapshot` のログと `extract` の警告に出ます。送った PC でもう一度アップロードすると、元の形に戻ります。本体のフォルダが無く `.<セッション ID>.old` だけが残っているセッションは、数えません(消し残しがあるセッションを共有から消したときと見分けられず、消したセッションが古い中身で戻ってしまうため)。数えなかったことは、ログと警告に出ます。共有から消したセッションなら、そのフォルダも消してください。消した覚えが無ければ、送った PC でもう一度アップロードすると戻ります。前の版が出力先に写した作業用のフォルダが残っていれば、数えていないことと場所を警告に出します(消してかまいません)。
- **形が違う `atlas-session-store.json` は使いません**: 行がオブジェクトでない、列の型が違う(文字列のはずの列に数値、など)、必ずある列が無いときは、そのファイルを使わずに警告(`<セッション ID>: atlas-session-store.json を読めない (形が違います(…))`)を出して続けます。そのセッションは `events.jsonl` だけで集計します。
- **リンクは辿りません**: セッションのフォルダの中のファイル(`events.jsonl`・`workspace.yaml`・`session.db`・`plan.md` など)がシンボリックリンクなら、指す先を写さず、`snapshot-manifest.json` の `extras.skipped` に記録します(フォルダの外のファイルを出力先に取り込まないため)。

`extract` は、repository の記録が無いセッションについて、作業フォルダ(`gitRoot`。無ければ `cwd` から上へ探した `.git`)の `.git/config` の `[remote "origin"]` を**読むだけ**で(git コマンドは使いません)、URL から「所有者/リポジトリ」を取り出してプロジェクトにします。worktree(`.git` がファイル)は `gitdir` → `commondir` を辿って共有の設定を読みます。origin が無い・読めないときはパスのままです。上へ探すときは、ホームディレクトリと一時フォルダより上には上りません。`group upload` で写したフォルダを集計し直すときは、これを行いません(上の「プロジェクト名は送った側の記録から取ります」)。

## 別のフォルダを開く(open)

```
npm run atlas -- open "\\server\share\log"            # アップロード先: 全員の分
npm run atlas -- open "\\server\share\log\<名前>"     # 人のフォルダ: その人の分
npm run atlas -- open "D:\atlas-logs\Player-Weapon"   # プロジェクトやタスクタグのフォルダ
npm run atlas -- open --pick                          # フォルダを選ぶ画面から選ぶ(open-folder.bat と同じ)
```

- **フォルダを選ぶ画面から選ぶ**(`--pick`。Windows だけ): フォルダを選ぶ画面を出し、選んだフォルダを開きます。画面は、前に開いたフォルダ(`<out>-folders/*/folder.json` のうち、いちばん新しく開いたもの)の場所で出ます。「キャンセル」を押すと、何も書かずに終了コード 0 で終わります。`--pick` とフォルダの指定は一緒に使えません。リポジトリ直下の `open-folder.bat` は、引数が無ければ `open --pick` を、引数があれば(フォルダを bat に重ねて離したとき)`open <フォルダ>` を実行します。
- **フォルダはフルパスで 1 つ指定します**(空白を含むときは `"…"` で囲みます)。集計できる形かを先に確かめ、セッションが見つからないフォルダ・無いフォルダ・フルパスでないものは、何も書かずに理由を出して止まります。何を読むかは「[snapshot と extract が読むもの](#snapshot-と-extract-が読むもの)」の `--home` と同じです(読むのは 2 段下まで)。
- **出力先は、フォルダごとに分けます**: `--out` と `--notes-dir` には、いつもの集計の場所をそのまま指定します(省けば既定の `out/` と `atlas-notes/`)。集計は `<out>-folders/<キー>/out/` に書き、いつもの `out/` と `atlas-notes/` には触れません。
- **開いた画面は読むだけです**: タスクタグとメモは、送った人が付けていたもの(各セッションのフォルダの `atlas-session.json` の `tags` と `atlas-memo.md`)を出し、画面からは書き換えません(サーバも、タスクタグ・メモ・アップロード先・まとめて送る印の書き換えを 403 で断ります)。集計し直す・判定・設定は使えます。`atlas all --home <送り先>` で集計した出力先を `atlas serve` で開いたときも、同じく読むだけです。詳しくは [screen.md の「別のフォルダを開く」](screen.md#別のフォルダを開く)。`<キー>` は `<フォルダ名(40 文字まで)>-<パスから作った 8 桁>` です(同じ名前の別のフォルダを混ぜないため)。

  ```
  out-folders/<キー>/folder.json   開いたフォルダと、今の状態(集計中・表示中・失敗)。画面の「開いたことのあるフォルダ」はこれを読む
  out-folders/<キー>/open.log      画面から開いたときの、集計の出力(進み具合と失敗の理由)
  out-folders/<キー>/built.json    前に集計したときの入力の印(何も変わっていなければ、作り直さずにそのときのレポートを使う)
  out-folders/<キー>/out/          集計の出力先(atlas.html など。いつもの out/ と同じ中身)
  atlas-notes/folders/<キー>/      そのフォルダの画面のメモの置き場(読むだけなので、今は書きません。前の版で書いたものは残ります)
  ```

- **開くたびにフォルダを読み直し、変わっていたところだけ作り直します**。元のフォルダから手元へ写すところ(snapshot)は毎回行います(元が変わったかは、写してみないと分かりません。変わっていないファイルは写し直しません)。その後の extract・metrics・build は、前に集計したときから何も変わっていなければ省き、そのときのレポートをそのまま開きます(ログに「そのときのレポートを使います」と出ます)。作り直すのは、次のどれかが変わったときです: 写した複製(ファイルの名前・大きさ・更新日時)、`open` に渡した絞り込み、設定ファイル、atlas のコード、判定(`judgments.json`・`turn-judgments.json`)。レポート(`atlas.html`・`sessions.json`・`metrics.json`・`vcs-retention.json`)が前に集計したときのままでないとき(開いた画面で「集計し直す」や判定を動かした後など)も作り直します。必ず作り直したいときは `--rebuild` を付けるか、開いた画面で「集計し直す」を押します。使い回すのは、アップロードしたフォルダ(送った側が添えた記録だけで集計が決まるもの)だけです。`~/.copilot` の形のフォルダは、この PC のディスク(作業フォルダの VCS の状態など)も読んで集計するので、いつも作り直します。
- そのフォルダのサーバがもう動いていれば、読み直さずに、その画面をブラウザで開くだけにします(`serve` と同じ)。同じ出力先に書く処理が動いている間は、始めずに理由を出します。
- **使えるオプション**: `--pick` `--rebuild` `--port` `--no-open` `--config`、絞り込み(`--since` `--project` など。集計にそのまま渡します)、`--snapshot-all` `--snapshot-prune`。`--home`(開くフォルダは `open` の後ろに書きます)・`--judgments`・`--bundle`・`--anonymize` は使えません。
- **開いた画面で「集計し直す」を押すと、同じフォルダを読み直します**(`open` に渡した絞り込みは引き継ぎません。`serve` と同じ)。
- 開いたフォルダは `atlas.config.json` には書きません(覚えるのは `folder.json` だけ)。

## レポートのファイル

`out/atlas.html` は 1 ファイルで完結しており(外部への通信なし)、サーバ無しにブラウザで開けます。共有するときは、伏せ字版(`--anonymize`)で作った `out/atlas.html` と、用語の説明 `out/glossary.html`、詳細ページの入った `out/sessions/` フォルダを一緒に渡してください(伏せ字版の `all` は記録の `.md` を作りません)。5 MB 以上になると `build` が注意を出します(出力はします)。そのときは `--since` で期間を、`--project` などで対象を絞って作り直してください。

## wiki の指定

llm-wiki の参照は、ツール呼び出しの引数に vault の場所が現れたものを数えます。**vault を指定しないと wiki は集計せず、レポートの件数は 0 のままです。** 集計するときは、リポジトリ直下に `atlas.config.json` を置いて vault を指定してください(`setup.bat` が尋ねながら書きます。雛形は `atlas.config.example.json`。`atlas.bat` と画面の「集計し直す」もこの設定を読みます)。

```json
{
  "wikis": [
    "my-wiki",
    {
      "path": "my-notes",
      "index": ["README.md", "00-home.md"],
      "pages": ["notes", "areas/work"],
      "extensions": [".md", ".mdx"],
      "skills": ["notes-search"]
    }
  ]
}
```

| 項目 | 意味 | 省略時 |
|---|---|---|
| `path` | vault のフォルダ名か、その末尾を含むパス(必須)。大文字小文字は区別せず、区切りは `\` と `/` のどちらでも構いません | — |
| `index` | 索引のファイル。vault からの相対パス | `["index.md"]` |
| `pages` | 個別ページを置くフォルダ。vault からの相対パス。`"."` は vault 全体 | `["."]` |
| `extensions` | 個別ページの拡張子 | `[".md"]` |
| `skills` | wiki の skill として数える名前(完全一致) | なし(名前では数えない) |

- `wikis` の要素は文字列でも書けます。`path` だけの指定で、ほかは省略時の値です。
- `index` と `pages` は別々に判定し、索引に当たるものは索引として数えます。`pages` の配下にも索引にも当たらないファイルは「その他」です。
- vault の中に置いた skill は、`skills` に書かなくても skill のファイルの場所から判定します。
- vault を複数挙げると、レポートの「個別ページ」の一覧には `my-notes/notes/a.md` のように vault 名が先頭に付きます。件数は全 vault の合計で、vault 別には分けていません。
- **`path` はフォルダ名だけの指定が確実です。** フルパスにすると、エージェントが別の書き方(bash の `/e/notes`、`~/notes` など)で触った分は数えられません。逆にフォルダ名が短くて他と紛らわしいときは、`work/notes` のように親フォルダまで含めてください。`my-notes-app` や `notes.md` は `notes` とは別物として扱います。
- `~/` で始まる `path` はホームフォルダに展開します(展開後はフルパスの扱いです)。
- 相対パスだけで触った呼び出し(vault の中で作業していて `wiki/a.md` とだけ書いた場合など)は vault の場所が現れないので数えません。
- 項目の書き間違いは、件数が 0 になって気付きにくいのでエラーで止めます。

判定は `extract` で行うので、設定を変えたら `extract` からやり直してください(`atlas.bat` や `npm run atlas` なら毎回行います)。`extract` のログに対象の vault と参照のあったセッション数が出ます(未設定のときはその旨が出ます)。0 件のときは、まず `path` が合っているか確かめてください。

## アップロード先の指定

画面のタスクタグの「アップロード」・`upload-project.bat`・`group upload` が写す先の基底フォルダです。`setup.bat` の 3 つ目の質問か、画面の「場所を決める…」で決めると `atlas.config.json` に書かれます。手で書くときはフルパスで書きます(`~/` で始めるとホームから)。

```json
{ "uploadRoot": "E:\\dev\\atlas-logs" }
```

写す先は `<uploadRoot>\<グループ名>\<セッション ID>\` です。基底のフォルダが無いときは作らずに止まります。

## まとめて送るプロジェクトの指定

`upload-project.bat` が番号を聞かずにまとめて送るプロジェクトです。`schedule-upload.bat` で登録した毎日の自動送信も、このプロジェクトだけを送ります。画面の「プロジェクト別」の「まとめて送る」で印を付けると書かれます(`setup.bat` では尋ねず、書き直すときも今の設定を残します)。名前は集計のプロジェクト名(画面のプロジェクト別の名前、`sessions.json` の `project`)そのままです。

```json
{ "uploadRoot": "E:\\dev\\atlas-logs", "uploadProjects": ["owner/app", "X:\\work\\tool"] }
```

無いか空なら、bat はその場で番号を選ぶ形になります。今の集計に無い名前は送らずに知らせ、ここに無いプロジェクトは送らずに、最近更新したものの名前を出します。

## VCS の照合の指定

`atlas vcs`(と `all`)は、ログに残る作業フォルダのリポジトリを読みます。リポジトリを別の場所へ移した・ドライブを変えたときは、ログのパスでは見つからず「作業フォルダがこの PC に無い」になります。設定ファイルの `vcs.pathMap` で、ログのパス(`from`)を今の場所(`to`)に読み替えられます。

```json
{
  "vcs": {
    "pathMap": [
      { "from": "D:\\work\\old-repo", "to": "E:\\dev\\repo" }
    ],
    "mode": "worktree"
  }
}
```

- `from` と `to` はフルパスです。前方一致で、フォルダ名の途中では切りません(`D:\work\old-repo2` は当たらない)。Windows のパスは大文字小文字と `/` `\` の違いを無視します。JSON の中では `\` を `\\` と書きます。複数当たるときは長い `from` を使います。
- 読み替えたセッションは、レポートと表に「パスを読み替え」と出ます。開始時のコミット(ログの `headCommit`)はそのまま使うので、移す前と同じリポジトリ(同じ履歴)を指してください。
- `mode` は比べる版の見方で、`--vcs-mode` と同じ値です(省略時は `worktree`)。`worktree` と `committed` は照合した日で値が変わり、古いセッションほど後から人が手を入れた分が混ざります。期間で比べるときは `fixed` と `lagDays`(1〜365 日)で日数をそろえてください。`fixed` では、その日数がまだ経っていないセッションを「決まった日数がまだ経っていない」として照合しません(後で照合し直すと測れます)。取り込んでいない変更は見えません。
- `labels` で状態の名前(`kept` / `modified` / `missing` / `unattributable`)を差し替えられます。表の列名・画面・詳細ページに使います(40 文字まで)。`note` は画面の「AI の変更の残存」の節の説明に足す一文です(1000 文字まで)。どちらも `atlas vcs` の結果(`vcs-retention.json`)に入るので、変えたら `atlas vcs`(か `atlas.bat`)で照合し直します。チームの決まりや言葉づかいは、リポジトリに入れずにここ(未追跡の設定ファイル)に置けます。
- 書き間違い(知らない項目・相対パス)は、照合が 0 件になって気付きにくいので、エラーで止めます。

## 判定に使うモデルの指定

LLM の判定(`judge run`・`turns run`・`skill-draft`・`npm run atlas:judge` と、画面の「判定する…」の「このツールが判定する」)で、GitHub Copilot CLI に渡すモデルです。Copilot に保存した自分の API キーのモデル(BYOK)は `<プロバイダー名>/<モデル ID>` で書きます([judge.md](judge.md#2b-このツールの中で判定する画面からまたはコマンドで))。

```json
{ "judgeModel": "anthropic/claude-sonnet-5-5" }
```

- 決まる順: コマンドの `--model` > 設定の `judgeModel` > どちらも無ければ Copilot の既定のモデル。どれを使ったかは、判定のログの最初に出ます。
- **設定が無いと、GitHub Copilot の AI クレジットを使います**(Copilot の既定のモデル)。BYOK のモデルなら AI クレジットは使わず、提供元の API の従量課金になります。画面の確認ダイアログには、使うモデルと、どちらの費用かが出ます。
- `--backend anthropic`(Anthropic API を直接呼ぶ)には使いません(モデル名の形が違うため。そちらは `--model` で指定します)。
- 画面から動かす処理は、サーバと同じ設定ファイルを読みます(`serve` や `open` を `--config` で起動したときは、その設定ファイル)。

画面と bat は、設定ファイルを書き換える間 `atlas.config.json.lock` を作り、1 つずつ書きます(別の処理の書き換えを消さないように。落ちて残ったものは 10 秒たてば無視します)。書き換えるのは 1 項目だけで、ほかの項目の書き方(手で詰めた配列など)はそのまま残します。

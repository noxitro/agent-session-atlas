使い方: atlas <コマンド> [オプション]

コマンド:
  snapshot   ~/.copilot の必要部分を <out>/snapshot へ複製する(元は書き換えない)
  extract    スナップショットから <out>/sessions.json を作る
  metrics    sessions.json から <out>/metrics.json を作る
  vcs        AI が作った変更が、その後の VCS(git / svn / p4)のファイルに残っているかを照合し、<out>/vcs-retention.json に書く。
             VCS は読むだけ(書き込み・同期のコマンドは呼ばない)。アップロード先から集計したときは、送った側の PC の結果を読む
  build      <out>/atlas.html と <out>/sessions/<id>.html を作る
  export     build に加えて、各セッションの記録(経過・消費)を <out>/sessions/<id>.md に書く(LLM での振り返り用)
  all        snapshot → extract → vcs → metrics → export(セッション記録つき)を通しで実行する(コマンド省略時の既定)
  判定は外部の LLM に頼みます(このツールは LLM を呼びません)。束を作り、チャットに貼るか ZIP をエージェントに渡して、
  返答を取り込みます(docs/judge.md)。
  bundle     LLM に工数を判定させる評価バンドルを <out>/bundle に作る。ZIP を渡せない相手用に、
             指示とパケット数件を 1 ファイルにまとめた <out>/bundle/parts/part-<番号>.md も書く
  judge import <ファイル>
             外部の LLM で作った判定(JSON か、JSON を含む Markdown)を検証して judgments.json に取り込む
  turns bundle [--unjudged] [--zip] / turns import <ファイル>
             依頼ごとの判定(採用・依頼の種類・合わなかった点・普段の工程名)。bundle は M365 Copilot などに添付する
             <out>/turn-bundle/parts/ と、フォルダごと渡すときの chunks/・INSTRUCTIONS.md を作る(--zip で
             <out>/turn-bundle.zip にもまとめる)。import は返答を <out>/turn-judgments.json に取り込む
  judge m365 / turns m365 / tasks m365 [--model <M365 のモデル>] [--limit <ファイル数>] [--timeout <秒>]
             開いている M365 Copilot のアプリ(Windows)を UI Automation で操作し、未判定の添付ファイル(bundle・turns bundle・
             tasks bundle で作ったもの)を 1 つずつ新しいチャットで送って、返答を取り込み、レポートに反映する。モデルの既定は
             Think Deeper、1 ファイルの待ち時間の既定は 900 秒。判定するのは M365 Copilot。添付は OneDrive に入る
  memo list / memo show <id> / memo set <id> <本文...> / memo set <id> --file <path> / memo remove <id>
             セッションごとのメモ(<notes-dir>/memos/<id>.md)を一覧・表示・保存・削除する(remove は画像を残す)
  tasks sync / tasks list / tasks link
             管理ツールのタスク(設定の tasks で指定した XML)。sync は XML を読んで <notes-dir>/tasks.json を更新し、
             機械の紐づけ(<notes-dir>/task-links.json)を決め直す。list はタスクの一覧を出す。link は機械の紐づけを
             決め直し、変わればレポートを作り直す。集計(all・build・export)のたびにも XML を読み、機械の紐づけを決め直す
  tasks bundle [--session <id>] [--zip] [--per-part <n>] / tasks import <ファイル>
             機械で決まらなかったセッション(--session ならその中)の紐づけを外部の LLM に頼む束を <out>/task-bundle に作る
             (題名・最初の依頼 3 件・候補のタスク。--zip で <out>/task-bundle.zip にもまとめる)。import は返答を検証して
             task-links.json に紐づけの出所 LLM で書き、レポートを作り直す(手動と、前に LLM で決めた紐づけは変えない)。
             1 つのセッションが、いくつかのタスクに紐づくことがある(10 個まで)
  serve      out/ を 127.0.0.1 だけに配信してブラウザで開く(画面からメモを書け、集計し直す・判定の添付ファイルを作る・
             返答の取り込み・記録と全文記録の表示ができる)。ブラウザを閉じると止まる(画面から動かした処理の実行中は終わるまで待つ)
  open <フォルダ> / open --pick
             いつもの集計(この PC のデータ)とは別に、指定したフォルダを集計して、別のサーバで開く。指定できるのは、
             アップロード先(全員の分)・その下の人ごとのフォルダ(その人の分)・プロジェクトのフォルダ。
             出力先は <out>-folders/<フォルダごとの名前>/out、メモは <notes-dir>/folders/<同じ名前>/ に分ける
             (--out と --notes-dir は、いつもの集計の場所のまま指定する)。画面の「別のフォルダを開く…」と同じ。
             --pick はフォルダを選ぶ画面(Windows のみ)を出し、選んだフォルダを開く(取り消したら何もしない)。
             前に集計したときからフォルダの中身も atlas も変わっていなければ、作り直さずにそのときのレポートを開く
             (--rebuild で必ず作り直す)
  skill-draft <番号>
             改善点の「スキル化の候補」(out/insights.json の番号)から SKILL.md の下書きを LLM に作らせ、
             out/skill-drafts/ に書く(クレジットや従量課金を消費しうる。明示したときだけ動く。このツールが LLM を呼ぶのはここだけ)

オプション:
  --home <dir>       Copilot のデータの場所(既定: 環境変数 ATLAS_COPILOT_HOME、無ければ ~/.copilot)
  --out <dir>        出力先(既定: リポジトリ直下の out/)
  --since <date>     この日時以降に更新されたセッションだけ(例: 2026-07-01)
  --project <key>    プロジェクトで絞る(完全一致、無ければ部分一致)
  --client <name>    クライアントで絞る(例: github/cli, github/autopilot)
  --model <name>     そのモデルを使ったセッションだけ(m365 では M365 Copilot のモデルの選択、skill-draft では下書きに使うモデル)
  --branch <name>    ブランチで絞る
  --session <id,...> 特定のセッションだけ(カンマ区切り、複数回指定可。id は先頭一致で解決、曖昧ならエラー)
  --task <id>        管理ツールのタスクで絞る(そのタスクに紐づいたセッションだけ。metrics・build・export・all・bundle・turns)
  --notes-dir <dir>  メモの置き場(既定: リポジトリ直下の atlas-notes/)
  --file <path>      memo set: 本文をこのファイルから読む
  --judgments <file> 判定結果 judgments.json の場所(既定: <out>/judgments.json)
  --bundle <dir>     評価バンドルの場所(既定: <out>/bundle)
  --include-empty    bundle: 依頼の記録が無いセッションもパケットにする
  --per-part <n>     bundle・tasks bundle: parts/ の 1 ファイルに入れるパケットの数(既定 5、tasks bundle は 10)
  --unjudged         bundle・turns bundle: 判定済みのセッション(依頼)を入れない(tasks bundle はいつも紐づけの無いものだけ)
  --zip              bundle・turns bundle・tasks bundle: 束を 1 つの ZIP(<out>/bundle.zip・turn-bundle.zip・task-bundle.zip。
                     無圧縮)にもまとめる。フォルダを読めるエージェントやローカルの LLM に渡すとき用(parts/ は入れない)
  --temp-dir <dir>   extract: このフォルダ配下を「(一時フォルダ)」にまとめる(複数指定可)。指定すると既定の判定
                     (%TEMP% と AppData\Local\Temp・/tmp のパターン)を使わない
  --snapshot-all     snapshot: 既定で写さない大きなもの(rewind-snapshots、一覧に無い名前のもの、logs/)も写す
  --snapshot-prune   snapshot: 前回 --snapshot-all で写したが今回は写さないものを消す(既定は残して manifest に日時を出す)
  --config <file>    extract・vcs・metrics・all・serve・open・tasks: 設定ファイル(wiki の vault・アップロード先・タスクの指定)の場所
                     (既定: 環境変数 ATLAS_CONFIG、無ければリポジトリ直下の atlas.config.json)
  --settings <dir>   extract・vcs・metrics・build・export・all・bundle・turns・judge・serve・open・tasks: 設定のフォルダ(共有の AtlasSettings)。
                     <dir>\atlas.config.json を読み、その設定に tasks があればタスクの状態と紐づけを <dir> に置く。
                     open は省いても、前に使ったものか、開いたフォルダから上へ探した AtlasSettings を使う。
                     開いたフォルダの出力先を --out に指したときは、省いても open が使ったものを使う
  --vcs-mode <v>     vcs・all: 比べる版をどこで見るか。worktree(既定、今の作業ツリー)/ committed(最後に取り込んだ版)/
                     fixed(セッションの終わりから決まった日数後の版。日数は設定の vcs.lagDays、既定 7)
  -h, --help         この説明を出す
  -V, --version      版(Cargo.toml の version と、作ったときの git のコミット)を出す

export のオプション:
  --tool-output <v>  ツールの結果を記録に入れる条件: fail(既定、失敗したときだけ)/ all / none
  --max-chars <n>    依頼・応答・要約 1 件の上限(文字、既定 20000)。超えた分は中略して字数を書く
  --full             解析用の全文記録(out/full/<id>.md、上限なし。暗号化データと base64 本体だけ除外)と
                     out/coverage.json(網羅の検査)も書く。共有しないこと

serve・open のオプション:
  --port <n>         ポートを固定する(既定は空きポートを自動で取る)
  --no-open          起動後にブラウザを開かない

skill-draft のオプション:
  --backend <name>   copilot-cli(既定、copilot -p)/ anthropic(従量課金、ANTHROPIC_API_KEY が必要。
                     --features anthropic-backend を付けてビルドした atlas だけ。既定のビルドには無い)
  --timeout <秒>     制限時間(既定 600)
  copilot の実行ファイルは環境変数 ATLAS_COPILOT_BIN で差し替えられます。

# Surface brief: atlas レポート(out/atlas.html と out/sessions/<id>.html)

- モード: Operate(ダッシュボード)。主読者は利用者本人、二次読者は共有相手(文脈なし)。PC ブラウザ主、モバイルは崩れなければよい。
- 仕事: 全体 → 絞り込み → 根拠のセッション、の順に辿る。欠測(入力トークン記録なし)を隠さない。
- 制約: file:// 単一 HTML(共有用。閲覧のみ)、外部参照なし(同一オリジンの相対パス api/… への fetch だけは許す。atlas serve の API)、システムフォント、ライト/ダーク、色だけに頼らない、キーボードでフィルタ操作。

## Direction contract

THESIS: 申告書・検針票のような「様式」。全数値が罫線で仕切られた記入欄に収まり、欄の左上に小さな項目名が刷られている。カード並べの SaaS ダッシュボードを拒む。
OWN-WORLD: 白地に様式の緑インク(罫線・項目名)、本文は墨。角丸なし、1px の罫だけで区切る。グラフ系列は dataviz 既定パレット。
STORY: 読者は表紙の 4 欄で規模を掴み、要点で「何が起きたか」を読み、フィルタ行で絞り、明細とプロジェクト表から根拠のセッション詳細へ降りる(帳票の 表紙 → 摘要 → 明細)。
FIRST VIEWPORT: 上端に表題と生成日時と「記録 N 件のうち M 件を集計対象」の 1 文(表題帯。スクロールで消える)。その下は「目次 + 本文」の 2 段。768px 以上は左に 13em のサイドバー(sticky。節を 概況(全体・要点・改善点・工程と詰まり・集計明細、工数の判定済みなら AI 投入量 vs 推定人手工数)/ 内訳(5 節)/ 一覧 / 付録 の 4 群に縦に並べ、読んでいる節に印。その下に「グループ」の群(「すべて」と各グループの名前・件数・説明、現在に印。切り替えだけ。管理は本文の先頭の見出し、GROUP MANAGE)、下に「表示中 N / 集計対象 M」と、絞り込みが効いていれば「K 条件で絞り込み中」の印と解除)、右が本文。768px 未満はサイドバーを出さず、目次を上部に固定した細い 1 行(横に流れる。現在地に印。末尾に「グループ N」のボタンで同じ一覧を目次行の下に開く。右端に件数と解除)にする。本文は 1 行のフィルタ行(通常の流れ。固定しない。属性の軸だけ: 期間・プロジェクト・クライアント・モデル。グループの軸はサイドバー / 目次行の一覧が持ち、フィルタ行には置かない。使用頻度の低い条件は「その他の条件」に畳む)、表紙の記入欄 1 行(4 列: セッション・期間・実働時間・推定人手工数)、要点の 4 枠。集計明細(12 欄の記入欄グリッドと入力トークン記録の内訳帯・欠測語の凡例)は要点の下。サイドバーの幅はコンテンツから取らず、ページの最大幅を 1360px + 13em + 32px に広げて確保する(768px 未満はスマホの幅で、サイドバーを出すと本文が 150px ほどしか残らない。それより広い幅では表は横スクロールで読む(両端の影が手掛かり)。2026-11-09 に 1280px から下げた: 1280px 未満で目次とグループが上部の 1 行に畳まれ、グループの選び方が分かりにくいと利用者から指摘があったため)。(2026-11-01 Phase 9 で変更。変更前は表題帯 → 目次行 → 固定したフィルタ行(件数つき)→ 本文で、目次に現在地の印は無かった。それより前は全体サマリ 16 欄と内訳帯が要点より先だった)
SELECTION: 絞り込みの軸に「セッションの選択」がある(Phase 10、2026-11-01)。セッション一覧の左端にチェック欄(見出し行のチェックでそのページをまとめて)、一覧の見出しの直下に操作列「N 件を選択中 / 選んだ N 件だけ集計 / 選択を解除 / グループに追加 ▾ / (グループで絞り込み中)このグループから外す」(0 件では無効)。集計すると filter.ids に入り、サイドバーの件数と「K 条件で絞り込み中」に 1 条件として数える。選択で集計中は一覧の行が全てチェック済みで出て、操作列に「この選択で集計中」の印。チェックした行は form-wash の下地。色だけに頼らない(チェックの印と件数の文字がある)。
GROUPS(第 3 段、同日。第 2 段の「絞り込み行の select」を置き換え): グループの居場所は 1 か所、サイドバーの「グループ」の群(768px 未満は目次行末尾の「グループ N」ボタンで同じ中身を目次行の下に開く。tabindex=-1 の枠に焦点を移し、Esc / 外を押すで閉じて焦点はボタンに戻す。ダイアログではない)。行は button(名前・件数「m / n」・説明)、現在に aria-current(form-wash + 左の緑の枝)。現在の行を押し直しても外れない。「すべて」が先頭、一覧のチェックから集計中は「選んだ N 件」の印(button でない)が現在。0 件は 1 行の案内。多いときは群の中だけ縦に流す(40vh)。名前・説明の編集と削除は本文の先頭の GroupHead(GROUP MANAGE。以前は現在の行の下に 改名 / 一文 / 削除 を出していた)。選択は名前(filter.group)で持ち、hash には名前と id の両方(伏せ字版は id だけ)。
GROUP MANAGE(2026-11-03、利用者の問い「サイドバーに改名や削除を載せるのは良い UI か」への答え A): サイドバーのグループの一覧は切り替えだけにする(選ぶたびに現在の行の下へ 改名 / 一文 / 削除 の行が差し込まれて下の行がずれ、取り消せない削除が改名と同じ重さで並び、「一文」が動詞でなく何をするか分からなかった)。管理は本文の先頭の GroupHead(グループで絞り込み中だけ): 「グループで絞り込み中」の項目名・名前(h2)・件数・説明、右に「編集」(serve のときだけ)と「絞り込みを外す」。「編集」は名前と説明を 1 つの欄で直し(変わった分だけ 1 回の PUT)、削除は編集欄の右端に文字だけの「このグループを削除…」→ 確認(焦点は「やめる」、本文「グループだけが消え、セッションと記録はそのまま残ります」)。Esc は 1 段ずつ戻る。枠は 1px の罫と上に 2px の --form(節の見出しと同じ。片側だけの太い縁取りは使わない)。同種の見直し: 現在のグループを押し直すと外れる隠れた切り替えをやめた(押し直しても同じ。外すのは「すべて」と見出しの「絞り込みを外す」)、「選んだ N 件(押すと外す)」の行をボタンでなく印にした、利用者向けの「一文」を「説明」に揃えた(CLI の --note の説明はそのまま)。残したもの: プロジェクト別の表の名前は「もう一度押すと解除」のまま(印に書いてあり、絞り込みの行の選択でも外せる)、メモの削除は本文を空にして保存(確認つき)のまま。
GROUP REVIEW(2026-11-03、実データの一時コピーでグループを 3 つ作って点検): 選択(チェック)はグループ・選んだ N 件の絞り込みを外したとき(「すべて」「解除」)と、現在でないグループに足し終えたときに外す(以前は残り、「すべて」に戻った後に作ったグループへ前のグループのセッションが黙って混ざった。実データで 4 件のつもりが 7 件、2 件のつもりが 9 件)。追加の結果の一文に「チェックは外しました」。所属の表示: 一覧の行の題名の下に .sub の 1 行「グループ: 名前、名前」(伏せ字版では出さない)、詳細ページは serve のときだけ表題のメタ欄の下に「グループ」の項目名と名前のリンク(../atlas.html#group=名前。無ければ「なし(…)」。静的ページは作った時点の情報で古くなるので埋め込まない)。「グループに追加 ▾」のメニューはボタンの右端に揃えて左へ開く(左揃えで 1440px のとき右に 73px はみ出し、ページが横に流れていた)。作成欄の説明文の「絞り込み行の「グループ」」を「左の「グループ」(狭い画面では目次の行の「グループ」)」に直した。残したもの: 選択は 1 ページ(50 件)ずつ(絞り込み中の全件を選ぶ操作は無い)、グループ同士を並べて比べる表は無い。
EDIT MODE(第 2 段、同日): atlas serve から開かれたとき(http(s) + meta の token + GET api/state 成功、伏せ字版でない)だけ編集できる。画面と保存の境界は api.ts の小さな API(state / groups の POST・PUT・DELETE / heartbeat)。「グループに追加 ▾」は既存グループの一覧(ボタンの下に開く。Esc / 外を押す / ↑↓)と末尾の「新しいグループ…」。追加は 1 回で済み、絞り込みは変えず「N 件を「名前」に追加しました」を role=status で短く出す。「新しいグループ…」は入力欄をインラインで開く(名前 / 説明(任意) / 作成 / 取消。帳票の記入欄と同じ 1px の枠。ダイアログにしない)。作成するとサイドバーの群に即座に出て、そのグループで絞り込む。失敗は入力欄の下に理由(role=alert)。編集できないとき: 操作の代わりに 1 行の案内(伏せ字版では何も出さない)。サーバが止まったら(heartbeat の失敗)ページの上に warn-wash の帯「サーバが止まっています。atlas.bat を実行し直してください」を出し、編集の操作を消す(閲覧はそのまま)。3 画面とも帯は同じ見た目(base.css の .down-band)。
LIBRARY(Phase 11、2026-11-02): 指示文と skill の閲覧ページ(instructions.html)は用語ページと同じ作法(共通の目次の帯、base.css)。見出しごとの節(h2 + 版数・使用セッション数の 1 行)に、版ごとの details(summary に 版 n・ハッシュ・字数・セッション数・初回・最終・本文 .md へのリンク。最新の版だけ開いた状態)。中は前の版との行差分(form-wash の下地、+ は緑、- は warn)、本文の pre(等幅、60vh で縦に流す)、使われたセッションへのリンク。付録の目次から入る。export のときだけ作り、伏せ字版では作らない(本文が自由記述のため)。
INSIGHTS(Phase 12、2026-11-02): 「改善点」の節(id insights、概況の「要点」の次)。節の頭に 1 文の注意(LLM なし、相関まで、「傾向」、率は 5 セッション以上)と全件ページへのリンク。中は 2 列(380px で折り返す auto-fit)の 4 箱: 指示文の傾向(挙げる項目の ol + 版の小さな帳票)、skill の傾向(帳票 + 未使用の 1 行)、止まっている箇所(閾値の 1 行 + セッションの ol + プロジェクト別の 1 行)、スキル化の候補(ol、ツールの並びは等幅、回数・セッション・スコアの meta、「詳しく →」で insights.html#c-n)。各箱は上位 5 件まで。前 3 箱は絞り込みに従って再計算、候補は build 時の全セッション(「絞り込み前」と明記)。空のときは basis の 1 文。全件ページ insights.html は用語ページと同じ作法(page-nav、base.css)で、4 節(指示文の版の帳票・skill の帳票・止まっている箇所の帳票・候補の details)。伏せ字版は本文(依頼文・見出し・代表文)を出さず、版はハッシュ、候補は「依頼文の繰り返し」と書く。
MEMO(Phase 13、2026-11-03): 詳細ページの表題の直下、概要の前に「メモ」の節(h2 と更新日時)。本文は 1px の枠の様式(.memo-body)で、見出しは h3 から。メモがあれば目次の先頭に出る。無ければ節は hidden で、file:// では何も見えない。atlas serve のときだけ編集の script(GET api/memo-editor.js)を読み込み、節を表示して、読み込みが済んでから「メモを書く / 編集」を出す(編集はサーバの最新の本文から始める)。編集はインライン(ダイアログにしない): 項目名「本文(Markdown)」のテキスト欄、1 行の案内、保存 / 取消 / 画像を追加、状態の行(role=status)、失敗の枠(role=alert、warn-wash)。空にして保存と、入力ありの取消は確認を 1 回(状態の行の隣に出す。初期フォーカスは「やめる」)。競合は入力を残して「上書きして保存」。一覧ではセッション名の下に .sub の 1 行「メモ: 抜粋」(文字があるので色に頼らない)。「その他の条件」に「メモのあるセッションだけ(N)」のチェック(0 件なら出さない)。伏せ字版には節も抜粋も絞り込みも出さない。
OPERATIONS(Phase 14、2026-11-03): 起動は atlas.bat 1 つで、操作は serve の画面から(EDIT MODE と同じ条件。file:// と伏せ字版には何も出さない)。atlas.html: マストヘッドの右(配色の切り替えの左)に「集計し直す」「判定する…」(.btn。実行中・サーバ停止中は無効)。帯(JobBand)は本文の上(down-band と同じ位置)に、この画面のデータより後に始まった処理だけを出す: 実行中(form-wash + 下の form の罫。「〈処理〉をしています(経過 n 秒、条件)」+ 直近の出力 1 行(等幅、省略記号)+「止める」)、完了(「新しい集計ができました」+ 塗りの「再読み込み」+「閉じる」。自動では読み直さない)、失敗・中止(warn-wash + warn の罫、終了コード、details のログ(末尾 200 行、等幅、14em で縦に流す))。実行中と完了だけ上に貼る(sticky、top は --topbar-h。狭い幅では目次行の下)。失敗・中止はログを開くので貼らない(本文を覆わない)。読み上げは状態が変わったときの 1 文だけ(sr-only の role=status。経過の秒は live に入れない)。判定はネイティブの <dialog>(showModal、Esc で閉じる、閉じたら開いたボタンへ焦点を戻す): 上に 3px の form の罫、題「LLM で判定する」と右上の「閉じる」、「判定するもの」(工数 / 依頼ごとの採用のラジオ。前回の選択を覚える)と「判定の方法」(このツールが判定する / チャットに貼って判定する のラジオ)。このツールのときは 1 文の説明、記入欄「件数の上限」(数値。工数は既定 10・1〜500、依頼は既定 60・1〜5000。判定するものごとに覚える)と「判定に使うもの」(copilot -p の 1 行。選ぶ欄は無い。anthropic は出さない)、件数の行(form-wash、「未判定 N 件のうち M 件を判定します」)、費用の枠(warn-wash、「AI クレジットを消費します。」を太字で先頭)、右下に「やめる」(初期フォーカス)と塗りの「M 件を判定する」(0 件なら無効)。詳細ページ: atlas serve のときだけ GET api/session-tools.js を読み込み、表題のメタ欄の下に「記録を読む」(.btn の見た目のリンク。記録の .md があるときだけ)と「全文を作って読む」(押すと「作成中…」と経過、終わったら表示へ移る。失敗は warn の枠)。記録の表示(/view/<id>?kind=transcript|full。別のウィンドウで開く。下の REVIEW)は詳細ページと同じ作法(page-nav の目次の帯、base.css): 戻るは詳細ページ、リンクは「.md を開く」「用語の説明」、目次は本文の h2(読んでいる節に印)、表題は記録の先頭の # 行、その下に種類・大きさ・更新日時の 1 行、本文は 1px の枠の様式(.doc、最大 120ch、pre は等幅で 60vh まで縦に流す)。20MB を超えるものは描かず warn の枠で大きさと .md を開く案内。

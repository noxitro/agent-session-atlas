# Surface brief: atlas レポート(out/atlas.html と out/sessions/<id>.html)

- モード: Operate(ダッシュボード)。主読者は作者本人、二次読者は共有相手(文脈なし)。PC ブラウザ主、モバイルは崩れなければよい。
- 仕事: 全体 → 絞り込み → 根拠のセッション、の順に辿る。欠測(入力トークン記録なし)を隠さない。

## Direction contract

THESIS: 申告書・検針票のような「様式」。全数値が罫線で仕切られた記入欄に収まり、欄の左上に小さな項目名が刷られている。カード並べの SaaS ダッシュボードを拒む。
OWN-WORLD: 白地に様式の緑インク(罫線・項目名)、本文は墨。角丸なし、1px の罫だけで区切る。グラフ系列は dataviz 既定パレット。
STORY: 読者は表紙の 4 欄で規模を掴み、要点で「何が起きたか」を読み、フィルタ行で絞り、明細とプロジェクト表から根拠のセッション詳細へ降りる(帳票の 表紙 → 摘要 → 明細)。
FIRST VIEWPORT: 上端に表題と生成日時と「記録 N 件のうち M 件を集計対象」の 1 文(表題帯。スクロールで消える)。その下は「目次 + 本文」の 2 段。1280px 以上は左に 13em のサイドバー(sticky。10 節を 概況 / 内訳 / 一覧 / 付録 の 4 群に縦に並べ、読んでいる節に印。下に「表示中 N / 集計対象 M」と、絞り込みが効いていれば「K 条件で絞り込み中」の印と解除)、右が本文。1280px 未満はサイドバーを出さず、目次を上部に固定した細い 1 行(横に流れる。現在地に印。右端に件数と解除)にする。本文は 1 行のフィルタ行(通常の流れ。固定しない。期間・プロジェクト・クライアント・モデルに、グループ(atlas-notes/groups.json があるか、セッションを選んで集計中のときだけ出る。選んだ集合がどのグループとも違えば「選んだ N 件」)。使用頻度の低い条件は「その他の条件」に畳む)、表紙の記入欄 1 行(4 列: セッション・期間・実働時間・推定人手工数)、要点の 4 枠。集計明細(12 欄の記入欄グリッドと入力トークン記録の内訳帯・欠測語の凡例)は要点の下。サイドバーの幅はコンテンツから取らず、ページの最大幅を 1360px + 13em + 32px に広げて確保する(1280px 未満でサイドバーを出さないのは、13 列のセッション一覧(1360px)と 9 列のプロジェクト別がさらに窮屈になるため。1280〜1440px ではセッション一覧は横スクロール(両端の影が手掛かり)、プロジェクト別も僅かに横スクロールする)。(2026-11-01 Phase 9 で変更。変更前は表題帯 → 目次行 → 固定したフィルタ行(件数つき)→ 本文で、目次に現在地の印は無かった。それより前は全体サマリ 16 欄と内訳帯が要点より先だった)
SELECTION: 絞り込みの軸に「セッションの選択」がある(Phase 10、2026-11-01)。セッション一覧の左端にチェック欄(見出し行のチェックでそのページをまとめて)、一覧の見出しの直下に操作列「N 件を選択中 / 選んだ N 件だけ集計 / 選択を解除 / グループとして保存」(0 件では無効)。集計すると filter.ids に入り、サイドバーの件数と「K 条件で絞り込み中」に 1 条件として数える。選択で集計中は一覧の行が全てチェック済みで出て、操作列に「この選択で集計中」の印。「グループとして保存」は HTML からファイルを書けないので、groups.json に貼る JSON 片をクリップボードと読み取り専用の textarea(帳票の記入欄と同じ 1px の枠、等幅)に出し、貼る場所と atlas group add の例を添える。チェックした行は form-wash の下地。色だけに頼らない(チェックの印と件数の文字がある)。

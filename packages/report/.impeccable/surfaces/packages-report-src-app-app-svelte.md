# Surface brief: atlas レポート(out/atlas.html と out/sessions/<id>.html)

- モード: Operate(ダッシュボード)。主読者は利用者本人、二次読者は共有相手(文脈なし)。PC ブラウザ主、モバイルは崩れなければよい。
- 仕事: 全体 → 絞り込み → 根拠のセッション、の順に辿る。欠測(入力トークン記録なし)を隠さない。
- 制約: file:// 単一 HTML(共有用。閲覧のみ)、外部参照なし(同一オリジンの相対パス api/… への fetch だけは許す。atlas serve の API)、システムフォント、ライト/ダーク、色だけに頼らない、キーボードでフィルタ操作。

## Direction contract

THESIS: 申告書・検針票のような「様式」。全数値が罫線で仕切られた記入欄に収まり、欄の左上に小さな項目名が刷られている。カード並べの SaaS ダッシュボードを拒む。
OWN-WORLD: 白地に様式の緑インク(罫線・項目名)、本文は墨。角丸なし、1px の罫だけで区切る。グラフ系列は dataviz 既定パレット。
STORY: 読者は表紙の 4 欄で規模を掴み、要点で「何が起きたか」を読み、フィルタ行で絞り、明細とプロジェクト表から根拠のセッション詳細へ降りる(帳票の 表紙 → 摘要 → 明細)。
FIRST VIEWPORT: 上端に表題と生成日時と「記録 N 件のうち M 件を集計対象」の 1 文(表題帯。スクロールで消える)。その下は「目次 + 本文」の 2 段。768px 以上は左に 13em のサイドバー(sticky。節を 概況(全体・要点・改善点・工程と詰まり・集計明細、工数の判定済みなら AI 投入量 vs 推定人手工数)/ 内訳(5 節)/ 一覧 / 付録 の 4 群に縦に並べ、読んでいる節に印。その下に「表示中 N / 集計対象 M」と、絞り込みが効いていれば「K 条件で絞り込み中」の印と解除)、右が本文。768px 未満はサイドバーを出さず、目次を上部に固定した細い 1 行(横に流れる。現在地に印。右端に件数と解除)にする。本文は 1 行のフィルタ行(通常の流れ。固定しない。属性の軸だけ: 期間・プロジェクト・クライアント・モデル。使用頻度の低い条件は「その他の条件」に畳む)、表紙の記入欄 1 行(4 列: セッション・期間・実働時間・推定人手工数)、要点の 4 枠。集計明細(12 欄の記入欄グリッドと入力トークン記録の内訳帯・欠測語の凡例)は要点の下。サイドバーの幅はコンテンツから取らず、ページの最大幅を 1360px + 13em + 32px に広げて確保する(768px 未満はスマホの幅で、サイドバーを出すと本文が 150px ほどしか残らない。それより広い幅では表は横スクロールで読む(両端の影が手掛かり)。2026-11-09 に 1280px から下げた: 1280px 未満で目次が上部の 1 行に畳まれ、分かりにくいと利用者から指摘があったため)。(2026-11-01 Phase 9 で変更。変更前は表題帯 → 目次行 → 固定したフィルタ行(件数つき)→ 本文で、目次に現在地の印は無かった。それより前は全体サマリ 16 欄と内訳帯が要点より先だった)
SELECTION: 絞り込みの軸に「セッションの選択」がある(Phase 10、2026-11-01)。セッション一覧の左端にチェック欄(見出し行のチェックでそのページをまとめて)、一覧の見出しの直下に操作列「N 件を選択中 / 選んだ N 件だけ集計 / 選択を解除」(0 件では無効)。集計すると filter.ids に入り、サイドバーの件数と「K 条件で絞り込み中」に 1 条件として数える。選択で集計中は一覧の行が全てチェック済みで出て、操作列に「この選択で集計中」の印。チェックした行は form-wash の下地。色だけに頼らない(チェックの印と件数の文字がある)。
EDIT MODE(第 2 段、同日): atlas serve から開かれたとき(http(s) + meta の token + GET api/state 成功)だけ編集できる。画面と保存の境界は api.ts の小さな API(state / memos / heartbeat など)。サーバが止まったら(heartbeat の失敗)ページの上に warn-wash の帯「サーバが止まっています。atlas.bat を実行し直してください」を出し、編集の操作を消す(閲覧はそのまま)。3 画面とも帯は同じ見た目(base.css の .down-band)。

INSIGHTS(Phase 12、2026-11-02): 「改善点」の節(id insights、概況の「要点」の次)。節の頭に 1 文の注意(LLM なし、相関まで、「傾向」、率は 5 セッション以上)と全件ページへのリンク。中は 2 列(380px で折り返す auto-fit)の 4 箱: 指示文の傾向(挙げる項目の ol + 版の小さな帳票)、skill の傾向(帳票 + 未使用の 1 行)、止まっている箇所(閾値の 1 行 + セッションの ol + プロジェクト別の 1 行)、スキル化の候補(ol、ツールの並びは等幅、回数・セッション・スコアの meta、「詳しく →」で insights.html#c-n)。各箱は上位 5 件まで。前 3 箱は絞り込みに従って再計算、候補は build 時の全セッション(「絞り込み前」と明記)。空のときは basis の 1 文。全件ページ insights.html は用語ページと同じ作法(page-nav、base.css)で、4 節(指示文の版の帳票・skill の帳票・止まっている箇所の帳票・候補の details)。
